# M0 T18 S64 P153: ANSI Delphi TDBComboBox

The x86 Delphi 7 data-aware demo in [the investigation](M0-T18-S64-data-aware-sample.md) has an application-owned ANSI `TDBComboBox` that forwards WM_PAINT to the registered ANSI COMBOBOX procedure from its own module. Its editable dropdown previously retained native styling. The existing VCL combo renderer now accepts that exact class only in `CBS_DROPDOWN` role, with its original same-owner parent, same UI thread and a paint-scope witness for the registered ANSI procedure and class-owner caller. Fake paint, unrelated caller, changed parent, owner-draw, other dropdown types and the unverified W forwarding path do not gain the new witness. The control owns its data and callbacks. No original resources or public ABI changed.

A private copy of the real demo with a test-only thread-locale import (same caveats and hashes as [P152](M0-T18-S64-P152-dbedit.md)) loaded the actual candidate x86 DLL, SHA-256 `f7569754b9ce75c4e58aa35df7b16d1fb12a27b91e2495da60d26924cc1f2faa`. Its combo retained nine items and opening/closing without selection. In the in-memory data source, selection and record navigation produced `250 -> 111 -> 111 -> 250`; a neighboring TDBEdit input/restoration and record navigation also matched, and the process exited 0. Equal-sized 65-by-21 printed combo captures differed in 428 RGB pixels, including 217 in the outer two-pixel band; the rest includes arrow/content area. `IsWindowUnicode` for this real combo changed from 0 to 1 after the candidate's subclassing, so encoding coverage is explicitly bounded. The real demo field accepts numeric content; an attempted accented-character test did not change the value in either baseline or candidate and is not a multilingual pass.

The dual-width native ANSI class fixture covers exact role, fake paint, foreign caller, wrong parent, unsupported simple/dropdown-list roles, W forwarding rejection, reparenting, owner-draw change, reentrant parent change, selection, open/remove, font and cleanup. On this machine's ACP 1252, both widths also round-trip `Café` via ANSI and Unicode list messages. The former release fails the new positive case on both widths; scratch faults removing the owner check and allowing the unverified W witness each fail the intended x86 assertion. An early prototype fixture used the W window-procedure setter and failed the accented-text check even on the old package; correcting its ANSI setter made the model representative. Other code pages and real text entry remain unverified.

The C17 MinGW GCC/Ninja/ccache clean x86/x64 build, ABI, source receipts and byte-exact resource gates passed. The same-snapshot four-file package passed 24 focused tests in 20.15 seconds without skips. Both publication destinations match the tested hashes and each passed both width models. Other Delphi versions, dropdown types, Unicode forwarding, code pages, physical input, persistent writes and full integration remain unverified. M0/T18/S64 remain open.
