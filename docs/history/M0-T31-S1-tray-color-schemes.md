# M0 T31 S1 托盘配色

原版 Luna 的配色标识与顺序来自 COLORNAMES。显示名称使用 THEMES_INI
中对应 ColorScheme 的 DisplayName。缺少显示名称的配色使用资源标识。
仅在有多种配色时建立子菜单，单配色主题仍在主菜单。

沿用现有全局选择的 DWORD。给目录与配色标识组合单独分配身份，默认目录与
显式配色使用不相交的标识区间。加载实际资源时按标识找到目录与配色，
描述中的字号和其余设置保留。普通启动沿用主题描述默认值。
验证覆盖资源名、标识、窗口渲染选择和托盘已有的控制器切换路径。

## 发布与验证

- 双宽干净构建、ABI、归档依赖、七件身份和原图资源门禁通过。快照 SHA-256
  为 0013ffb8e637e9fee129c5702e9b5da19ccd251d8cdfdcf79e3f1ea93467b1b9。先向 assets 与 O:/winnt 发布，再测试两处同摘要七件。
- 原版 Luna 资源双宽读回 3 个配色名称、9 个变体和错误选择负例。
- 实际原生 HMENU 使用真实 Luna 原件，Luna 子菜单按顺序显示 Default (blue)、
  Silver、Olive Green。Win16、Win2K 和 Exit 仍在顶层。
- 双宽控制器测试验证互斥、同目录切换、再次选择取消、单配色、失败保持及
  菜单标签中的 &。双宽实际资源解析按同目录三个 ID 读取各自的 INI。
- 两处正式启动器各以 x86 和 x64 自有原生窗口验证 Luna 默认配色标题绘制与撤销。
  原版两个 Luna 文件的摘要保持。正式包聚焦回归 13/13。
- 旧版综合探针的普通按钮采样不稳定。同一夹具交替对照中，T30 通过 4/6，T31 通过 7/12。当前版失败在按钮按下／移除像素，旧版也复现按下像素失败。另用只检查标题和关闭命中的自有夹具验证本次普通启动范围。
- 可选 Shell 窗口枚举探针未发现后台运行的自有托盘 HWND，改用同一生产菜单工厂
  的原生 HMENU 断言。Explorer 的实际点击和管理员桌面全局切换未执行。
