# M0 T18 S64 P62: VB5 Data sample startup investigation

The P54 private VisData sample did not reach its main form. An isolated, self-owned x86 C debugger observed the original `VISDATA5.exe` and the P54 registration-free-manifest copy separately, with bounded time and job cleanup. Both showed the same Error dialog; the only observed exception was the expected initial debugger breakpoint (`80000003`). The original and manifest copies loaded 31 and 29 DLLs respectively, with no observed OCX, VB5DB or DAO module load before the dialog. Both self-owned jobs were reclaimed with zero active processes. The debugger did not intercept COM or library-load return values: absence of an exception or loaded module is not a diagnosis of why startup failed. Neither run reached the Data window, and no change was made to system registration or the sample database.

The reviewed `VISDATA.VBP` declares an OleExe with `Sub Main`; its source calls `frmMDI.Show`, and the MDI form declares old toolbar and common-dialog controls plus DAO-dependent startup. The P54 source and sample were already in task scratch. More specific startup evidence, or a simpler genuine sample, remains necessary; do not classify this result as a renderer bug or a lack of VB5 Data support.

Microsoft documented VB5 Control Creation Edition as a free release at https://news.microsoft.com/source/1997/03/10/microsoft-announces-final-release-of-visual-basic-5-0-control-creation-edition/. A public historical archive was downloaded only to task scratch for static examination: SHA-256 `022af94b651cd9d31e0676a6819dd5085940893f1ecc4abaa85b48c30de6f318`; Windows Authenticode returned `HashMismatch` with a historical Microsoft signer. The old Microsoft download endpoints returned 404. Three entries were extracted without execution or installation; its VB5DB.DLL hash `0bc8086116559eb56bd6850b13f3e96ded2804c46ee5a04e8e752496b5cbfe46` matches the already stored research copy, but the extracted IDE itself was unsigned. The archive and IDE were not run, installed, registered, shipped, or made a dependency; matching one member is not proof of the archive's integrity.

No product or tracked test source changed. The four files in assets and O:/winnt/system32 were checked identical to each other. VB5 Data and the full task remain open; this investigation establishes only the observations above.
