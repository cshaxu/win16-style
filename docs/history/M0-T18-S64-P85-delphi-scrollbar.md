# M0 T18 S64 P85: Delphi TScrollBar native role

Ordinary DelphiVCL4Python 1.0.7 TScrollBar windows remained native because the class is not reported as a native superclass even though its own paint and scroll-position messages reach the registered SCROLLBAR procedure. An exact newly created same-thread TScrollBar is now a passive candidate. Only a native WM_PAINT call witnessed from its class owner allows a verified role to bind after paint; public scrollbar range, page, position, native class extra bytes, style, original parent and reentrancy are checked before the existing scrollbar renderer installs. No name-only or message-only inference is used. Reparenting retires the binding. The verified role delegates direct mouse and key messages while disabled to the original procedure, preserving the observed real VCL behavior. The existing original graphics and public ABI are unchanged.

The final same-batch package ran on self-owned x86/x64 DelphiVCL4Python 1.0.7 at 144 DPI in horizontal and vertical configurations. All four controls attached and received classic rendering; the corresponding temporary candidate/current-package client captures had 6,250 differing RGB pixels per 250x25 or 25x250 control, reflecting a changed palette across the client area. Native-message keyboard and arrow-click runs delivered SB_LINEDOWN then SB_ENDSCROLL, position 25→26→27 and released capture, matching the previous package. Direct synthetic messages to explicitly disabled HWNDs were separately compared in both orientations and widths: key messages matched old notifications and 25→26 with VCL re-enabling the HWND; mouse messages matched the old no-notification and 0..0/0/0 read-back while the HWND remained disabled and valid. The latter range change is observed but its cause is unknown; it is not an instruction to interact physically with a disabled control. The final package repeated normal, disabled-key and disabled-mouse samples in both widths and orientations with explicit result checks. Target processes ended after WM_CLOSE; the abbreviated real-sample driver did not independently verify exit codes or job active counts. No physical input, drag/track sequence, additional real DPI, arbitrary Delphi version or whole-task integration is claimed.

A self-contained C fixture on x86/x64 at actual 96 and 144 DPI covers a no-native-paint impostor, foreign-caller native forwarding, horizontal/vertical scrollbars, range/page/position, keyboard and arrow messages, disabled key and mouse forwarding, clip preservation, reparent retirement, removal inside a scroll notification and destruction. The old assets package failed the attachment positive check on both widths. Deliberately removing the caller guard, disabled-key forwarding or disabled-mouse forwarding caused their corresponding x86 negative to fail. A first x64 foreign-caller test used an optimized tail call and did not represent the intended caller; noinline/non-tail was used for the reported result. An initial mouse observer synchronously sent the release after native tracking had blocked the same UI thread; the owned job timed out. Corrected tests pre-post the release and are still synthetic, not physical. See [investigation](M0-T18-S64-delphi-scrollbar-investigation.md).

A clean same-snapshot C17 MinGW GCC 16.1/Ninja/ccache 4.13.6 build passed source, original-resource, governance, x86/x64 ABI and package gates; build times 25.81/31.17 seconds. Snapshot manifest SHA256 `4c1daade14386af757442e11e44c141fe95f168110cfc2e58f355a0d26a10a12`. The actual four-file package passed 18 focused cases with zero skips in 8.17 seconds, including both DPI modes for the new models and adjacent EDIT, panel, superclass and mandatory launch/ABI cases. An earlier package snapshot predates the disabled-mouse correction and was not used for release. The exact tested package was published to assets root and O:/winnt/system32, eight hashes matched, and the installed model passed both widths from both destinations.
