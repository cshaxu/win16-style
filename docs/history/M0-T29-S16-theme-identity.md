# M0 T29 S16 主题身份与接入能力

## 窗口接入声明

主题编译器在两份 `.theme` 写入版本化的窗口接入选项。
启动器在启动目标前读入选项，独立判断 Explorer、Terminal 和控制台接入。
兼容绘制器当前支持范围存于主题加载边界。显式要求未支持的路径会使主题加载失败，
缺省声明沿用已交付的范围。各项含义与后续验收见 [T29 规划](../proposals/msstyles-classic-runtime.md)。

- x86、x64 MinGW/Ninja 增量构建和原生主题描述测试通过。覆盖生成文件、缺省声明、缺字段、重复字段及非法版本、键和值。
- x64 主题编译后的两份描述和 MSStyles 经 `check-classic-themes` 读回。
- x64 启动器针对自建临时主题目录验证 Terminal 请求关闭、开启和兼容性拒绝。使用自建无效映像，未执行目标。原 CLI 回归一并通过。
- 来源回执、源码边界和差异格式通过检查。测试临时目录已清理，保留仓库的增量构建目录。

## 普通启动的主题身份

普通启动从目录名计算不含年代的主题标识，连同主题已选出的兼容适配器写入启动包 v4。
新包分字段传输策略、主题标识及适配器。接收端继续读取 v2/v3，
沿用既有导出 context 布局。DLL 启动在 loader lock 中仅消费启动包，
窗口和对话框需要的主题解析仍由原来的调用位置负责。

- 双宽 payload 测试覆盖旧格式、同一标识配两个适配器及无效 v4 字段。
- 临时目录 `Same Folder` 先后只放 Win16 和 Win2000 两套主题。
  两宽解析出相同标识，分别定位并读取正确适配器和主题。
- 真正通过候选启动器执行的两套主题在 x86/x64 共 4 次同宽传播通过。
- Win16 自有窗口三代传播 8 项通过，覆盖两个跨位宽方向、两个同位宽方向、A/W 和挂起语义。
  旧夹具可执行文件在复制文件阶段报错，增量重建夹具后通过。没有更改断言。
- Win2000 改名主题 `Alias 2000` 用两宽自有进程另测 x86→x64 与 x64→x86。
  两条边的父进程和子进程皆加载正确位宽的中性 DLL 并实际附着 Win2000 外框。
- 通过候选启动器加载三种改名、混搭主题，x86/x64 的打开文件、目录和打印路由共 18 项通过。

## 托盘、全局会话和窗口请求

托盘按目录标识选中条目。启用时重新读主题取得兼容适配器，关闭时使用
已有会话选择。全局会话分别保存目录标识和适配器，窗口记录实际已应用的选择。
独立窗口接入使用同一目录标识。UWP 通过原动作槽携带适配器，撤销依据
已应用的外框和标识。旧请求的年代位仅在读入兼容边界解释。

- 两宽托盘单元覆盖切换、失效时保留当前状态、主题文件替换后再次启用，
  以及主题文件失效后的停用。
- 两宽现有产品全局接收路径共六组自有目标、36 次切换全部通过。
  每宽从未应用、普通启动 Win16、普通启动 Win2000 分别开始。每步查窗口绘制
  状态与记录的标识，恢复时要求标识移除。
- 两宽自建 UWP 外框各覆盖两个适配器、错误匹配、缺主题、外框复用、
  切换及描述消失后的移除。四次独立窗口接入通过，覆盖普通与合成外框的
  两个直接回调路径。该验证没有启动真正的 UWP 宿主或建立管理员全局会话。
