# M0 T18 S64 P158: Delphi data lookup popup frame and scrollbar

The P156 lookup control opens an application-owned `TPopupDataList` during its mouse-down callback; the popup is owned by the source control's root, not the control itself. P156 left it native. This change admits only the exact same-process, same-thread, same-module popup created in that witnessed callback, with the source's root as popup owner and the expected popup/border role. A private exception-safe, nested scope restores the previous source on normal or exceptional return. The existing nonclient grid renderer supplies the frame and scrollbar; it does not replace list items or bindings. The popup retains the exact source attachment until cleanup, checks it and its parent on subsequent messages, and retires if the source, parent or popup owner changes. Original graphic assets and public ABI are unchanged.

The actual candidate DLL `31bbb8f64f0b2f69257a3e573f967dba6cb2d473ba14b2cc78b8d6a521509ca4` was loaded in the real x86 private XDB sample. Same-window removal changed 502 frame pixels and 2,210 scrollbar pixels, with zero of the 102x130 list-client pixels changed. Both WM_VSCROLL line-down and queued arrow down/up changed the list content (3,124 and 2,049 pixels respectively) while the current and P156 list-client images matched before and after each step. Capture was released, a subsequent item click closed the popup, and the target exited zero. Its virtual scroll position remained 2 while content changed, so position alone is not used as the success criterion. This is message-level evidence for one x86 application; see [investigation](M0-T18-S64-lookup-popup-investigation.md) for prior inconclusive input attempts.

A self-contained dual-width model exercises successful scoped creation, wrong owner, out-of-scope creation, changed owner, source destruction, native exception unwind and cleanup. A separate scratch-only dual-width nested test verifies independent source association by destroying one source while its sibling popup remains attached. The old P156 package fails the positive attachment assertion on both widths. An x86 fault removing scope restoration is caught by the outside-scope assertion. These tests do not certify arbitrary handle reuse, all timing or other framework versions.

C17 MinGW GCC/Ninja/ccache clean x86/x64 build, ABI and source/resource checks passed. The same-snapshot four-file package passed 26 focused tests in 16.98 seconds without skips. Actual package and both installation locations passed the two-width popup model; both installation locations' four SHA-256 values match the tested package. The release remains limited to witnessed mouse-down creation: keyboard-created or reused popups, thumb dragging, repeat timers, cancellation, actual high DPI, physical input, other VCL versions and full integration remain unverified. M0/T18/S64 remain open.
