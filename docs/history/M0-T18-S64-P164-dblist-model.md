# M0 T18 S64 P164: TDBListBox native superclass regression

Embarcadero documents [`TDBListBox`](https://docwiki.embarcadero.com/Libraries/Athens/en/Vcl.DBCtrls.TDBListBox) and [`TListBox`](https://docwiki.embarcadero.com/Libraries/Athens/en/Vcl.StdCtrls.TListBox) as descendants of TCustomListBox; its [style contract](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.StdCtrls.TCustomListBox.Style) distinguishes ordinary text and owner-draw. This is evidence of the documented class relationship, not proof of the exact native forwarding or binding in all versions.

A self-authored model registers exact `TDBListBox` as a USER LISTBOX superclass. The published P163 DLL already attached and styled this model on x86 and x64: `ntw16s_native_superclass` recognizes the underlying USER class. A proposed additional name-based product branch was removed when P163 unexpectedly passed the new positive assertion. Thus this delivery makes no production source change; the test is an existing-path regression, not a demonstrated old-version bug. The fixture checks selection, item data and selection after removing styling, a pixel change across removal, and owner-draw remaining native. A DefWindowProc impostor is rejected in the protocol model. Two DPI-awareness modes and both widths passed; this model does not emulate Delphi data binding or custom VCL drawing. No actual TDBListBox sample was found, and no real VCL integration is claimed.

Clean same-snapshot x86/x64 GCC/Ninja/ccache package `s64-dblist-model-p164` passed ABI; actual package `s64-dblist-model-p164-test` passed 20 focused tests in 14.94 seconds with no skips, including both superclass and protocol-owner models, MDI, lookup, combo and menu regressions. Full integration remains pending. Although production sources were unchanged, rebuilt output hashes differ from P163; the exact tested four-file batch was therefore published to both assets and `O:\winnt\system32` (`s64-dblist-model-p164-publish`), all eight hashes matched, and both installed locations passed both widths' list model. The previous version itself passed the new positive case, so there is no old-product failure claim. First old-version run expected failure and was stopped after observing its success; this was the evidence for dropping the redundant branch.

Other RTL/VCL versions, live field updates and events, owner-draw semantics, unusual DPI and physical input remain unverified. Related sample and animation investigations are [here](M0-T18-S64-datalist-sample-search.md) and [here](M0-T18-S64-animate-investigation.md). M0/T18/S64 remain open.
