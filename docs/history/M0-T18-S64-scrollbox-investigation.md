# M0 T18 S64: Delphi TScrollBox investigation

The [author's Delphi XE example](https://mrxray.on.coocan.jp/Delphi/plSamples/075_TScrollBox_ScrollBar.htm) was downloaded only for research. Archive SHA-256: `0d953a7cd0f0af8fbe63525b28ee7382d38701ba57321d06ccc290e885a16024`; `02_AllwaysHide/Project1.exe` SHA-256: `4e0646fd2c1f82283cb359558f7483cbd8fe9f87a16101366dedfb71100ef83b`. Its source shows a normal `TScrollBox` containing an image; the two buttons only toggle the horizontal and vertical scrollbar visibility. No downloaded source or resource was incorporated into the product.

In isolated x86 96 DPI runs, both native and P122 saw a Unicode application-owned `TScrollBox` with `WS_CHILD`, both scrollbar styles and `WS_EX_CLIENTEDGE`; the styled root was attached but the scroll box was not. Direct line-scroll messages moved horizontal and vertical positions 0,0 to 8,8 and back in both. Both runs exited zero and their owned jobs emptied. Native and styled client widths differed (263 versus 271), so a cross-process image comparison would not prove preservation.

A test-only same-thread observer temporarily replaced the owned native process's resolved DefWindowProcW import, synchronously redrew the box and restored the import; it observed WM_NCPAINT forwarded to DefWindowProcW. This establishes that call for the tested sample and operation, not a general VCL contract. A scratch x86 prototype identified the class and reused the existing grid frame/scrollbar painter; in a same-window symmetric redraw/removal comparison 10,232 nonclient pixels changed and zero client pixels changed. Horizontal and vertical line messages still moved 0,0 to 8,8 and back, and the target and launcher exited zero with the owned job empty. An earlier prototype that attached only the passive frame-scrollbar helper produced zero nonclient changes and must not be counted as styling.

The sample's own two buttons were then exercised on isolated native and prototype instances: in each, the window style transitioned `56300000 -> 56100000 -> 56000000 -> 56300000`, with the original visible state restored; both instances exited zero and their jobs emptied. This verifies those state transitions, not pixels or interaction during each hidden state.

This is not a production-ready implementation: its class-based admission is deliberately provisional and does not establish a sufficiently narrow ownership/paint witness or lifecycle. Hidden-state pixels, drag, resize, reparent, disabled state, DPI, other versions, full image semantics, x64, negative models, actual package and release remain to be verified. M0/T18/S64 remain open. The registered scratch location is `build/t18-s64-vb-scrollbox-survey`; no binaries were published.
