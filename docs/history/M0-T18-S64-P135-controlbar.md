# M0 T18 S64 P135: ControlBar outer frame

The self-owned DelphiVCL4Python 1.0.7 x86/x64 `TControlBar` sample at 144 DPI contains a native `TToolBar`. P134 did not style its outer container. A restored, process-local import observer found that the control's `WM_NCPAINT` calls `DrawEdge(EDGE_ETCHED, BF_RECT | BF_ADJUST)` for its complete window rectangle on its own window DC, from the class owner's module. Internal toolbar-band edges use a memory DC and different arguments. The no-outer-bevel variant used a different edge value.

The implementation accepts only the exact Unicode same-process/thread `TControlBar`, unchanged same-owner parent and registered class procedure, and a fresh scoped nonclient draw from the same owner with the witnessed full rectangle, window DC, mapping and edge flags. After the original successful call, it draws the existing black one-pixel frame within the caller's clip and restores DC state. The original `DrawEdge` result, error and adjusted rectangle remain intact. The new hook branch reads the rectangle only inside that control's scope; unrelated calls retain their former path. Unwitnessed variants, reparenting and mismatches remain native. Band contents, toolbar data and callbacks are not redrawn. No exported ABI, original graphics or product files changed.

In the actual package, both real sample widths showed 736 changed nonclient pixels and zero client changes in a same-window removal comparison. With outer bevel disabled, both widths showed zero changes. Separate actual-package runs asynchronously posted a toolbar click; the application's callback recorded `attached=1` in both widths and the owned instances closed. A synchronous test-side callback attempt timed out while the Python/VCL host was active; its job was reclaimed and that run is not counted. The asynchronous runs do not claim physical input or universal application behavior.

Self-owned x86/x64 C models cover wrong parent owner, wrong edge/rectangle/caller, absent call, foreign DC and viewport, partial clipping, switching edge states, preservation of the native adjusted rectangle, same-window pixels, child button click and capture, reparent retirement and cleanup. P134 fails the positive assertion at both widths. Exception unwind and complete process-wide GDI lifetime are not independently established by this new model. The clean C17 MinGW GCC/Ninja/ccache build, source receipts, byte-exact original graphics and both ABI checks passed. The actual four-file package passed 28 focused cases in 19.29 seconds with zero skips, including panel, toolbar, scroll box, status, grid, VB and menu paths. Both publication locations matched the tested package and each passed both installed-width models. Other VCL versions/DPI, bevel modes, physical input and full T18 integration remain unverified.

The production diff adds 34 and removes eight lines across attachment and hook code; build registration adds eight lines and package cases add two, with two project-authored C tests in the source receipts. Search `rg -n "controlbar_|box_dispatch|hook_DrawEdge" src/ntw16s-dll` identifies the scoped witness and shared hook; prior box and status paths remain guarded separately. An earlier clean candidate was discarded after tightening the hook's unrelated-call scope; only candidate2 was tested and published. Scratch is registered under `build/t18-s64-vb-controlbar` and `build/t18-package/s64-controlbar-*`. M0, T18 and S64 remain open.
