# M0 T29 S13 主题目录首参数

用户要求重开 T29，提前完成排队主题任务的启动语法及发行布局。

```text
run16s.exe Win16 notepad.exe
run16s.exe Win2K sol.exe
run16s.exe --global
```

普通启动必须指定主题目录名和目标程序，后续参数由目标程序解释。主题目录
在启动器旁边，目录名大小写不敏感。裸 `--global` 独立进入未启用样式的托盘。
启动时扫描所有直接子目录，每个目录的独立描述和样式资源决定能否应用，
兼容的自定义目录名也会进入托盘菜单。当前呈现器为 Win16、Win2K。
每个目录使用一份描述文件，文件名可与目录名不同。目标执行的 UAC
重新进入路径携带准确的主题目录名。

发布器按旧清单摘要退役 `themes/` 下的四份旧位置文件，再核对新位置。
新目录中遇到发行清单无法确认身份且摘要不同的文件，发布会报错并保留该文件。
主题资源的格式、输入和现有运行时呈现范围延续 T29 S12。

验证要求包括双位宽干净构建、同一快照的七件包、不同工作目录的实际启动、
两种命名主题的应用、拒绝旧参数、全局 UAC 参数、缺失主题拒绝及实际远端复核。

## 开发验证

已完成 x86、x64 增量构建。两个任意命名的 Win2K 目录使用不同的
按钮宽度，实际启动的四个测试窗口在两种位宽分别测到 31 和 25 像素，
与各自主题输入一致。自定义 Win16 主题在不同工作目录下启动成功，
`--16`、`--global`、`--wait` 出现在目标参数位置时按原样传递。
目录探针确认无效主题和嵌套主题排除，兼容主题均发现。
两个 UAC 再入口单测通过，未触发实际提权或管理员整桌面验证。
托盘原生夹具发现三份有效主题，过滤缺件主题，启动时仍关闭全局样式。
自有窗口的双位宽全局接收器分别验证 31 和 25 像素的两份自定义
Win2K 主题，经过六个有向切换后恢复原样。


## P1 正式验证

MinGW GCC 16.1.0、Ninja 和 ccache 4.13.6 在独立构建目录完成 x86/x64。
两个旧测试夹具缺少新的链接依赖或模拟入口，修正后延续原干净构建目录。
发布快照的 1281 个构建输入均逐文件核对。原字形检查通过，四份主题文件
移到启动器旁的 Win16/ 和 Win2K/，内容摘要保持一致。
assets 和 O:/winnt 各核验七个 SHA-256。

样式选择在启动载荷和现有全局控制器中携带主题标识，两条路径均按选定
目录读取资源。目录标识碰撞时拒绝歧义，目录重新命名后重启托盘可刷新名单。

发布后聚焦集 22 项通过。另两项原有 Win32 Win2000 外框测试在此会话中
最大化、还原阶段均未通过。对照发布前备份的正式包，两个位宽的输出和
退出码逐字节一致。保持同一失败标记，样式发布记录单列其范围。
独立的按钮绝对宽度、托盘发现和自有窗口样式切换探针均通过。
管理员真实托盘和物理输入未运行。摘要和用例列表见
[发布清单](../etc/release.json)。

P2 将 Git 字节保留规则更新到新的主题发布路径。.theme 配套文件的 CRLF
是编译生成的正式字节，仓库下载和本地安装使用相同摘要。

P3 从远端 P2 下载七件正式文件，逐件与项目 assets 和 O:/winnt 对照，
并确认九个退役路径均不存在。复核 1281 个构建输入，八个差异仅为
Git 换行转换。最终六个 S13 临时构建、包、回归及发布备份目录已清理，
合计 494,405,738 字节。保留 Ninja 增量树和 ccache。
