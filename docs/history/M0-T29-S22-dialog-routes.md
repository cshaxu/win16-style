# M0 T29 S22 公共对话框路线

以 S21 P1 为运行基线。原有 Win32 A/W、COM、Shell、打印、页面设置及颜色等
公共框能力继续按 T20、T28 S3 和 T29 S14 的验收边界执行。

| 路线 | 当前可观测实现 | 迁移接收者 |
| --- | --- | --- |
| Win32 A/W 打开、保存 | `file_dialogs.c` 将策略分别接到旧布局控制器、Explorer 文件调用观察或原 API。 | 公共控制器消费文件布局和观察能力。 |
| COM 打开、保存、目录 | `com_dialogs.c` 的 `dialog_route` 将年代值转换为原生、经典或 Explorer 路线，保留多选、回调和原生回退。 | COM 控制器继续拥有调用、回写、资源和回退。 |
| Shell A/W 目录 | `folder_dialogs.c` 按年代值选择既有经典树或原生调用。 | 独立目录能力，保留筛选回调和 PIDL。 |
| 打印、页面设置 | `window_titles.c` 在 A/W 和扩展入口按年代值选择监视和布局。 | 公共打印、页面设置及窗口观察机制。 |
| 颜色、字体、查找、替换 | 检查现有 scoped chrome 和应用自定义模板。颜色选择器的色样边框仍有硬编码画刷。 | 主题呈现与公开参数约束分别交由现有绘制和适配层。 |
| 全局与普通启动 | `file_dialogs.c` 读取当前主题，缺失策略时从 family 推断；全局初始化 Explorer 对话框时可能换用固定 Win2K 样式。 | 从选定主题分开解析路线和呈现，验证其余场景原生回退。 |

先冻结各路线的启动与全局行为，再收敛主题字段和适配。逐项保留 ABI、调用方
数据、已有模板与兼容回退，以同一运行件的双位宽原生、默认主题和混搭主题
对照为验证基准。
