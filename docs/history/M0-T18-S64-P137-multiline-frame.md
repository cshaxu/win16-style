# M0 T18 S64 P137: multiline edit frame

The existing multiline EDIT scrollbar handler returned from WM_NCPAINT before drawing the client-edge frame. The verified edit path now draws the existing frame while retaining original scrollbar handling; when a partial nonclient region is supplied, it copies that region and uses GetDCEx to intersect it with the window DC. The special whole-window region keeps the full-frame path; allocation or DC failure skips this frame paint. Region ownership and DC release follow the Windows APIs. It does not change application text, mask behavior, fonts, graphic resources, exports or product files. Search: `rg -n "edit_scrollbars|list_border" src/ntw16s-dll/controls.c`.

The dual-width native model exercises TEdit and TMemo including both scrollbars, text selection, read-only, scrolling, reentrant removal, and nonclient pixels. The old package showed zero changed outer-frame pixels; the new package showed 1144 with zero client changes. A partial WM_NCPAINT probe on the first candidate exposed 200 changed pixels outside the 20-pixel requested region on both widths; the final candidate changes 20 inside and zero outside. The no-client-edge test marks the top edge excluding the vertical scrollbar: final candidate changes 0/180; a scratch fault that removes both edge guards changes 180/180 and is rejected at both widths. An earlier whole-window pixel-count test changed 636 pixels in both old and candidate due to other drawing; it was not a valid negative and is not counted.

Actual package x86/x64 DelphiVCL4Python 1.0.7 TMemo samples at 144 DPI attached, set two lines, retained selection 1..3, restored original content, and exited with their owned jobs; the probe recorded messages, not physical input.
