# M0 T21 S14：旧映射与全局传播

## 根因和范围

Windows 进程可以在文件更新后继续映射旧映像。全局接入在同一路径重用已有模块；PE 路径指向新文件并不代表进程内执行的是新代码。P33 的全局线程实现早于 P59 接入晚传播，因此旧窗口即使附着，也不能据此断言目标的后代会继承 DLL。不能一律按不同 PE 头拒绝所有旧映像：S13 P85 已有 P74→P82 同路径正常对照。

自有隔离实例的双宽实验从 Git 提交 `2ace527` 提取 P33 DLL，在目标已映射后只在任务 scratch 移走原文件并放入 P97 DLL；控制器从同一 scratch 路径启动。等待全局会话 `ready=1` 和目标窗口 `attached=1` 后，由目标创建子进程：x86/x64 均记录 `sent=1 child_exit=41`，子进程 `dll=0`。相同流程用 P97 映射及 P97 控制器作正向对照，双宽均 `child_exit=0`、`dll=1`。各实例均自有、私有桌面、正常回收；探针在 `build/t21-s13/p33-p97-synced.c` 和 `p33-managed-target.c`，用于本次研究，不是产品或测试依赖。

P33 文件 SHA-256：x86 `0a5990e5dc553522b02fae65126f793c14eec06449c5f682f6815da8fc64876e`，x64 `75ec49d0f035e5adabe1427149e782c64ceead5148cc2ccb2eb8bcc7fb55683d`。四个真实现有进程的只读 PE 时间戳、映像大小和校验值与该构建一致，不证明完整内存映像字节一致，也没有对这些进程注入、卸载或关闭。

现有 DLL 可能被固定并有代码在执行，强制远程卸载或使用第二套同名模块不能证明安全，也与简单统一的架构目标冲突；本 S 不实施。受影响的应用安全退出并重新启动后才能加载更新的文件。此处置不证明全部版本组合兼容，也不解释或修复本机会话的 x64 全局钩子 126。用户已接受对既有进程不能完全接管及退出残影的限制；T21 仍开放。
