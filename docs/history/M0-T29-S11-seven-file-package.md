# M0 T29 S11 七件独立包与发行切换

基线为 [S10 过渡包](M0-T29-S10-neutral-runtime.md)。发行契约现在固定
`run16s.exe`、两位宽 `ntwshk` 与 `themes/Win16`、`themes/Win2K` 的
两组主题。演示和四个年代 DLL 继续在构建树提供兼容测试输入。

## 开发验证

- 验包从产品契约读取文件清单，拒绝额外文件、目录和重解析点。附加的
  旧 DLL、多余空目录、改写为父目录的主题引用均触发拒绝。标准主题构建
  和独立解析由 `check-classic-themes` 运行，出货门禁核对主题引用、
  数据 PE 形状及构建根 SHA。两份中性 DLL 的 ABI、位宽、原始 18 张字模表、
  来源声明和原生导入同时核验。
- 增量七件候选通过 13/13 个聚焦用例。启动、传播、普通窗口和 COM 用
  实际候选路径。旧 ABI 及演示来自同轮构建树的验收输入，演示进程在只
  暂存两份中性 DLL 和两组主题的路径核实实际装入。未创建私有桌面。
- 部署仅移动正式清单和摘要可识别的旧文件。发布前核对候选和两个目标
  目录，使用同盘改名保留地址切换前的文件。两处独立自建目录的对照先
  故意在第二处阻止移动一个退役 DLL，核对事务回滚后全部旧摘要均恢复。
  解除自有文件锁后，成功完成两处七件和退役，证明无关文件保持。
- 将已验证的 S10 运行件和主题以七件布局暂存，用原生三代传播夹具
  专测 Windows 2000 启动。四组位宽各覆盖 A/W 创建，8/8 组通过，
  三代窗口和控件均已附着，未发现四个退役 DLL 的映射。
- 同一七件布局分别移除和损坏两种主题的描述文件，四个用例都在创建
  目标进程前拒绝启动。新增四个自有窗口用例在两种位宽上通过。UWP 宿主
  回调路径验证两种样式的应用、撤销和几何恢复，受控全局接收端逐宽覆盖
  原始、Win16、Win2000 之间的六个有向切换。该测试范围限于夹具自身，
  未执行管理员托盘整桌面验证。
- 扩展聚焦回归的首次包装运行中，`demo-pair` 未在旧式文件对话框关闭后
  读到 `Cancelled`。用同一增量构建单独重跑演示场景通过。新增四个自有
  窗口用例另行直接运行通过，首次失败仍计入本轮开发记录。
- 首次干净工作树在源码治理阶段发现新下载表使用本地二进制链接。
  干净树只携带源码和说明。将下载表恢复为发布 URL 后重跑，构建仍不
  读取预发布二进制。

## P1 干净构建与发布

同一快照使用纯 C17、MinGW GCC、Ninja 和 ccache 干净构建。x86 用时
260.65 秒，x64 用时 304.45 秒，两宽的快速 ABI 测试均通过。独立主题读回、
生产 PE、原图及来源、公共归档边界和构建依赖路径门禁通过。快照的 1,281 个
源码、工具及测试输入与本地工作树逐件核对一致。

先发布七件至 `assets` 和 `O:/winnt`，再启动同摘要包的回归。两个发布路径
的七个摘要均与干净候选匹配，`demo.exe` 和四个年代 DLL 已从两处退役。
退役前的映像由部署器留在本次任务回滚区。

聚焦回归 17/17。两宽覆盖 ABI、启动传播、Win2K 外框与 COM 打开取消、
UWP 自有宿主和六向样式切换。另从 `O:/winnt` 同摘要副本通过 8 组 Win2K
三代传播、4 组无效或缺失主题启动拒绝和两宽 UWP 缺主题保留旧表面。三代
传播未观察到退役 DLL；两宽 UWP 保留旧表面的用例覆盖两个切换方向。

从实际 `O:/winnt/run16s.exe` 启动 Calculator 两种风格和 Scan Win2K，
通过表面状态、最小化、最大化、还原和撤销几何。两项 Win2K 的标题渐变
可见像素采样通过。真实商店记事本两种风格均保留 WinUI 内容桥，原生 DWM
标题被抑制，标题采样符合目标，两个测试窗口正常关闭。测试限于自有窗口和
代码驱动的操作。未运行物理输入、完整包矩阵或管理员托盘整桌面验证。

产物、测试和限制见[发布清单](../etc/release.json)。实际远端复核待完成。
