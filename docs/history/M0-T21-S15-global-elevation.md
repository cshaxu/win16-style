# M0 T21 S15：全局模式交互式提权

普通权限无法启用管理员进程事件源，导致由未接入父进程创建的后台目标可能错过传播。用户已授权管理员权限。本 S 仅在 `--global` 且标准错误连接到交互控制台时请求 UAC；已提权、无控制台或标准错误重定向时保留原来的直接路径。普通单应用启动不变。用户取消 UAC 时报告错误并退出，不暗中启动较低覆盖的全局模式。

自有控制台原型证明，跨 UAC 的 `SEE_MASK_NO_CONSOLE` 在本机仍产生不同控制台，原控制台 Ctrl+C 不到达提权进程；提权子进程调用 `FreeConsole` 和 `AttachConsole` 后，父子共享控制台，Ctrl+C 与退出通过。初版不提权对照误共享驱动器控制台并中断驱动器；更正为自有独立控制台后通过。真实 UAC 同意的候选启动分支替身记录管理员令牌、控制台和 Ctrl+C 成功；用户实际选择“否”的对照返回 9，未启动全局控制器。

自有测试构建通过新线程切换至私有桌面，并显式将该桌面传给 x86 宿主；在真实 UAC 同意后观察到提权全局会话 ready，Ctrl+C 后父进程返回 0 且会话对象消失。这是带测试隔离改动的构建，不冒充正式包逐字节测试。早期测试夹具试图在已有窗口的线程切换桌面返回 170；随后改用新线程。未响应的 UAC 提示和过期源码快照均未计为通过。

提权控制器持有原启动器的同步句柄；启动时及活动期间检测启动器退出并走正常停止清理。自有私有桌面回归直接调用生产全局入口：启动器替身在会话 ready 后退出，控制器返回 0，测试确认会话映射不存在；该测试不强求物理卸载用户已接受可能残留的 DLL。
