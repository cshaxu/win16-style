# M0 T18 S22 — VCL SpeedButton observation

The local 32-bit cnc-ddraw configuration EXE has five `TSpeedButton` entries in an actual binary Delphi form resource, including Display, Advanced, Compatibility and Hotkey; the entries declare flat appearance and application click handlers. This establishes a real form-resource sample, rather than treating a bare RTTI class string as an instantiated control. Its 144-DPI isolated, self-owned copy displayed the navigation panel with the current DLL loaded. The original EXE was not distributed, and the user's original INI remained unchanged. Exact sample, probe and result details are in [the observation record](../etc/evidence/s22-speedbutton-observation.json).

Official Delphi documentation describes [TGraphicControl](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.Controls.TGraphicControl) as parent-painted and without its own Windows screen object. The [Glyph contract](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.Buttons.TSpeedButton.Glyph) permits state-specific application images, and [Flat](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.Buttons.TSpeedButton.Flat) changes border semantics. Accordingly, a replacement must preserve application images, transparency, callbacks and state; a text or color match cannot identify a control.

The visible left TPanel was 350x702 at 144 DPI. Its MSAA client returned zero children and a successful UI Automation descendant query also returned zero. A test-only observer temporarily patched eleven exact imports in the owned EXE, traced one synchronous panel redraw, then restored every slot. It saw a panel background FillRect and repeated application `DrawTextW` measurement and actual drawing on the panel DC, with per-control viewport behavior. Sending mouse messages to the Advanced and Display navigation regions changed visible TComboBox counts 1 -> 2 -> 1; four toggles remained visible, capture returned null after each and the original INI SHA stayed unchanged. The candidate's target exited zero and the owned job emptied. This proves these navigation actions occurred in the isolated sample, not physical mouse acceptance or all SpeedButton variants.

The public observations do not expose a per-button object, action or safe control-specific draw scope in this sample. Application code and VCL code share the main EXE, so a caller-module check is insufficient. No offsets, captions, geometry, pixel colors or VCL private layouts were promoted into product identity. No product source, ABI, or original graphics changed; the existing behavior remains. A future verified public object/draw contract or another identifiable legitimate sample is needed to continue, with image, transparency, flat/down/disabled and callback preservation. This is not a claim that every VCL SpeedButton is impossible to style.

The S22 clean x86/x64 build passed the source, original-resource, governance and ABI gates. Its four-file candidate passed 14 focused VB/VCL, launch and propagation cases, zero skips, in 22.90 seconds; 81 standard cases and full integration were omitted. The candidate also repeated the real 144-DPI navigation and restored all eleven observation slots.
