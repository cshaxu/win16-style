## 实施顺序

先从启动器、托盘和已加载主题模型收敛选择契约。再按能力替换窗口、控件和
对话框接收者，以对应实际包用例保持已交付行为。最后删去链接闭包中的旧实现
和内置历史配方，核对可兼容的导出与包内容。每批优先双宽增量构建及定向测试。
正式源码变更合批完成后才做一次完整交付。

当前审计只冻结了真实输入组。尚未逐对象核对，也尚未删除任何正式运行件依赖。

UWP 激活。UWP 的自有测试入口也接收选择对象。测试代码负责生成兼容预设
输入。托盘正式路径仍从选定目录的再次验证中读取适配器。
普通启动不再将主题按 Win16 或 Win2000 转为启动标志。载荷、DLL 接收者
和安装器复用既有 ABI 的选择编码，保持 v2/v3/v4 读取和 v4 发送格式。
测试验证同一主题 ID 能携带两种适配器，覆盖更换选择时保留策略位。

双位宽增量目标通过。x86 四项与 x64 五项定向 CTest 通过，覆盖启动、
传播、托盘选择、载荷及 UWP 目标识别。附加四组真实启动使用同一份 EXE

正式 DLL 仍按两个适配器分派初始化，旧资料的默认目录与绘制器仍在链接。
下一批继续做窗口与控件的统一接收者，保持复核用历史兼容样本独立于正式路径。
本批为开发验证，完整构建和正式发布与 S23 后续迁移合批。

## 标题按钮声明与系统菜单输入

共享槽位分配器为主题已声明且窗口支持的角色生成矩形。省略某个槽位
不会使整组布局退出。全客户区和非客户区的标题绘制、Win32 命中、
现代宿主重叠检查以及系统菜单定位均依据实际槽位。Win32 的标题栏
信息会标记主题省略的按钮为不可见。未声明 SYSTEM 槽位时，
全客户区的合成外框以标题栏左下缘作为键盘菜单锚点。

原生系统按钮是否缺失、键盘菜单锚点变换和 USER 跟踪由公共菜单控制器
处理，Win3.x 外框提供已测量的主题槽位。菜单行呈现、按压捕获、
其他按钮以及窗口宿主继续各用原有入口。两份正式主题资源未改。

x86 和 x64 各六项增量测试通过。新增断言覆盖省略 SYSTEM 后标题可命中、
省略 CLOSE 后最大化保留；既有合成外框、取消和恢复回归通过。同一开发包
双宽系统菜单实际调用四组通过，保留自有窗口的菜单项状态与选择，Win2000
两宽还核对了键盘切换选项。当前验证使用有界自有窗口及消息级输入。
其他混搭槽位的实际绘制和链接闭包仍待验证。

## 窗口和控件附着的主题失效处理

Win32 两类外框、菜单、基础控件、复合控件及全客户区合成入口使用共同的
附着主题读取。显式选择的主题无法加载时，新的附着返回资源不可用，
已分配的状态及绑定在发布前回收。未显式选主题的旧兼容调用仍可使用原有
默认呈现。普通窗口创建事务对主题不可用恢复原生外观并保留应用窗口。

双位宽增量编译和六项生命周期回归通过。首轮自有 Win16 窗口因新的读取错误
被创建事务销毁。接到现有原生回退出口后，两位宽、两种外框共四组完整实测
通过。各组在普通启动进程中暂移测试描述文件后创建自有窗口和按钮，确认
二者保持原生，直接附着均返回 1812，归还文件后可应用并移除。该探针仅在
临时 Win16 主题关闭控制台外框。双宽四项主题身份和声明冲突读取通过，
五份原始资源及来源字节摘要通过。所有本轮临时目录已清理。

正式包还保留旧预设兼容入口和年代绘制器。本批没有发布。

## 正式启动共用窗口创建及原生主题入口

正式 DLL 的两种启动模式共用 CreateWindowExA／W 和 SetWindowTheme
三处入口。全客户区模式保留创建事务，原生非客户区模式只在 USER 返回
有效窗口后附着。两种模式保留原生主题的记录和还原。后续窗口接入按
已取得的入口所有权避免再绑定同一原生函数。旧独立构建仍保留兼容入口。

首次 x86 编译指出原生 WINAPI 和内部 C 回调的调用约定不同；用同一
主题回调转调原生 trampoline 后，双宽正式与独立兼容 DLL、启动器通过。
检查实际 PE 符号，双宽正式件各只有三处对应本地函数。双宽应用夹具
共六次，覆盖窗口创建前后时点、样式复位和菜单键盘；双宽主题状态测试
两次，混搭主题对话框 26 次。另四次实际启动分别测两种主题和两种位宽，
确认 ANSI／Unicode 自有窗口调用 SetWindowTheme 后恢复应用请求。
本轮未测带全局会话的普通进程接管、真实应用宿主或正式部署。S23 继续，
两种启动适配器的 DialogBox、CreateDialog 和 MessageBox 尚有重复。
