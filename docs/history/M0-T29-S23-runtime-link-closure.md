# M0 T29 S23 运行件链接闭包

冻结基线为 S22 P1 076779b0a9992b5a30fcf45e4b64b9568cbd85c6。
对双宽干净构建的 build.ninja 提取 ntwshk DLL 链接规则和 LINK_LIBRARIES。
两宽均有 28 个旧组件目录的直接对象和 11 个年代归档。对象路径归属是
审计入口。每个对象须进一步核对导出、函数责任、主题读取和产品调用。

| 批次 | 当前真实入口 | 迁移验收 |
| --- | --- | --- |
| 主题选择和进程上下文 | EXE main、uwp、tray_controller；DLL dllmain、startup；classic_theme 的 profile 与 packaged 路径 | 按已验证主题身份和声明传递能力。移除正式进程中的年代判定、默认路径或内置预设。兼容 ABI 用途须逐项举证。 |
| Win32 与现代窗口外框 | win16-window、win2k-window、两个 window-uwp | 标题、边框、按钮、宿主布局和恢复共用通用呈现。系统菜单按钮和图标位置、系统按钮按压和命令由主题槽位及宿主能力驱动。 |
| 控件与公共对话框 | win16-control、win2k-control、win2k-file、win2k-print、win2k-stock | 逐项保留已交付的控件、回退、打印资源及原生结果。选定主题的资源与协议声明负责差异。 |
| 共享和兼容 | win16-common、win2k-common；28 个旧目录直接对象 | 对照直接调用、归档实际成员和 PE 资源。通用机制迁入相应运行时归属。所有保留的薄入口须核对调用及对应回归。 |

## 实施顺序

先从启动器、托盘和已加载主题模型收敛选择契约。再按能力替换窗口、控件和
对话框接收者，以对应实际包用例保持已交付行为。最后删去链接闭包中的旧实现
和内置历史配方，核对可兼容的导出与包内容。每批优先双宽增量构建及定向测试。
正式源码变更合批完成后才做一次完整交付。

当前审计只冻结了真实输入组。尚未逐对象核对，也尚未删除任何正式运行件依赖。
