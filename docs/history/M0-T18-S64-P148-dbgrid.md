# M0 T18 S64 P148: Delphi TDBGrid scroll frame

The real application-owned Unicode `TDBGrid` identified in [the investigation](M0-T18-S64-data-aware-sample.md) retained modern scrollbars with the previously released package. For an exact TDBGrid class owned by the application executable, the creation thread and original parent, with `WS_EX_CLIENTEDGE`, non-RTL role and validated public scrollbar information, the existing grid nonclient renderer is now available. The application retains responsibility for grid contents, data binding and callbacks. Classes without the client edge, without a validated scrollbar, and windows moved to a different parent are left native. No resource or public ABI changed.

The x86 real application test used the actual same-snapshot package DLL (`c08be46d7d335a1cca6dd41c41978b5f4f176dc53d97f057c90f87f2d338468f`) and private XML sample. Its matching 482-by-172 PrintWindow grid screenshots show classic scrollbars; in the 67,179-pixel central content area outside the scrollbar bands, RGB pixels match the prior release at initial selection, after a down-key message and after an up-key message. Both runs exited zero and the sample XML SHA-256 remained `86099abec399f4005effdabe8b3157655cf56b19c93b549dacf38d81fd5518c3`. These are message and printed-pixel observations on one 96-DPI x86 application, not proof of physical input, editing or committed data writes. The thread-hook observer still did not report readiness, so the actual grid attachment export was not independently read; the style difference and the model are the evidence.

The dual-width native fixture rejects a missing client edge and a missing scrollbar, verifies the positive scroll role, nonclient pixels without client changes, original-parent retirement and destruction. Both previous published DLLs fail its new positive assertion. A clean x86/x64 GCC/Ninja/ccache four-file build, ABI, original-resource and source gates passed. Actual same-batch package passed 24 focused tests in 20.03 seconds without skips; both publication destinations have identical four-file hashes and each passed both width models. Other Delphi versions, application modules, no-scroll grids, alternate drawing modes, DPI, physical input, binding writes and complete integration remain unverified. M0/T18/S64 remain open.

## Correction: hidden versus unavailable scrollbar

The original statement above that grids without a scrollbar are left native was too broad. The implementation checks whether public scroll information is valid; it does not require a visible scrollbar style. In a self-owned x86 `DelphiGridTest` run, private sample XML reduced to one column and one row produced `style=54010000` (neither horizontal nor vertical scrollbar style). Bare and P148-style 482-by-172 `PrintWindow` captures differed at 1,304 RGB pixels, all within the outer two-pixel band, with no interior difference; the sample targets exited zero. This is evidence for this real hidden/no-visible-scrollbar instance, not all Delphi implementations or DPI.

A project-authored x86/x64 native fixture now distinguishes a never-created/unavailable scrollbar from an existing hidden scrollbar with valid public scroll information. Both widths preserve attachment through hide/show/hide, compare nonclient changes without client pixel changes, and release their test windows. A deliberately faulty x86 scratch DLL that requires a visible scroll style was rejected specifically at the new hidden-scroll positive assertion; that fault DLL was not published. This is a test and evidence correction, not a P148 product binary change. Data insertion, real-app dynamic scrollbar transition, other DPI and physical input remain unverified.
