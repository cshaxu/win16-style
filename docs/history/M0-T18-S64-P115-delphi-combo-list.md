# M0 T18 S64 P115: modern Delphi list-only combo

Real DelphiVCL4Python 1.0.7 x86/x64 at 144 DPI uses CBS_DROPDOWNLIST, forwards its own WM_PAINT through its owner to USER COMBOBOX and exposes the public combo protocol. P114 did not attach the shell. This bounded change admits that role only under the same owner/thread and native paint witness; existing role, ownership and reentrant checks remain. A role change between editable and list-only, owner-draw, or reparent retires the attachment. A verified native list-only combo may return a NULL item HWND; the real Delphi sample returns the combo itself. Its list HWND is separately checked. The original application font remains in the native combo; a private System glyph font lease is used only by our list-label painter and released on change/removal. Sending WM_SETFONT during removal would close a native open popup, so the passthrough avoids that call. No public ABI or resource changes.

The self-contained native x86/x64 fixture checks wrong parent, false or foreign witnesses, item selection, NULL item, font changes and application ownership, open-popup removal, reparent, owner-draw and editable-role changes, reentrant query and cleanup. Its independent pixel comparison draws a freshly acquired System variant and compares the selected label's bitmap, allowing bounded vertical alignment; the deliberately no-font candidate failed that comparison on both widths and the candidate passed. A previous naive before/after bitmap comparison failed to catch that negative and was discarded. P114's saved published package failed the new attached assertion in both widths. The fixture shares the font-generation code to derive the reference, so it is a regression for routing and ownership, not independent proof of the generator's typography.

The clean actual package was exercised in real Delphi x86/x64 at 144 DPI, with 32 items, native selection and open/close. The popup was captured, remained open on removal, retained a valid list HWND, and subsequently closed; target and launcher exited 0 and owned jobs emptied. Changing and restoring the application font worked and its temporary font was deleted. Here item HWND is the combo itself; child attachment readings do not establish a separate EDIT. The first x64 attempt lacked PYTHONPATH and failed to import delphivcl; an explicit existing runtime path fixed the retry. These are synthetic input and captured pixels, not physical input. Other DPI, owner-draw, RTL, IME, localization and other Delphi versions remain unverified. Full T18 integration remains pending.

Clean C17 GCC 16.1.0, Ninja and ccache 4.13.6 double-width build passed PE/ABI and resource identity checks. The same four-file package passed 20 focused tests in 12.80 seconds without skips. Both assets root and O:/winnt/system32 received the tested files, with matching SHA-256; the installed list fixture passed x86 and x64 at each location.
