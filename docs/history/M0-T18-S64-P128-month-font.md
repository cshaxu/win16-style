# M0 T18 S64 P128: bounded calendar text

The [investigation](M0-T18-S64-monthcalendar-investigation.md) established that the observed x86 Delphi XE `TMonthCalendar` draws through `DrawThemeText`, which selects Segoe UI and passes font-specific glyph indices to `ExtTextOutW`. Selecting System around the outer theme call had no effect.

The implementation only considers the witnessed same-window native painter at 96 DPI, verified theme roles and flags, and strings composed of ASCII and U+200E. It measures the original string using proportionally scaled System bitmap glyphs and draws it only if the measured text fits the native rectangle. A title must also fit between the public previous/next arrow rectangles; the existing DC clip is intersected with the native rectangle, including for the observed `DT_NOCLIP` flags. Unsupported characters, roles, disabled state, other DPI, missing data, selection failure or insufficient space retain native text. The original app font handle, date, theme, layout and original graphics are not changed. The font is cached per attachment with same-thread leases and exception cleanup; no product export or file was added.

On the x86/96 DPI Delphi XE sample the scratch candidate changed title and date-grid text, retained native Today text, and preserved next/previous-month operation and capture release. Its public Today region and client area outside title/grid had zero pixel differences from P127. The sample was terminated in its own job to avoid its close handler writing the system locale; this is not normal-shutdown evidence.

The self-owned x86/x64 models independently check glyph-region changes, added selected-background color, public footer and other regions, calendar date/layout/theme/color, false or stale witness, reparent, paint/query exceptions, same-font sharing across two controls, release of the captured actual font handle, and `SelectObject` failure. P127 fails the new font assertion; a deliberate missing lease release fails the captured-handle check; a deliberately mishandled `HGDI_ERROR` fails the fallback title comparison. DPI 144 is simulated at a product import and the non-English checks test the text predicate only. Real high-DPI and non-English calendars, arbitrary title layout and physical input are not established. The observer and fault injection are confined to the test's owned process and restore its altered imports.

The clean C17 MinGW GCC/Ninja/ccache dual-width build, ABI and original-resource gates passed. The actual four-file package passed 29 focused cases in 22.44 seconds without skips. The real sample confirmed 486 changed title pixels, 2643 changed grid pixels, and zero Today or other pixels against P127; month navigation returned to the starting month. Both assets and O:/winnt/system32 matched all four hashes and passed both installed-width models.

The staged source diff covers five production files (56 additions, 4 deletions) and the model and package selector (16 additions, 4 deletions), net 64 lines across code and tests. The font and date state remain owned by the application; the existing theme call remains the fallback. The similar-path search `rg -n "DrawThemeText|month_|system_acquire" src/ntw16s-dll` was reviewed: the new replacement is limited to the witnessed month path, while status and other theme handling retain their existing paths.

M0/T18/S64 remain open.
