# M0 T18 S64 P122: Unicode Delphi Rich Edit

The x86 Delphi XE sample from its [original author](https://mrxray.on.coocan.jp/Delphi/plSamples/673_RichEdit_Stream.htm) creates a Unicode `TRichEdit` and forwards WM_PAINT to the registered RichEdit20W procedure. P121 left this control unattached. The new path uses the same owner, parent, thread and fresh-paint checks as the existing ANSI RichEditURL path, and changes only the frame and scrollbar. The author's archive and source were used for research; no third-party source or graphic was added to the product.

With the actual candidate at 96 DPI, a symmetric window-DC comparison showed 812 changed edge pixels and zero changed client pixels, with format, selection and event mask unchanged. A separate test edited while attached and undid the edit, restoring the original text, selection, format and event mask. Both owned processes and launchers exited zero and their jobs emptied. The real x86 DoubleKiller ANSI control retained its previous behavior: 1898 changed edge and 4573 other nonclient pixels, zero client pixels changed; format, selection, length, event mask and scroll state were preserved, and the down arrow moved from 0 to 16 and released capture.

During the Unicode model, a synthetic x64 paint exception exposed a pre-existing dangling VB paint TLS scope. Abnormal direct paint dispatch now restores the owned paint, status and spin scopes before releasing the attachment. Removing that cleanup in an isolated negative reproduced an access violation on the next paint. The ANSI and Unicode x86/x64 models pass subsequent paint, ownership and witness negatives, selection and formatting, link notification comparison, long-scroll dragging, reparenting, role changes and cleanup. An earlier asymmetric sample run showed 155 changed client pixels after an edit/undo sequence; the symmetric no-edit comparison and separate attached edit test above are the supported observations, not a claim that every redraw sequence has identical pixels.

The P121 published package failed the new Unicode fixture at its attachment assertion on both architectures. The clean C17 MinGW GCC/Ninja/ccache x86/x64 build and ABI checks passed. The actual four-file package passed 25 focused cases in 14.30 seconds without skips; both publication destinations match the package and each passed both architectures with ANSI and Unicode fixtures. Source and original graphics identity checks passed. The real sample is x86 only; other runtime versions, DPI, physical input, full IME behavior and the complete T18 matrix remain untested. M0, T18 and S64 remain open.
