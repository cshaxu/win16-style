# M0 T21 S3: manual global controller

`run16s --global` now installs x64 and x86 desktop hooks through the existing DLLs; the x86 system rundll32 is a transient host, not a fifth product. A same-user desktop-scoped mapping records the controller identity and random control cookie. Existing windows receive bounded notifications; future visible windows are picked up by the hook on their GUI thread. Supported top-level and standard controls reuse the existing renderer; unsupported controls, other desktops, UWP/XAML and listed shared system hosts are outside this delivery. No login startup or global Windows settings are changed.

Following the user's latest simplification decision, global shutdown only removes attachments owned by the global mode. A window already owned by ordinary `run16s` is left alone; its startup and child-process hooks are not patched or disabled. Loaded DLLs are pinned in processes that receive global attachments to avoid unloading while callbacks or window procedures may still run; they may consequently remain loaded and keep the installed DLL file occupied until those processes exit. Shutdown can leave visual remnants. Notifications have time limits: a start sweep reported one timeout/failure, and no claim is made that all existing windows were reached. The named exclusion list is not proof that every possible shared host is identified.

The private-desktop actual-package integration test covered existing and new native x86/x64 test windows; four globally owned windows were removed on stop, two x64 ordinary `run16s` instances (one started before and one after global mode) retained their style, and both created styled new windows and styled child processes after stop. A new independent process after stop remained native. The x86 and x64 same-thread tests passed duplicate application, wrong-thread refusal, edit/button/frame removal, destruction and reentrant destruction; pre-existing ordinary attachment remained owned by ordinary mode. These are targeted native probes, not an all-applications or pixel-perfect restoration guarantee. x86 ordinary-mode mixed ordering, real application input, duplicate startup, controller/host crashes, higher integrity, multiple desktops and long-running resource behavior remain to be checked in subsequent T21 work. The public additive exports are reviewed in [ABI note](M0-T21-S3-abi.md).

The clean snapshot `s3-global-final` passed GCC/Ninja/ccache dual-architecture build, ABI, source provenance and byte-exact original graphics checks. The same four-file package passed 11 focused actual-package cases with no skips (`s3-global-check2`): global E2E, both window lifecycle cases, both ABIs, demo boundary/pair, initial injection, child propagation and package-tool checks. The first package run failed before reaching the E2E target because the test registration supplied `--private` twice; the runner fix and a full retry passed. The corrected test runner was used from the main tree; production build inputs and package were unchanged. Physical input and the complete package matrix were not run.
