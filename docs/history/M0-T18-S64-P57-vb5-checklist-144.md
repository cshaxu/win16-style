# M0 T18 S64 P57: VB5 checklist at 144 DPI

The private DPI-aware copy of the original x86 VB5 AppCommand sample uses the real MSVBVM50-owned ThunderRT5ListBox. At 144 DPI its item is 23 pixels high; the runtime draws an 11 by 11 glyph at x=0, y=6 using a 44 by 11 source bitmap. The previous published package left its native image unchanged. The candidate limits replacement to that observed runtime, DPI, role, item geometry and source shape; other unsupported geometry falls back. VB6 retains its separately observed 22-pixel, x=2, y=5 geometry. Input, text, notifications, and original graphics remain owned as before.

The real sample used a private per-monitor-aware manifest and private runtime dependencies; it is not shipped or required for the project. Its four enabled/disabled and checked/unchecked images matched the existing original 11 by 11 glyph at 121/121 pixels each. Final-package images were byte-identical to the images used for that comparison. Mouse and keyboard selection returned 0 to 1 to 0, and the sample and job exited normally. At 96 DPI the old and candidate images for the three selection states were byte-identical and both exited normally. Initial sample setup omitted its XML dependency and failed before the test; the dependency was added and this failure is not a product result. Scratch diagnostics also had one reused output-directory error and one inappropriate viewer invocation; neither is counted as a pass.

The self-contained models cover both PE widths, VB5 and VB6, four states and invalid geometry; both old-package VB5 models failed the new styled assertion. All four final-package 144 DPI combinations passed. Two x64 CTest entries passed in 11.24 seconds. The 12-case same-batch focused actual-package run passed without skips in 38.92 seconds, including ABI, first injection, propagation and both existing checklist models. A real x86 VB6 144 DPI CBMXfer run passed with explicit cleanup of its own hidden Options form, as documented for P56. The installed assets and system32 packages each passed the x86 and x64 VB5 144 DPI models. Clean dual-width GCC/Ninja/ccache build, source and original resource identity checks passed.

The tested and published SHA-256 values are run16s.exe `6484ced31b7c6742aa0834c318de95e2f18ece656fcc6eb6d56fed84c1e63ba1`, ntw16s32.dll `1dadb5c3a976191e79e1cffa3bc13cc3517e0501fd429961fe9c4aa37373dd3f`, ntw16s64.dll `2fd94e1450e60bbb0e5c1f54f34ed9a643e260d99caed4bb3ea545e278f71dd2`, demo.exe `836bc7dcf9abb94e8dda966101eca0953abc7f7f99d13f0e174822ba0b0c1016`. Both publication locations match all four.

This is a limited observed geometry, not universal VB5 checklist support. Real samples were x86; actual VB x64, other DPI values and layouts, physical input, full integration, and unassisted CBMXfer viewer shutdown are not covered. T18 and S64 remain open.
