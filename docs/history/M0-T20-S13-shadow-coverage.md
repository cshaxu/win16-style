# M0 T20 S13：扩展错误入口与嵌套原型

## 结果

S12的自有进程原型只跟踪Open和ChooseColor，未覆盖ChooseFont的负例会把
真实错误1错误地显示为旧的12291。本S在独立测试模式增加对保存、字体、
普通打印、页面设置、查找和替换各A/W入口的受控进程内hook，连同原有打开、
颜色，共8类。每一类先产生测试伪错误12291，再调用真实API的无效结构，
核对真实 `CommDlgExtendedError` 返回值与原生trampoline一致；双宽 A/W
共4组、每组8类通过，实际均为1。这是无效参数对照，不能据此推断各对话框
正常显示、取消或所有配置已覆盖。

嵌套负例：外层旧文件框的测试确认标记置位后，同线程触发内层错误文件调用。
S12单一线程变量被内层清掉，双宽 A/W 都错误读到1而不是预期12291；测试以
`nestedlegacy` 明确捕获这个缺陷。原型在测试模式保存并恢复外层标记后仍初次
失败：系统保留了内层错误1，原始允许值检查拒绝交接。针对**该固定测试条件**
处理内层结构错误后，双宽 A/W 的 `nestedfixed` 均读到12291；此条件是测试
特化，不是任意嵌套错误的通用实现。初次失败和旧模型负例均保留。

`PrintDlgExA/W` 的无效结构在本机返回HRESULT `80070057`，底层扩展错误
在调用前后均为65535，原型保留测试伪错误12291；双宽 A/W 各一组。这只
说明该无效参数场景，没有验证真实打印、内部嵌套或其他系统版本。

## 产品边界

另行试验让旧式框正常处理确认，临时把测试用 `OPENFILENAME` 的容量设为 2，
期待系统自己产生 12291，而无需模拟错误接口。使用实际选中的长文件时，
本机 x86/x64 Unicode 两组得到 12291；ANSI 两组则返回成功和错误 0。
因此这一方法没有跨 A/W 的可靠证据，且运行时更改结构容量的兼容性也没有
得到保证，不能用于产品。该探索仅运行于自有隔离进程，未修改用户文件。

以上只在自有测试进程中对解析到的真实API入口打补丁；没有接入ntw16s DLL、
没有全局hook或修改系统设置。原型缺少真正可泛化的作用域/错误所有权协议，
尚未覆盖未列出的入口、普通成功与取消、任意嵌套深度、异步以及异常卸载。
S10多选文件枚举、应用确认、格式和编码也仍是独立未解决项。不能根据8类
错误参数对照认定可发布；产品多选继续保留Explorer路径。
