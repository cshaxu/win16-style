# M0 T18 S11 — bounded toolbar text

The existing limited VB OCX text-toolbar painter passed a fixed 512-WCHAR buffer to `TB_GETBUTTONTEXTW`, whose API has no buffer-size argument. A real native toolbar with a 700-character caption overwrote 189 guard WCHARs on both x86 and x64 with the old implementation. The replacement uses `TB_GETBUTTONINFOW` with `TBBUTTONINFOW.cchText`, rejects a full/truncated buffer, and retains native painting in that case. Ordinary initial and subsequently updated captions remain accepted; lengths 510 and 511 exercise the boundary. No Delphi-specific toolbar support is claimed.

The self-owned private-desktop probe exercises COMCTL v5 and v6 on both bitnesses; all four passed with the guard intact. The native API contracts are documented at https://learn.microsoft.com/en-us/windows/win32/controls/tb-getbuttontext and https://learn.microsoft.com/en-us/windows/win32/api/commctrl/ns-commctrl-tbbuttoninfow. This is a bounded protocol fix, not evidence that image, owner-draw, Delphi VCL or other unsupported toolbar variants are styled.

With desktop creation available again, a separate real-app run launched the self-owned 32-bit `D:\programs\misc\DoubleKiller.exe` (SHA256 `cdd83ab909db749992d11ace2dff671493c0568d7a14697f8bef4b06d8647ca8`) using the clean candidate. The loaded DLL was that candidate's `ntw16s32.dll` (SHA256 `21c9edeb6d36748268364d9f82258387105fe1f010b8e690a832a96bd0170cbb`). On each of four pages, the existing native probe reported 28 buttons, 3 edits and 2 combos attached, zero failures; the owned job exited with zero active processes. This is a real-app check of those controls, not Delphi-wide coverage or evidence of this application's toolbar.

The clean x86/x64 build passed source, original-graphics and ABI gates. The actual four-file package passed 91 cases in 345.40 seconds with zero skips (physical input and the separate core matrix were not run). The tested four SHA256 values were published to both `assets/` and `O:\winnt\system32`, with all eight destination hashes matching. No product graphics or public ABI changed. Delphi-specific TToolBar/TStatusBar ownership and application rendering still require their own evidence; the OCX-only parent/module gate was not generalized from its class name.
