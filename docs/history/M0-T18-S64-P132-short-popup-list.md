# M0 T18 S64 P132: short value-editor popup lists

The P131 real Delphi XE x86 sample's list has 13 items. Reducing it to two items caused USER32 to remove `WS_VSCROLL`; P131 then failed the live identity check and left the list frame native. Selection still returned the expected value. The creation-time contract, including the original scrollbar style and the `TValueListEditor` / `TInplaceEditList` ownership hierarchy, remains unchanged. Only the live requirement that a scrollbar remain present is removed; the same executable, thread, desktop reparent, border, non-owner-draw and USER32 LISTBOX paint-witness checks still apply.

In the real x86 96-DPI sample, an owned-thread probe changed the open list from 13 items to two, added 18 and returned to two. Attachment remained true through all stages while the system scrollbar style disappeared and reappeared. A same-window removal comparison with two items showed 500 changed nonclient pixels and zero changed client pixels; the font handle and two entries remained, selecting entry 1 returned its three-character Japanese text, the popup hid and capture was released. The owned process exited zero. These changes to the sample's list were test-side only; they do not establish behavior for arbitrary Delphi versions or real high DPI.

Self-contained x86/x64 native models cover the short list, long-to-short and short-to-long transitions, unchanged item selection and font, same-window client/nonclient pixel comparison, and the existing parent, owner-draw, paint-witness, scrollbar and destruction checks. P131 fails the short-list assertion at both widths. The clean C17 MinGW GCC/Ninja/ccache build, source receipt, original graphic identity and both ABI checks passed. The actual same-snapshot four-file package passed 26 focused cases in 21.17 seconds with zero skips, including startup, VB controls, menu cancellation and adjacent controls. Both publication locations matched the tested hashes and each passed both installed-width models. Full integration, physical input and other actual DPI/versions remain unverified.

The production diff is one line added and one removed; the model adds 11 and removes one, and package markers add two and remove two. Search `rg -n "rich_popup|WS_VSCROLL|ntw16s_rich_witness" src/ntw16s-dll/attachment.c` confirms that creation still checks the scrollbar style and the other rich-control identities retain their existing checks. The sample, temporary probes and package build are registered in `build/t18-s64-vcl-value-survey` and `build/t18-package/s64-short-*`. M0, T18 and S64 remain open.
