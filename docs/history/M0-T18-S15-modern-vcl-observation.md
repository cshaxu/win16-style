# M0 T18 S15 — modern VCL isolated observation

A byte-identical task-local copy of `D:\programs\RedAlert\cnc-ddraw config.exe` (SHA256 `e21131cca40be055b9cf728ed822474f2560793635fc323127b63ba9a838d5d6`) was launched in a private desktop and owned kill-on-close job, using a synthetic `ddraw.ini` in its own task directory and `CNC_DDRAW_CONFIG_FILE` pointing there. No settings buttons were pressed. The original game-directory `ddraw.ini` remained SHA256 `47bc143a85fe84a0cc6c9ead9a0d12b8ff6c51395f84be8ca4846d6555633f85` before and after. Both bare and styled owned instances exited zero with empty jobs. Upstream [configuration source](https://github.com/FunkyFr3sh/cnc-ddraw/blob/master/config/ConfigFormUnit.cpp) documents a settings-path override and executable-directory fallback, but current upstream source has not been proven to correspond to the local binary.

At 144 DPI the styled copy loaded the published 32-bit DLL; the main form and five `TComboBox` windows report attachment. Captures visibly show the classic title and combo frame, while four `TToggleSwitch` controls, `TPanel` containers and application-drawn text remain modern. This establishes the observed gap, not a claim of complete application support. Each toggle is owned by the application EXE, has zero class extra bytes, and is not a native BUTTON subclass. `BM_GETCHECK` returned zero for all four, including visually different states. `AccessibleObjectFromWindow` returned generic client role 10 and no default action; its state did not identify the visually on/off difference. A separate C UI Automation client returned a null `IUIAutomationTogglePattern` for all four, despite successful element and pattern-query HRESULTs. These results do not prove all VCL versions lack public accessibility support.

A safe implementation must first trace this exact owner's drawing calls and bind them to the owned HWND/DC without decoding private VCL fields, swallowing callbacks, guessing state, or changing application settings. A direct BUTTON-style replacement using the tested state APIs is unsupported by this evidence. Further investigation and any implementation remain for a later S; existing caption, font, graphics and classic controls stay unchanged. Physical input, keyboard semantics, additional pages, other DPI, and other VCL versions are not covered.

The fresh S15 candidate independently reproduced the observation and cleanup, loading its own `ntw16s32.dll` (SHA256 `1aef99cc26b5f2381ca20cc1b4a4b8f8c4f0e3321d2b5a0c310c029dcdc8bf7d`); source `ddraw.ini` remained unchanged. A module snapshot of the visible owned instance included UxTheme but did not list GDI+ or Direct2D; this snapshot alone does not establish which APIs drew the toggle or exclude later dynamic loading.

The first S15 actual-package matrix failed `menu-cancel-x86` in scenario 0: the 2.5-second timer fired after 176 repeated paint observations; this run overlapped the optional modern-VCL observers, but causation is unproven. A subsequent standalone run against the exact same candidate DLL passed all 15 cases in each DPI context. The original failure remains recorded; no assertion was relaxed and a fresh full package run was started without extra observers.

The second full-package attempt passed the previously failing x86 menu test but failed `tree-v6-64` because the styled x64 worker exceeded its existing 10-second deadline while executing the last of 18 variants (`wait=258`, 10015 ms); it did not report a rendering assertion failure. A subsequent standalone run of the same candidate passed all four bare/styled and DPI contexts, with worker durations 1.5–4.8 seconds. The cause of the intermittent timing difference remains unknown, and the original deadline and assertions were not changed. A further package run uses two concurrent slots to distinguish resource pressure; its outcome is reported separately.

The third full-package attempt (two slots) ended inconclusive because this agent read `progress.json` while the test runner was writing it, resulting in a sharing violation. No product assertion failed at that stop; this was an observer/test-runner coordination error. A fourth run uses the same package and two slots without reading the live progress file. The earlier menu and tree failures remain independently recorded above.

The unstyled owned copy also returned four null UI Automation Toggle interfaces with successful element and query HRESULTs, so this observation is not limited to the injected copy. The fourth full same-package run passed 91 cases with no skips in 540.52 seconds at two slots. Physical input and the separate full integration matrix remain untested.
