# M0 T20 S16：默认文件快捷方式解析

## 根因与范围

S15 实际对照发现，现代 GetOpenFileName 默认对所选文件快捷方式返回目标，
系统旧框对同一绝对 .lnk 路径返回快捷方式本身；现行桥接将默认新框转旧后
因此返回错误对象。显式 OFN_NODEREFERENCELINKS 的行为由 S15 保留。

本次在桥接旧框的确认 hook 中，对符合白名单、带筛选、非 NOVALIDATE 的
普通 Open 请求，尝试解析绝对盘符路径或旧式列表选中的单一文件名 .lnk；仅当目标是现存绝对盘符路径
的普通文件时，把目标交还系统旧框继续确认。系统负责文件校验、偏移和缓冲
错误；不伪造 CommDlgExtendedError。线程独立上下文按嵌套作用域恢复。
保留链接标志、无筛选、Save、其他 API 和不符合条件的请求不启用该处理。

文件目录快捷方式、带子目录的相对路径、UNC、断链、虚拟对象、长于 MAX_PATH 的路径及
目标不存在等尚未实现或验证；解析失败时维持之前行为。不能把该有限路径称为
全部链接语义兼容。COM 公寓初始化若已处于其他模型则沿用现有公寓；辅助初始化
仅在本函数成功初始化时配对释放，原始 LastError 在 hook 中保留。
