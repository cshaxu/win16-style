# M0 T18 S64 P97: NumberBox spin input and state

A self-owned DelphiVCL4Python 1.0.7 NumberBox at actual 144 DPI received posted WM_MOUSEMOVE, WM_LBUTTONDOWN and WM_LBUTTONUP in that order, all at the right button's target-relative (240,6). In compact mode the value and OnChange moved 72 to 73; in inline mode the right button moved 72 to 71. Both results and the two callback values matched on x86/x64 for a bare process and P93 assets. A test-only same-thread subclass saw capture acquired during down and released during up; the test observer's IAT and subclass were removed and target/launcher exited zero with an empty owned job. This is native synthetic input, not physical input. Four negative self-owned runs omitted WM_MOUSEMOVE: both architectures and both layouts remained at 72, with no second callback during the bounded wait. This explains the earlier technique's failure for these samples, but does not prove a general VCL contract.

The previous hypothesis that GetCursorPos failure caused the click failure was not established. A temporary runtime IAT observer saw GetCursorPos fail on the private desktop in some runs; the successful movement-and-click cases worked without faking it. A trial returning a simulated position without a preceding movement did not trigger the click. That temporary override was used only in one owned test process and restored; the reported dual-width success and negatives did not use it.

A longer-lived test-only StretchBlt observer drew the P95 temporary raised frame through movement, down, and up. For both widths and layouts its real numeric callbacks and capture behavior matched a corresponding observer-only baseline. This proves only these specific behaviors, not production safety or visual correctness. Source-buffer sampling on both widths showed a concrete state issue: compact top button's uniform background was white normally, RGB e1/e1/e1 after movement, cd/cd/cd during down, and e1/e1/e1 after release; inline right button's corresponding pixels were 9b, 89, 7d and 89. Different source hashes confirmed distinct bitmaps. These are observations in a particular configuration, not stable state identifiers. The prototype always draws a raised frame even during down, and has no reliable ownership discriminator, so it must not ship as-is. Other button, disabled state, range commit, physical input, other DPI and runtime versions remain open. No product or binary changed; both installed directories remain P93. T18/S64 remain open.
