# M0 T18 S64 P160: Delphi data navigator button backgrounds

The author of [Rosi Components](https://www.rosinsky.cz/delphi_download/) provides compiled demonstrations and project sources for testing without component installation. The private compiled archive `RosiCompDemosCompiled.zip` has SHA-256 `617d66b084b94095b2fca2508d0dc99692b4241939c041a7f33186685016f358`; the companion source archive is `70e431c21f32684d6052cdd75a7086ed5373e305a69f1f4186abe0c0d51ac8ce`. Only the sample EXE, its private demo MDB and corresponding form/source were extracted to registered scratch. The i386 EXE hash is `831ac77761f6ad9237558c1c7d00f35fd44911289b689470e07563fa4afe5010`; the MDB was `06e96fcd0e0959c5f9f4a675f9c44ac42667682f899972e5b8627819b6fac50c` before and after each run. No third-party source or graphics were imported into the product. A separate Ethea data-aware installer was also investigated; innoextract 1.9 and a newer external build could not parse v1.4.1, and the readable v1.3.4 contained no compiled sample. None of those installers was executed.

The Rosi sample exposes one application-owned `TDBNavigator` window, with no child button HWNDs. In the same window and application-module `WM_PAINT` scope it draws BUTTON-theme part 1 at per-button window origins; observed states are normal 1, pressed 3 and disabled 4. The bounded change recognizes only the exact same-thread, same-parent-owner class, and replaces these witnessed button faces using the existing renderer after the native theme call. It validates DC ownership, map/layout, origin, client bounds, theme and caller; application glyphs and actions remain application-owned. Hot and unknown states keep their native drawing. Source controls reparented or invalidated retire the attachment. No public export or original resource changes.

The actual clean candidate x86 DLL `f1e629c0db25a99780055fd47cf2ba6293332be3b68644f5cfd49a08c719c8ca` ran the isolated real sample. Normal 596x25 navigator images had 14,537 differing RGB pixels versus the published baseline; all 294 dark pixels in the ten checked icon regions matched. In the next-button pressed capture, all 32 checked dark icon pixels matched. Clicking next then previous by messages changed 17,471 grid pixels then returned to zero difference from the initial image. Both instances exited zero, capture was released, and the private MDB hash remained unchanged. The ink comparison is bounded to the stated thresholds and regions; it is not a proof for every possible icon color or application.

Dual-width self-contained native models cover normal, pressed, disabled and hot fallback, black glyph preservation, partial clipping, wrong parent, wrong caller, invalid origin, click delivery, reparent and cleanup. The old published DLL fails the positive attachment case on both widths; an x86 scratch fault omitting caller verification fails the foreign-caller assertion. One initial build failed because the model's resource include path and function-pointer casts needed correction; it was not counted as passing. Original-resource and ABI checks passed, as did the clean GCC/Ninja/ccache x86/x64 build and 28 actual-package focused cases in 15.45 seconds with no skips. Both published locations match the tested four-file hashes and pass the dual-width model. Physical input, additional data actions, hot style, disabled-parent behavior, other VCL versions/DPI and full integration remain unverified. M0/T18/S64 stay open.
