# T26 S1 公共样式依赖检查

对当前工作区的 `src/lib-style/common`、`src/lib-style/uwp` 和
`src/lib-win32/style` 搜索包含路径、符号及大小写不敏感的 Win16/Win2000
产品名称，未发现直接引用。搜索不能证明所有间接依赖或运行行为。

使用现有 `build/.ninja/x86` 和 `build/.ninja/x64`，构建全部 12 个
`style-*` 静态库目标，Ninja 均报告无需重建；随后对共 24 个归档执行
`nm -u`，未发现名称包含 `ntw16s`、`ntw2ks`、`win16_` 或 `win2k_` 的
未解析符号。x86 下的前导下划线也纳入匹配。此检查仅覆盖这些命名模式和
当前 24 个归档，不证明所有风格无关性，也不覆盖源码未参与的构建目标。

后续新增 `tools/check_style_boundary.py`，并在 `Build-Package.ps1` 的干净
源码检查与双位宽静态库检查中调用。当前源码、自检负例和 x86/x64 各 12
个归档均通过；来源及治理自检通过。检查按产品和具体风格名称匹配，不能
识别通过中性名字隐藏的私有契约，也不能替代完整调用审计。该构建门禁
尚未经过下一次完整干净包构建。

两种样式均实际调用的公共能力和未接入的能力仍须逐项核对。现有候选未
完整发布或提交；UWP 分发及 Win2000 DWM 恢复失败仍未解决。
