# M0 T21 S17：真实 UAC 组合的隔离验证

本 S 调查普通控制台启动器、真实 UAC、全局会话、双宽目标及退出能否在自有私有桌面串成一次实测。独立原生对照不运行全局样式：父进程确认运行在 `Win16S-Dialog-37892-279880796`，进入 `ShellExecuteExW` 后等待；驱动 35 秒超时（258、返回 99）并清理自有进程，未记录提权子进程桌面。用户反馈没有看到系统 UAC 提示。此结果不能证明系统不支持或产品失败，也不能代替完整组合测试。

本 S 未修改产品源码或发布二进制。纯 C、GCC、Ninja、ccache 同快照双位宽干净构建通过；该新构建的四文件实际包 22 项聚焦回归通过且无跳过，完整矩阵和物理输入未覆盖。测试包 SHA-256：run16s.exe `1182c997feee208b814bd089a615450e2cb483f4ad361264efa2712aaf01d9eb`；ntw16s32.dll `23f506bff59dead844558e4b1d58f6bd289c36b2dfed1be266feaf90cf6825c3`；ntw16s64.dll `d5db6a76c0fdb82502e66c5a288805b9869755d6a403bd29a2f2c163f09d2031`；demo.exe `d9499d418dc9ce45ece362871ff766e1723286eccc68dc7ccb500edbe7b8ef47`。这些 SHA 与已发布 S16 文件不同，不能将新测试包当作已发布包；同源码重建的时间戳和构建目录符号等差异在 S16 曾有有界分析，本次不宣称所有字节差异均已解释。

真实 UAC 冲突退出、管理员双宽全局接入、正式提权后入口和 Ctrl+C 分项证据见 [S16](M0-T21-S16-console-output.md)，不得将其合称为原始包跨 UAC 完整组合通过。此前私有桌面保留引用的来源未明，属于测试环境未解决事项。T21 保持开放。
