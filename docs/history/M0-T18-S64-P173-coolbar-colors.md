# M0 T18 S64 P173: preserve custom CoolBar colors

P169 can draw its classic grip even when the application sets a band foreground/background or a rebar-wide background/text color. A same-process dual-width native superclass fixture demonstrated attachment and the color values surviving readback in the old package while the grip was painted; that establishes the guard was missing, not a pixel-level comparison of the original colored grip. The new guard queries RBBIM_COLORS and the native rebar background/text colors, with identity checks after each native-procedure query. It accepts the measured default sentinel CLR_NONE or corresponding system color for the bar, and requires the band colors to match the corresponding system colors. Other values are left to native drawing. Existing ownership, content, geometry and lifecycle checks remain. Application-set values equal to system colors are indistinguishable but do not change the expected color.

The self-contained dual-width fixture covers individual band foreground/background and bar-wide foreground/background colors, verifies readback and that no grip was painted; each case passes on the final package. P169 failed the first three cases on both widths in a diagnostic run; the fourth was added afterward and is not claimed as an old-package negative. Default noncolored real GoVCL TCoolBar with two VCL buttons passed x86/x64 and COMCTL 5.82/6.x, with 212/380 changed pixels inside the grip, zero outside and unchanged child positions. The custom-color cases validate readback and no attachment, not complete pixel identity or all theme/version combinations. Current system colors and 96 DPI were used; runtime system-color changes and other Windows/VCL/DPI remain unverified.

The first candidate failed the real default sample and actual package test: 0xffffffff was initially confused with CLR_DEFAULT; real native and ordinary queries both showed that value and the code now tests CLR_NONE. The failed candidate was not published. Scratch model compilation emitted a multiple-manifest warning and a later diagnostic edit initially failed -Werror for indentation; formal CMake uses its explicit manifest. The actual package passed 20 focused cases in 14.63 seconds, zero skips.
