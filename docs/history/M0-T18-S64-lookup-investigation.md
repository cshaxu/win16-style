# M0 T18 S64: Delphi data lookup investigation

A private x86 copy of the vendor XDB data demo was run on a private desktop in a kill-on-close job. The executable copy has only the test locale initializer import added; the original sections and the private MIDAS dependency are documented in [the data-aware investigation](M0-T18-S64-data-aware-sample.md). This is one sample, not a claim about every VCL version. The published P153 package was the baseline; a separately built x86 scratch DLL was used for diagnostics and was not published.

The visible `TDBLookupComboBox` was ANSI, owned by the application image (class and parent owner `0x00400000`), with style `0x54010000` and extended style `0x00000200`. `GetComboBoxInfo` returned false with last error zero; `CB_GETCOUNT` and `CB_GETDROPPEDSTATE` both returned zero. These observations do not establish normal COMBOBOX protocol support. A targeted observation of the control window DC recorded `DrawThemeBackground` part 1/state 1, rectangle (100,0)-(117,17), with caller and class owner both `0x00400000`; the theme was tracked as COMBOBOX. Another call used the full (0,0)-(121,21) rectangle and was not a tracked combo theme. This observation does not establish other states or all paint paths.

A private input probe focused the control and delivered left-button messages at (110,10). It observed the separate visible `TPopupDataList` in the same owned job. The focused window remained the lookup control; after an Escape key message the popup was still reported visible. This is not a successful cancellation test and does not establish behavior for physical keyboard input. The demo target exited with code zero after the subsequent test. A first rerun using relative executable paths failed to find the window and was not counted as a pass; an absolute-path rerun succeeded.

A scratch-only experiment extended the existing `TInplaceEditList` identity gate to the observed ANSI lookup class and reused the existing dropdown draw path. No production file was changed. The 121x21 PrintWindow images before and after the experiment had zero differing RGB pixels. Instrumentation at the combo theme call saw no active `static_paint` scope, including after explicit invalidation; this narrows the next investigation but does not distinguish failure to attach from another paint-dispatch path. The diagnostic DLL and its logging must not be published. The first scratch build request used a nonexistent target name; the actual `ntw16s` target was then built. A sandboxed build stopped making progress and was interrupted; an unsandboxed scratch build completed.

Next: independently establish attachment and the exact message/paint path, including ANSI subclass semantics; then demonstrate actual button pixels, popup selection/cancellation and binding preservation before proposing a bounded production change. Dual-width model, real sample, negative cases, accessibility, resource lifetime, other runtime versions and DPI remain unverified. Scratch is registered under `build/t18-s64-vb-mask-survey` in CURRENT.
