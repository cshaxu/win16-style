# M0 T18 S64 P105: NumberBox numeric mode and focus comparison

Self-owned DelphiVCL4Python 1.0.7 x86/x64 TNumberBox samples at actual 144 DPI compared the pre-NumberBox P89 package with the published P93 package. Integer, float and currency modes were explicitly selected; the currency sample also set CurrencyString to `USD`, though the observed edit text did not contain that symbol. P89 did not attach the TNumberBox; P93 did. For integer, replacing the first selected digit through posted WM_CHAR changed text/value 42/42 to 72/72; for float and currency, 42.50/42.5 changed to 72.50/72.5. Actual OnChange output matched between packages on both widths. Final screenshot comparisons in the edit region differed by 940 integer pixels, 1123 currency pixels, and 1427/1123 float pixels on x86/x64; no claim assigns all differences to glyphs, focus or renderer.

A separate set sent WM_CHAR `X` after the valid digit and checked synchronous delivery, text and change event. Across all three modes and both widths in both packages, text was unchanged and there was no additional OnChange signal. This is a bounded test of one invalid character, not OnValidateChar override, paste, IME or all input validation. The earlier observer's EM_REPLACESEL can insert a nonnumeric character; that direct edit message is a different path and was restored before event registration.

With MinValue 0 and MaxValue 50, a real VCL OnExit handler and a separate ordinary button, the owned driver verified GUI thread focus first on the number box and then on the button after WM_NEXTDLGCTL. The entered 72 or 72.50 was clamped on leaving focus to 50 or 50.00 in the respective modes. Across both widths and packages, the OnExit log held the pre-clamp value, and the OnChange logs contained the entered value and then 50, with matching text/value output per package. The explicitly set currency string was not seen in the edit text; currency-symbol display/format after blur has not been independently verified. All 12 focus-comparison targets and launchers exited zero and owned job counts were zero; the observer restored its import and the original temporary text before registering handlers. Additional invalid-character and mode-comparison targets also exited normally. Physical input, other limits, locale-specific separators, precision, NaN, currency formatting, expression evaluation, custom validation and other VCL versions/DPI remain open. No production source or binary changed; both deployments still match P93. T18/S64 remain open.
