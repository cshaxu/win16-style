# M0 T18 S64: Delphi popup menu investigation, prototype only

The self-owned DelphiVCL4Python 1.0.7 sample at 144 DPI uses an ordinary TPopupMenu. Its x86 context-menu notifications go to a hidden, same-thread `TPUtilWindow`; the published DLL leaves the ordinary item native (`fType=0`). The normal menu and nested submenu on both x86 and x64 did enter the existing renderer (`fType=256` while open), and `Esc` restored the original item type and command ID. This evidence does not establish that every Delphi version uses the same owner or menu API.

A scratch-only creation-time attachment returned attached but did not receive the observed menu messages or change the menu; the precise reason for the bypass was not independently established. A separate scratch-only prototype intercepts `TrackPopupMenu`, temporarily subclasses an eligible same-process, same-thread hidden `TPUtilWindow` without changing its frame, and reuses the existing menu path. In both real x86 and x64 samples, its log showed `WM_ENTERMENULOOP`, `WM_INITMENUPOPUP`, then item type 256 while open, and type 0 after Escape. In both cases the menu loop exited and the owned sample closed. Main-menu nested open and restoration also passed. The model does not yet prove application callbacks, arbitrary owner-draw items, nested context menus, abnormal exits, DPI transitions, other APIs or lifetime safety. The x64 first attempts failed due to missing PYTHONPATH and an outdated observer export; only the corrected run is counted.

Logs and images are in registered ignored scratch `build/t18-s64-vb-vclmenu` (`proto32e`, `proto64d`, `tracktrace.txt`, `styletrace.txt`); temporary mixed diagnostic DLLs are under `build/t18-s64-vb-groupbox`. These are not a product package. Creating an isolated desktop returned error 5 under the sandbox; the successful owned probes ran with the required environment permission, without computer-use or touching other processes. No product code or binaries changed and no release was made. The prototype needs bounded, self-contained double-width negative and cleanup tests and actual package testing before adoption. M0/T18/S64 remain open.

A later scratch-only refinement records eligible windows at the return of their observed creation API and requires the creating call site and class module to match. The scoped removal is tied to the calling scope, and the existing native unwinder is used for cleanup. A project-authored model ran without the DLL, with the candidate, and with the old published package. Both widths passed with the candidate for original application initialization data, existing owner-draw item data, unchanged owner geometry/style, rejection of a different class and a visible owner, and destruction of the owner during the popup. Both old packages failed the ordinary-item styling assertion as expected. The real Delphi samples also passed on both widths with the refined candidate. Model and candidate remain ignored scratch, not the actual delivered package; nested popup reentrancy, exception unwinding, source ownership rejection, DPI changes and complete resource accounting still require evidence.

Additional self-authored scratch models used `TPM_RECURSE` to open a second popup on the same owner: both widths retained the outer item while the nested item restored, and both returned after the outer item restored. The first attempt omitted `TPM_RECURSE`; the native control also failed to enter the nested loop, and that attempt is not counted. An independently compiled test helper created the same-named class from a different module: both widths correctly stayed native, while the actual two runtime samples still styled. The call-site check now occurs only after inexpensive class/style tests.

An exploratory x86 exception test raised in `WM_INITMENUPOPUP`; both native and candidate processes terminated with `0xc000041d`, so it established neither unwinder cleanup nor a candidate regression. The aborted worker was the isolated, owned test process. Further work must use a valid exception test mechanism or preserve this limitation. No delivered source or binary changed.
