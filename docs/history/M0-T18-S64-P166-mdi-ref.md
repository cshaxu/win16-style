# M0 T18 S64 P166: release MDI host reference on failed attachment

In P163/P165, `install_created` increments the host attachment reference for a Delphi MDI child before calling `SetWindowSubclass`. If that exact call fails, its early cleanup released the popup source but omitted the MDI host. The normal detach path already releases both references. The corrected failure path releases the host and saves/restores the original last error around cleanup. This is a failure-path defect; no normal-operation leak was demonstrated. ABI and graphic resources are unchanged.

The self-contained dual-width native fixture patches only its own injected DLL import slot and forces `SetWindowSubclass` to fail once for the exact MDI child attachment callback. A white-box read of the host reference reported `before=0 after=1 forced=1` with P165 on x86 and x64 (new assertion fails), and `before=0 after=0 forced=1` with the correction on both widths. The patch is restored immediately and only owned instances are used. The PowerShell driver uses MinGW nm/objdump against the exact tested DLL for its private callback RVA. An initial fixture imported GetWindowSubclass by name and failed at load with 0xc0000139; resolving ordinal 411 fixed the test. An independent attempt to observe the error through the creation scope reported zero and did not establish error propagation; preservation of the error is implemented but not independently verified end to end. Actual resource exhaustion was not induced.
