# M0 T29 S4 代表部件

## 范围

标题栏、普通按钮和滚动条按同一批主题数据完成解析、布局、呈现与命中。先证明文件数据进入既有绘制入口，再接入正常应用和恢复流程。以 S2 台账和 P45 原生回归为基线。验证覆盖 Win16 与 Win2000、x86 与 x64、96 与 144 DPI，以及三类部件适用的普通、按压和禁用状态。

## P1 首批只读模型与标题颜色

`classic_theme_load` 按尺寸和配色选中标准变体，从 PE 资源读取类表和属性，并解析标题按钮组扩展。结果是调用方拥有的值快照，加载失败保持原输出，资源映射在返回前释放。P1 加入标题颜色、按钮和滚动箭头的填充与边缘颜色，后续再接入其实际几何和状态。

双宽自有探针用同一对成品主题，复用已有 Win16 标题栏绘制及命中入口和 Win2000 标题渐变绘制入口。在 96/144 DPI 分别验证激活和非激活色。临时各复制一份主题，分别将标准 `FILLCOLOR` 和 `GRADIENTCOLOR1` 改为 RGB(37,77,123)，两个位宽的两套既有绘制入口都读到了变更后的实际颜色。无效尺寸名返回资源名错误且保持输出。变色副本验证完毕后删除。

P1 的消费点为自有原生探针。现有产品和发布包尚未绑定主题文件。后续需让按钮组、普通按钮及滚动条进入既有布局、绘制、命中和恢复路径，并完成 S4 回归。

## P2 标题按钮槽与三部件消费

- 主题生成器与两种默认布局共用按钮分组定义。旧左右槽循环合为 application/window 的同一套几何计算，保留 Win16 窄标题裁剪和 Win2000 允许退回系统矩形的约定。
- 同一正常构建生成独立 v4 资源文件和双宽 COFF 资源。两种现有外观 DLL 各自带对应风格的数据，窗口和控件附着时只读取自身映像资源。读取结果由各窗口或控件状态拥有，随现有 detach 释放。Win16 显式传入的客户调色板优先。八文件包形状和启动机制保持原契约。
- 正常 Win32 标题栏改用主题颜色和槽位，Win16 标题栏命中及客户区测量共用槽位结果。普通按钮使用主题填充色与边缘色。滚动箭头使用主题填充色和边缘色，保留原 Win16 栅格及 Win2000 GDI 绘制和实际滚动范围。混合 Vista/WinUI 的宿主布局、系统度量和控件的其他色彩状态仍由既有路径提供。
- 将四个构建 DLL 映射为数据，用 Windows 资源 API 验证实际链接数据与同源独立文件逐字节相同。Win16 每宽九项，Win2000 每宽八项。独立主题四件仍匹配 S3 P5 摘要。
- x86/x64 探针分别通过对两份主题的标题、普通按钮和滚动箭头的颜色替换验证，按钮检查启用普通、按下及禁用，在自有窗口内发送现有消息。标题栏和滚动箭头在 96/144 DPI 绘制。未以离屏证据代替真实桌面焦点与物理输入。
- 增量 DLL 测试每宽 7/7 通过，包括 Win16 布局、Win2000 标题栏、框架附着及恢复、按钮、滚动几何，以及 Win16 的呈现与 DC 失败恢复。两项 Win16 测试首次误缺捕获目录，按既有工具要求传入私有 scratch 后均通过。两处已发布八件的 P45 SHA-256 全部匹配。
- 正常 DLL 入口使用独立、自有的非激活窗口对照，临时复制两种 DLL 并改 `VARIANT/NORMAL` 的按钮/滚动箭头填充色和 `CLASSIC_STYLE` 的右边距。两年代、双宽、窗口实际报告 96/144 DPI、原色与改色共 16 组均通过。Win16 最大化按钮命中边界分别移动 8/12 像素，Win2000 关闭按钮矩形按同样增量平移。按钮三态和箭头读出改色，解除附着后原窗口保留且再绘制没有改色。探针使用当前桌面上的离屏自有窗口与同步消息。

效率检查将移除重复槽位、生成链接数据和真实已有绘制入口合为一批。仅对已有增量树和临时变色副本运行开发验证，变色副本已删除；正式交付另保留一次同快照干净构建和发布后验证。

## P3 标题度量与滚动表面

主题源为普通标题、标题按钮和 Win2000 小标题写入标准 `TMT_HEIGHT`、`TMT_WIDTH`。Win32 附着时把度量与按钮槽保存在同一窗口状态。原 Win16 标题高度下限和 OEM 按钮随标题栏高拉伸的规则由布局保留，Win2000 根据工具窗角色选普通或小标题度量。

滚动主题按轴从标准 `SCROLLBAR` 部件提供滑块、轨道和可选尺寸框的填色与立体边缘色。当前两种风格的轨道在同一绘制通路中共用上下部件的配色。原有 Win16 棋盘、OEM 箭头与 Win2000 画笔、客户自有画刷、原生抓角及输入状态路径照旧。Win16 默认尺寸框仍取系统 `COLOR_SCROLLBAR`；含尺寸框属性的主题可指定底色。调用方显式提供的 Win16 调色板保持优先，旧资源可沿用原默认配色。选中资源只在窗口或控件既有状态内保存。

自有、非激活窗口使用增量构建 DLL 的原色和临时修改后的资源做 16 组对照。覆盖两风格、两位宽和窗口报告的 96/144 DPI。横纵轨道和滑块、尺寸框、按钮三态、标题栏高度和按钮宽度都观察到资源替换。Win16 以 `WM_NCHITTEST` 核对实际命中区，Win2000 以 `WM_GETTITLEBARINFOEX` 核对关闭按钮和标题区。解除附着后窗口仍可使用，控件已恢复到原绘制路径。原始五个图形头与来源声明摘要匹配。

同源候选的 Win16.msstyles SHA-256 为 `2dd0f1d3bf1b7a1566a15358443bc213f80463e6f10b8051cb76de7eeb613291`，Win2000.msstyles 为 `109208a1d48fcebce3dfc21942790e0b333abd7bcdf0375f64ca19daf5506c95`。与 S3 创建的两份 `.theme` 摘要分别一致。

## 下一批验证基线

原 `frame_buttons.h` 中的六帧均为 19×18。三种动作分别有普通和按下图像。系统菜单图像是同一张 36×18 原图的两块 18×18 区域，分别用于顶层窗口和子窗口。系统菜单按下时原绘制交换调色板角色，保留这条规则即可覆盖两种系统菜单的按下状态。把这六帧和两个裁片映射到主题后，分别核对 PNG 解码像素和实际绘制。后者用一处改色角色证明标题按钮从主题取图，并核对应用提供的调色板仍能重映射角色。

已有双宽基线共 12 项通过。短条、非标准厚度、纵横转置、原生表面坐标、标题按钮的按压取消和普通按钮原生状态均有现成测试。Win16 `core-geometry` 每宽运行 791877 条断言。后续新增测试聚焦主题资源替换后绘制与命中是否仍使用同一几何。

目前的 Win16 最小化图已用独立 C 原型验证。它以只读模式打开 `.msstyles`，用 Windows 自带 PNG 解码器恢复四个调色板角色。x86 和 x64 各在未初始化 COM、已有 STA 和已有 MTA 下核对全部 342 像素。尺寸错误保持调用方缓冲区原样。由此可以让标准图像本身承载角色，主题无需额外复制一份私有像素数据。探针 EXE 已删除，`build/t29-package/s4-caption-p4-prep` 下两个小型源码暂供接入与移植测试，完成后删除。
