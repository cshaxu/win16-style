# M0 T18 S64: Delphi TAnimate real sample investigation

A self-owned scratch copy of the x86 DoubleKiller executable (SHA-256 `cdd83ab909db749992d11ace2dff671493c0568d7a14697f8bef4b06d8647ca8`, matching the source executable) was launched on a private desktop in a kill-on-close job. A target-thread, task-owned native WH_CALLWNDPROC observer examined its visible TAnimate without opening files or starting a scan. The observer was unhooked and both target and launcher exited zero; the job reported zero active processes.

The bare and P163-styled runs both exposed `TAnimate`, visible/enabled, style `0x54000003`, extended style zero, with a 517x50 client inside a 517x50 window and zero nonclient margins on every side. The styled run's observer independently obtained the assets `ntw16s32.dll` and confirmed its root form was attached; the bare run saw no style DLL. In this sample there is no separate nonclient frame to replace. The ANSI class procedure belongs to the executable and differs from the same-encoding registered `SysAnimate32` procedure; this comparison alone does not prove what that procedure calls during animation. Its application-provided content is preserved under the user's scope decision, rather than intercepted on class name alone.

This does not establish that all TAnimate variants lack a border or need no work, nor does it establish AVI playback, transparent background or DPI behavior. Keep the family unverified until variants are checked; do not count this observation as an implementation. Full local evidence and task-authored sources are in registered scratch `build/t18-s64-vb-mask-survey/animate-*`.

Two preliminary runs failed: the first restricted-environment observer did not report in time; the second found the control but checked the job before process-exit accounting completed and observed one active process. A bounded completion-port wait corrected that diagnostic race; the final bare/styled runs above passed. The earlier styled run without the separate target-thread DLL/root proof is not used to claim attachment. No product code or binaries were changed; M0/T18/S64 remain open.
