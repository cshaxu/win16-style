# M0 T18 S64 P103: same-owner number box draw negative

A self-owned dual-width C fixture registered its own window class in a DLL. Three WM_PAINT modes in that same class-owner DLL created a 17x14 memory bitmap, then copied it with StretchBlt to the fixture window at (231,2). Mode 0 drew the four exact compact up-arrow lines observed in P101; mode 1 drew the same background and lines, plus a distinctive magenta internal application pixel; mode 2 drew a plain background without lines. A test-only observer temporarily patched only the fixture DLL's LineTo and StretchBlt imports, required caller module equal to class owner, destination WindowFromDC equal to the target, same source DC, four exact start/end coordinates, dimensions, destination and SRCCOPY, then overlaid the P95 raised frame. It did not patch any system-wide entry point.

In both widths, mode 0 and the simulated application image in mode 1 passed the exact same-owner/geometry checks; the sampled outer pixel changed from white `ffffff` to gray `a0a0a0` in both, and the mode 1 inner magenta marker remained. Mode 2 was rejected and its pixel remained white. Thus this specific ownership-plus-geometric predicate can alter a simulated same-module application image even if its overall background matches. This is a purpose-built C model, not evidence that an actual Delphi application invokes this collision, nor proof that every stronger source or callback discriminator fails. It shows why the currently proposed predicate alone is insufficient for the user's application-draw exclusion.

The first run used the startup SW_HIDE default and the root and child were not visible; it observed invalid pixels and is not a pass. After explicitly hiding then showing the root, a first sample at a naturally white raised corner did not distinguish the frame; sampling the opposite inner edge produced the reported valid contrast. Both final test workers exited zero on private desktops and restored the modified IAT slots; the model does not separately report worker job accounting. Source is task scratch, not a product dependency. No product source, binary or deployment changed; both published directories still match P93. Real same-owner application callback, robust source lifecycle witness, state transitions, additional DPI and versions remain open. T18/S64 remain open.
