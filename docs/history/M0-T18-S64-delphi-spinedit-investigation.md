# M0 T18 S64: modern Delphi SpinEdit investigation

The released P108 package was observed in isolated DelphiVCL4Python 1.0.7 x86 and x64 samples at 144 DPI. The ordinary `TSpinEdit` with value 42 and its `TSpinButton` child were both runtime-owned, not attached; registered and RealGetWindowClass names were their own names. The parent was 300x36 and the button 15x31 in the DPI-aware observer. The editing window had 4/8 class extra bytes in x86/x64. Unlike the previously supported 32-bit DoubleKiller variant, the owner was DelphiVCL.pyd and USER did not report EDIT as its real class.

A temporary runtime IAT observer saw both EM_GETSEL and the edit's own WM_PAINT forwarded to the registered system EDIT procedure in each width. The initialized public EM_GETLIMITTEXT, EM_GETSEL and EM_GETRECT returned nonzero limit, selection and nonempty rectangle, respectively. Observer imports were restored; both owned targets and launchers exited zero, with empty jobs. The IAT observer changes immediate caller identity and is diagnostic only. It did not test value changes, clipping, font, arrow states or more versions. The registered EDIT style bits include ES_MULTILINE, which must not automatically imply this spin edit is an ordinary multiline memo for scrollbar handling.

The edit surface can be investigated by adapting the existing witnessed EDIT protocol for exact TSpinEdit, preserving the application value and native input. The separate TSpinButton still requires an independently validated drawing/owner path. Candidate acceptance requires actual dual-width value and input comparison, independent models for witness/caller and lifecycle, existing legacy regression, clean same-batch package tests and both publications. No product/binary changed. T18/S64 remain open.
