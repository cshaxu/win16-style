# M0 T18 S64 P123: Delphi TScrollBox chrome

The [author's Delphi XE sample](https://mrxray.on.coocan.jp/Delphi/plSamples/075_TScrollBox_ScrollBar.htm) contains a Unicode application-owned `TScrollBox` with an image and two scrollbars. P122 did not attach it. Its registered class procedure belongs to the application module; the observed WM_NCPAINT reaches DefWindowProcW through USER32, whose address is the direct caller. A scratch-only import observer was restored after each observation. The archive and sample hashes and earlier negative prototype are recorded in [the investigation](M0-T18-S64-scrollbox-investigation.md); no sample source or resource is included in the product.

The bounded implementation requires the observed Unicode class, client edge, same-thread parent and class owners, a class procedure in the owning module, and a fresh nonclient-paint dispatch to DefWindowProcW for that same HWND. It reuses the existing frame and scrollbar renderer, preserving the application client painter. The new internal hook is part of the existing DLL; no public ABI or product file was added. Identity changes cause the existing owned style to retire. This establishes a bounded path, not blanket support for all VCL containers or versions.

With the actual package, the x86 sample at 96 DPI had 10,232 changed nonclient pixels and zero changed client pixels in a same-window symmetric redraw comparison. Both line-scroll positions moved 0 -> 8 -> 0; the lower arrow moved 0 -> 8, and the thumb drag reached 116 with capture released. The sample buttons changed scrollbar styles `56300000 -> 56100000 -> 56000000 -> 56300000`, restoring the original state. Three owned target/launcher pairs exited zero and their jobs emptied. Hidden-state pixels and physical input were not checked.

Project-authored x86/x64 fixtures cover wrong parent owner, absent and foreign-call witnesses, exception unwind and subsequent painting, reparent during witness, reparent after attachment, client-edge role change, nonclient change with zero client change and cleanup. P122 failed the new model's attachment assertion in both widths; the candidate passed both. The real application was x86 only. Broader versions, DPI, non-Unicode paths, physical input, custom nonclient drawing, full GDI lifetime and complete T18 integration remain unverified.

The C17 MinGW GCC/Ninja/ccache clean dual-width build and ABI gates passed. The same four-file package passed 27 focused actual-package cases in 22.43 seconds, with no skips. Both assets and O:/winnt/system32 matched the package's four hashes and passed x86/x64 installed models. Original graphics and provenance passed byte-exact checks. M0/T18/S64 remain open.
