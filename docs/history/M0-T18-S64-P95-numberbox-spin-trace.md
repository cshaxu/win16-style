# M0 T18 S64 P95: NumberBox spin rendering investigation

A self-owned DelphiVCL4Python 1.0.7 TNumberBox with `nbspCompact` and `nbspInline` was observed at actual 144 DPI on x86 and x64 using the P93 assets package. Temporary runtime import observers recorded four LineTo calls on each small offscreen DC, then StretchBlt SRCCOPY to the actual TNumberBox DC. Compact uses two 17x14 buffers at (231,2) and (231,17); inline uses two 17x29 buffers at (214,2) and (231,2). Rectangle geometry is sample evidence, not an identification or DPI rule. The runtime did not import the observed DrawThemeBackground entry through the tested import path; this does not rule out other theme or dynamic calls.

A test-only observer called the original StretchBlt and then applied DrawEdge to the two observed rectangles. Comparing whole-window DC snapshots against matching non-prototype runs showed 168 changed RGB pixels for compact and 258 for inline, identically on both widths; all changes were within the two outer two-pixel bands and zero in the inner rectangles or outside the button rectangles. This preserves the observed arrow interiors in that one normal sample only; it does not establish proper pressed, disabled, hover, custom color, DPI or visual fidelity. Import observers were restored, sampled target and launcher exit codes were zero and the owned job emptied in all eight runs. The temporary prototype is not production code or an approved implementation: it matches dimension and draw scope without a content-neutral source ownership witness and could misidentify matching application artwork.

An additional posted mouse-down/up test used the observed top-right point with client coordinates (240,6). Both posts succeeded but the old styled control did not change 72 and the callback event timed out after two seconds. This is a failed input technique, not evidence that the control's actual click fails or that the prototype preserves click behavior. P93's bounded keyboard/value comparison remains valid. No product source, binary, or deployed file changed in this investigation. The original unresolved ordinary-control scope remains open; next establish a reliable button-ownership/draw scope and a mouse input witness before considering an implementation.
