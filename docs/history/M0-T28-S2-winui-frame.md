  修正后用同一探针报告普通 22、最大化 26、还原 22；对应首个可见
  XAML 桥为 31、34、31，标题中部命中均为 HTCAPTION。以上为探针坐标，
  证明几何和命中。真实标签和菜单操作、关闭样式后的实际画面仍待验证。
- 增量测试覆盖原尺寸按钮像素、外框实例、合成重绘和 UWP 组合。
  沙箱中的 UWP 组合返回 ERROR_ACCESS_DENIED，普通 Windows 会话通过。
  未写入 O:/winnt 或 assets。Explorer 交叉验证、正式同包交付和远端复核待办。
- 本批复用 build/.ninja 两宽，无新临时构建。自有测试窗口已关闭，
  已核实并结束映射开发 DLL 的无窗口记事本残留。

发布缓存，现有占用进程保留。两个目的地逐件核对 SHA-256。

- 真实 WinUI 记事本在 144 DPI 普通、最大化、还原、调整尺寸均保留经典
  标题栏命中，首个可见 XAML 桥始终位于标题行下。File 菜单展开和收起，
  空白标签数 1→2→1，使用 Windows 原生可访问性 API 验证。
- Win32 演示和 WinUI 记事本关闭按钮均为 24×21，两份窗口 DC 的 RGB
  SHA-256 完全一致。真实 UWP 计算器两个风格均通过标准启动、最大化与
  还原、最小化、外框移除和几何恢复。普通屏幕 DC 和 UWP 分层 DC 均
  未返回有效像素，Win2000 计算器全项探针仍返回 1。
- 同包 x86 14/15、x64 15/16。两项失败均为已经登记的 Win32 DWM
  渲染恢复。发布启动器双宽另过各 8 轮经典窗口最大化及还原。
- 当前启动约定仍屏蔽默认 `--2k explorer`，共享 Shell 不做探针对象。
  Paint 探针未等到自有窗口。实际 WinUI 风格移除及恢复像素未验证。

摘要、命令和测试名见 [S2 实包记录](../etc/evidence/t28-s2-winui-frame.json)。

复查输入桌面为 Screen-saver，前台 HWND 为空。保留最终 UWP 像素取证，

## DWM 恢复修正

发布版 x86/x64 在首次绘制前移除均恢复 DWM。执行首次非客户区绘制后，
直接移除和公共包装均报告 `restored=0`。x64 对照可由一次 WM_NCPAINT
复现，重复设置 DWM 策略、重新计算外框、切换标题样式位及隐藏后重显均
不能恢复。仅给已解除子类的测试窗口发送 WM_THEMECHANGED 即恢复可观测
DWM 状态。经典外框现在只在原状态为启用、移除后仍禁用并且窗口没有被
重新附着时发送该通知。

增量构建后，生命周期、实例清理、标题像素、UWP 外框及重绘合计 10/10。
两宽再分别以直接移除和首次绘制前移除作为对照，4/4 报告
`restored=1 geometry=1`。窗口 DC 取色仍有差异，不能代表真实桌面恢复画面。
本轮诊断探针均已清除。修正版仍需干净构建、同包发布和验证。

另用只由测试进程创建的扩展客户区窗口和组合桥控制 A/B。两宽在旧发布版
均报告 DWM `1→0→0`，增量修正版均报告 `1→0→1`。修正前后都预留
22 个窗口坐标单位，移除后保留原外矩形、原客户区起点和可见子窗。

通过 Microsoft.Paint 自身的安装清单定位已安装的 WinUI 桌面二进制，
显式路径启动发布版后确认其新窗口加载 ntw2ks64 与 Microsoft.UI.Xaml，
登记 Win2000 外框且存在一个组合桥。Paint 关闭按钮区域未得到有效绘制
取样。144 DPI 最大化和还原时标题中部均返回 HTCAPTION，客户区顶部偏移
为 45 个探针坐标单位，首个可见组合桥从同一行开始。这与早先通过命令别名未找到
自有窗口的结果分开记录。

### 发布修正版追加对照

复核两个目录的 16 项 SHA-256 与实包记录一致。用发布版启动自有 Win32
演示与 WinUI 记事本，144 DPI 下三个按钮均为 24×21，最小化、最大化和
关闭各自的窗口 DC 像素摘要完全一致。该对照新增了最小化与最大化两项。

用 Scan 作为独立 UWP 对照，仍在附着前返回 1460，根 HWND 即 CoreWindow，
无样式表面。当前探针位于同一活动控制台会话的 WinSta0/Default，会话状态
码 0，前台 HWND 为空。该观察排除了探针运行于另一个控制台会话，尚不能
确定宿主缺失的系统原因。恢复条件是自有系统 UWP 实例出现可观测的
ApplicationFrameWindow；届时以两处已发布的相同文件复验。

随后直接通过 Windows 应用激活接口启动自有 Scan，返回 S_OK；九秒内
只观察到它自己的 Windows.UI.Core.CoreWindow，仍没有 ApplicationFrameWindow。
这项原生对照复现了系统计算器的结果，并确认缺少宿主发生在样式应用之前。
两处发布摘要仍全部匹配。停止重复启动，保留待复验项目。

用户重新连接 RDP 后，探针确认位于同一活动会话。修正版的计算器两种风格
及 Scan 的 Win2000 均创建宿主和样式表面，通过最大化、最小化、还原及
移除后的几何比较。Win16 计算器完整探针返回 0；两个 Win2000 完整探针
停在屏幕取色。Scan 的命中点属于样式表面，但 GetPixel 两点均返回
CLR_INVALID；计算器关闭按钮的实际屏幕 BitBlt 也失败。测试探针已清理。

临时操作探针在发布文件上独立验证菜单和缩放。两款应用均打开、取消系统
菜单，高度按请求增加 24，样式表面跟随并在移除后恢复几何，各返回 0。
双轴对照请求宽度增加 32，计算器实际增加 4，Scan 不变，两者的高度均
增加 24，样式表面与实际窗口等尺寸。保留该差异，未把双轴请求记为通过。
DXGI 可以创建设备，但 DuplicateOutput 返回 0x80070005，未取得合成像素。
仅使用原生消息和有界测试，未改生产文件。临时探针已清理。

窗口级 Windows Graphics Capture 取得两个自有 UWP 外框的合成像素。
计算器标题渐变的两个位置为 RGB 9D9D9D、AAAAAA。计算器与 Scan 分别
采集普通态和最大化态，144 DPI 的三个 24×21 按钮均与 Win32 的对应
字形摘要一致。中间按钮在普通态为最大化，最大化态为还原。GDI 和桌面
复制的失败记录保留。单窗口探针已清理，发布文件不变。

真实 WinUI 停用验证改用仓库原有的单 PID 测试过滤。仅使用系统激活的新
记事本直接子进程，核对安装路径、创建时间、实际顶层窗口；没有启用 UWP
分派或桌面托盘。发布版应用并移除后，外矩形三次都是 (0,0,641,408)，
客户区从 (9,0,632,399) 变为 (9,33,632,399) 再回到原值，DWM 为
`1→0→1`，附着标记为 `0→1→0`，控制器停止返回 0。Windows 未把
该测试窗口置于前台，前、中、后的窗口捕获均未返回帧，窗口 DC 对照的
原生与恢复区域均为均匀像素。真实停用的状态和几何已验证，画面待补证。
本次临时探针和自有应用实例均已清理。

交付前重新核对干净构建快照中的 1232 项构建输入，当前工作区无摘要差异、
缺失或额外输入，两处发布的 16 个文件也全部匹配。随后 Windows 会话
显示 RDP 已断开，打开输入桌面返回错误 5，未再启动应用。拍摄真实停用
画面的恢复条件是同一 RDP 会话可见并能为自有测试窗口提供画面。

复查时该 RDP 会话仍处于断开状态。只读查询远端 main 返回
`ba5bcdd5812a5036978478b6dedd476e8b43811c`，与本地提交基线一致。
待补的是恢复画面及其后的提交和远端实包复核。

RDP 重连后，窗口级 Graphics Capture 在同一自有记事本的应用前、应用后
和停用后均取得画面。两次应用前的对照像素一致。停用后 DWM 恢复为启用，
窗口及客户区矩形与应用前一致，但合成画面中原生深色标题栏右侧叠着浅色
的旧按钮。独立发送主题更新、恢复按窗口样式决定的 DWM 策略、刷新非客户
区激活及重新计算窗口样式均未清除。隐藏再重新显示自有窗口后，重复按钮
消失，原生深色按钮重新显示。候选的直接停用仍有画面回归。

在该已发布候选上独立验证：停用后用 `SWP_NOCOPYBITS` 重新计算外框，
随后使客户区及子窗口失效。未隐藏窗口，340×58 的标题区与应用前逐
像素相同。该对照由探针直接触发，不能算生产停用路径通过。

增量 DLL 在真正的停用入口依序恢复外框、丢弃旧像素并重绘客户区。
合成画面中的重复按钮消失。按 DWM 可见边界将标题图对齐后，覆盖三枚
按钮和相邻区域的 316×58 像素完全一致。窗口和客户区矩形保持一致，
但 DWM 可见矩形左、右、下各多 7 屏幕像素。恢复为默认 DWM 策略的对照
也保留此边界差异，故保留当前策略。上述结果来自独立增量包，尚无新的
正式发布。

自有记事本独立切换 DWM 非客户区策略可以恢复原可见边界；问题只在样式停用
事务后复现。提前执行几何恢复未改变结果。按顺序恢复原客户区并清理旧像素后，
向该窗口排队发送合成重建通知，让应用处理原生边距。实际生产移除路径实测
DWM 为 `1→0→1`，窗口、客户区和 DWM 可见边界均恢复，合成的标题区
300×50 像素与应用前完全一致。探针在验证阶段未额外补发通知或刷新边框。

## 合成恢复实包

双位宽干净构建通过来源、资源、ABI、依赖和包身份检查。八件先发布到
assets 和 O:/winnt，两处 16 项均与同一快照相符。旧 ntw16s64.dll 和
ntwshk64.dll 移入同盘发布备份，未结束任何现有进程。

标准命令启动自有 WinUI 记事本，核对真实顶层 HWND、XAML 及 Win2000
附着。独立 Paint 交叉验证同样通过。记事本用正式 DLL 完成单窗口启停；
合成的 300×50 标题区与停用前逐像素一致，三个矩形恢复。真实计算器和
Scan 的 Win2000 按钮在普通及最大化状态匹配 Win32 参考，默认 Win16
计算器外框与最大化、还原通过。

普通桌面验证的适用原生用例为 31 通过、2 失败。失败均为 Win32 生命周期

包都恢复 DWM 启用，而 T27 在同条件下未恢复。实际发布启动器的双宽

使用私有桌面的 UWP 夹具，剔除其结果，真实应用回归全部使用普通桌面。

## S2 收口复核

重放 Win32 失败时，DPI 不感知线程的 RDP 工作区宽度为 320 个坐标单位。
旧夹具请求 420，实际外框被限制为 340；停用时 USER32 又把为保留客户区
请求的 350 限回 340。缩小同一自有窗口后，USER32 接受恢复尺寸 260，
同一个发布 DLL 即通过完整客户区矩形断言。夹具现按工作区居中并预留
边框空间，原有断言不变。只修改一个测试源文件（+8/−1）和其来源回执，
产品源码、生命周期所有者和八个已发布文件的摘要保持一致。

- WinUI 记事本和 Paint 真实顶层窗口使用 Win2000 外框。记事本的标签、
  菜单、标题命中和缩放见首版实包证据。合成恢复包对照记事本停用前后的
  三个矩形、DWM 及 300×50 合成像素。共享 Explorer/Shell 未作为目标，
  默认 Explorer 启动保持既有支持边界。
- UWP 计算器与 Scan 系统菜单、纵向缩放、往返和卸除见 S1 同批复验。
  正式包重新验证 Win2000 的普通及最大化按钮，以及计算器默认 Win16。
- Win32 x86、x64 修正夹具增量核对通过，摘要相同的发布 DLL 又各通过
  直接移除和协调器移除，无需私有桌面。合并此前合法聚焦结果，适用原生
  用例 33/33；完整传统矩阵和物理输入仍在范围之外。
- 正式八件来自 P1 同一快照，两处发布及远端逐件核对。P2 留存复核记录，
  本次仅更新测试和证据，沿用该发布，无需重建或重新部署产品文件。
