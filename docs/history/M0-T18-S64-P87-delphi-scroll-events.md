# M0 T18 S64 P87: Delphi TScrollBar real event and page evidence

The released P85 package and its immediately preceding package were compared on separately owned DelphiVCL4Python 1.0.7 x86/x64 samples at 144 DPI, horizontal and vertical. A synthetic mouse click at the page-up track location produced `SB_PAGEUP` then `SB_ENDSCROLL`, changed position 26 to 25 and released capture in all eight runs. The probe pre-posted mouse-up so that the native control could complete its synchronous tracking; this is not physical input or a thumb-drag test. The owned targets ended after WM_CLOSE; the abbreviated driver did not independently check exit code or job active count.

To verify VCL callbacks rather than infer them from WM_HSCROLL alone, a Python OnScroll handler was registered after the initial native observer had returned and before Application.Run. A separate owned driver sent a key to the scrollbar after the message loop became available. On both packages, widths and orientations, the handler observed `scLineDown` with var position 26 and Position property 25, then `scEndScroll` with var position 26 and property 26. A second test set the var position to 40 in `scLineDown`: all configurations reported 40 in `scEndScroll`, the property became 40 and the driver read native position 40. Comparisons were byte-for-byte on the logged event values; the observer's IAT hooks had already been restored. The real framework and a Python callback were used; this is not a general guarantee for other VCL versions, event handlers, physical input or lifecycle.

An initial attempt installed OnScroll before the initial observer's synchronous message test while the Delphi Application.Run loop had not started. That owned sample timed out; a further x64 bare run showed an access-violation dialog in python313.dll and the callback's entry marker was absent. Registration without invoking the callback succeeded in bare and assets x86 samples. Deferring registration and input until the message loop made the reported runs succeed. The precise interpreter/bridge failure cause is not established, and the early failed runs are not counted as product regressions or passes. No product code, tests or binaries were changed in P87. All eight deployed file hashes still matched the P85 tested package. T18/S64 remain open.
