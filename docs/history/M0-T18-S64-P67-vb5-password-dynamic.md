# M0 T18 S64 P67: VB5 dynamic password-mask observation

A scratch-only adaptation of the project-authored VB observer ran the previously admitted x86 VB5 ResXpStylesTester sample bare and through the published package on a 96-DPI private desktop. The observer found a visible single-line `ThunderRT5TextBox` registered by the actual loaded `MSVBVM50.DLL`. It temporarily sent `EM_SETPASSWORDCHAR('*')` to this originally ordinary text box, supplied two distinct equal-length synthetic strings and one shorter string, captured the window, and restored the original mask, text and font handle. In each mode the equal-length image files matched byte-for-byte, the shorter image differed, and restoration succeeded. The bare and styled 485x21 captures differed in 1,669 RGB pixels; this comparison alone does not attribute each pixel to font, border or attachment.

The target and launcher were owned jobs and were forcibly cleaned up after the observations, so this is not a normal-exit or resource-lifetime test. A first styled attempt failed because both runs targeted the same CREATE_NEW screenshot path; it is not a product result. A retry with its own directory passed. The observer's inherited `VB6_PASSWORD_OWN_JOB_CLEANUP` label is incorrect for this VB5 run and does not change the identity described above. Actual VB password properties at creation, reveal-toggle events, physical input, IME, accessibility, other DPI and x64 VB remain unverified. This is a dynamic Windows-message experiment, not proof of the VB5 PasswordChar property or general application compatibility. The styled module was loaded from the published absolute asset path; attachment and exact glyph appearance were not independently established.
