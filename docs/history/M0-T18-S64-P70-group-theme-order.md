# M0 T18 S64 P70: Delphi group theme order and temporary candidate

A project-owned diagnostic DLL with a temporary `DrawThemeTextEx` tracer observed the actual x86 DelphiVCL4Python 1.0.7 group paint at 144 DPI. The runtime called `DrawThemeBackground` with BUTTON part 4, state 1 and group rectangle `(0,12)-(250,120)`, followed by `DrawThemeTextEx` part 4, state 1 with caption rectangle `(8,0)-(87,25)`; the text call returned `S_OK`. An empty-caption instance called the background path with `(0,0)-(250,120)` and did not call the text path. The diagnostic ran only inside newly owned application processes, which were closed. The test launcher folder mixed a diagnostic x86 DLL with an unchanged x64 DLL solely for this x86 observation; it is not a deliverable or a same-batch package.

A second scratch-only DLL candidate used the observed background for empty captions and the observed text rectangle for nonempty captions. It additionally checked same-thread, same-owner group/parent, real class, enabled state, direct caller module and DC mapping. The existing renderer and original resources were not modified. In separate actual x86 and x64 samples at 144 DPI, default captions each had 633 changed RGB pixels against their respective old published image, while the caption and a central customer-content rectangle had no changed pixels. The x86 empty-caption candidate changed 736 pixels overall and zero within an independent central client rectangle. The x64 empty-caption process exited 0, but no independent old-image pixel comparison was made for that case. A long x64 caption produced an image byte-equivalent in RGB pixels to the prior P69 temporary overlay; this does not independently prove correct mnemonic input. The probe ran on an isolated desktop and does not establish physical input.

The two-architecture temporary tracer build passed one ABI test per architecture; it compiled the complete test tree, taking 56.7 seconds for x86 and 163.8 seconds for x64, which was unnecessarily broad for this diagnosis. A first background builder terminated without a result and a subsequent attempt in the same build directory failed with a Ninja recompaction permission error. The independent successful build used a new directory. Later candidate recompiles used the single `ntw16s` target. These were research builds, not the required final four-file package or a publication.

The candidate is not ready for product admission: the hook must be restricted to a verified group paint scope so framework or application drawing outside that scope is not affected; identity, clipping, reentrancy, destruction/reparenting, title changes, disabled state, DPI and negative fixtures need tests. No product source, tracked test, graphics resource or published binary changed. T18/S64 stay open.
