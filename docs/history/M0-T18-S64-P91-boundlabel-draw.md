# M0 T18 S64 P91: Bound label ownership investigation

On a self-owned DelphiVCL4Python 1.0.7 form at actual 144 DPI in both x86 and x64, the `TLabeledEdit.EditLabel` and an additional ordinary `TLabel` both drew in the parent TForm DC through the runtime's `DrawTextExW` import. For `User name`, the runtime measured with DT_CALCRECT (0x440) then drew (0x40), both using origin (-10,-12), clip and rectangle 0,0,84,25, Segoe UI logical height -18, measured 84x25. The extra label, with explicitly assigned Arial, drew in the same parent DC with origin (-10,-110), rectangle 0,0,112,21 and measured 112x21. Probe output identifies these self-authored captions only as experiment markers; they are not product identification criteria.

The observer temporarily selected stock SYSTEM_FONT to measure and then restored the selected original font. `User name` measured 86x20, wider than its current 84-pixel rectangle; `Ordinary label` measured 112x20. This is not the project's scaled System font and does not rule out a suitable layout or typeface strategy. It demonstrates that blindly replacing a font in the current rectangle can clip or change the layout. The form's accessible client reported one child; corrected `AccessibleChildren` enumeration returned one ROLE_SYSTEM_WINDOW object whose HWND was the labeled edit, and no independent object for either windowless label in this specific sample. The initial attempt used a child ID with get_accName/get_accRole and returned E_INVALIDARG; it is not counted. Other accessibility providers and VCL versions were not checked.

Runtime and theme import observers were restored, font selection restored, the target and launcher exited zero and owned job accounting reached zero on both widths. Parent DC, font and drawing operation alone do not prove windowless label ownership or exclude application Canvas drawing; no content-neutral safe identity or layout update contract has yet been established. Thus no production code or binary changed. Prior generic findings remain in [S29](M0-T18-S29-label.md); actual bound-label text is still an ordinary-control gap, not considered completed. The question is open for further evidence, not declared impossible. T18/S64 remain open.
