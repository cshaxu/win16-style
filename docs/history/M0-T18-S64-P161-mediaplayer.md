# M0 T18 S64 P161: Delphi media player button backgrounds

A private, self-created DelphiVCL4Python 1.0.7 sample constructs the standard visible `TMediaPlayer` without a file or open device. On both x86 and x64 it is a single VCL-module-owned window, with the same module owning its form. Its button face uses same-window, same-module BUTTON-theme drawing in full-height absolute rectangles. Normal state 1 and pressed state 3 were observed; a focused first button used state 5. The change admits the exact class and same-owner parent/paint/caller contract and replaces only states 1 and 3 using the existing button renderer. State 4, state 5 and all other unverified states retain native drawing; media, commands, glyphs and original graphic resources remain owned by the application/framework. No public ABI changes.

The actual same-snapshot candidate loaded `ntw16s32.dll` SHA-256 `a6e4f87fa0cad449bab306324f1f3e06bd89d9f2ad99b9b11cd9167c8fb56779` and `ntw16s64.dll` SHA-256 `cb76c270a87671087d23d40b379cf2724ae7a8bcd07de4daed7753674ea89f43` into their respective real VCL samples. On each, the same-size normal image changed 10,254 RGB pixels outside the first focused button, and all 188 checked dark glyph pixels matched the baseline. In the pressed button area all 26 checked dark glyph pixels matched. Down and cancel messages returned, capture was absent afterwards, and both targets exited zero. Both baseline and candidate retained a changed screenshot after cancel; this does not establish correct cancellation. No media file was opened or played; these pixel thresholds are bounded observations, not proof for arbitrary graphics.

Dual-width models cover same-owner external DLL classes, normal and pressed backgrounds, exact graphic preservation, foreign caller, clipping and separate unverified-state-only windows. In the external-module fixture, system-themed edges changed by small amounts between consecutive screenshots even with no style attachment. The test therefore does not claim exact whole-image equality for those native states: instead it asserts that standalone state-4 and state-5 draws never become style-verified. A scratch fault that also styled state 4 was rejected by that assertion. P160 fails the new positive media assertion on both widths. Other data actions, physical input, focused/disabled style, media opening/playback, cancellation, other DPI and VCL versions remain unverified.

The pure C GCC/Ninja/ccache clean x86/x64 build, source/resource and ABI checks passed. The same-snapshot four-file actual package passed 28 focused cases in 15.51 seconds without skips. Both release destinations match tested hashes and each passes both installed-width models. M0/T18/S64 remain open.
