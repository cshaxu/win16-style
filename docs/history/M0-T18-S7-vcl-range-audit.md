# M0 T18 S7 — VCL range control audit

The existing `TProgressBar`, `TTrackBar`, and `TUpDown` bindings already use exact wrapper names, class ownership, and initialized public common-control protocols. Existing self-contained tests check visible pixel changes, state and input semantics, impostor rejection, and retirement. Progress controls under comctl v5 intentionally fall back to native appearance when the required state contract is unavailable. No new product-source behavior was introduced.

The clean x86/x64 candidate passed all 87 package cases without skips in 347.55 seconds, then its four files were published to the project assets root and `O:/winnt/system32`. The GUI probes used self-owned private desktops; physical input and genuine Delphi integration remain unverified. UpDown resource totals are observational, not a zero-delta guarantee.

The first package run exposed a demo observer false positive: GDI objects decreased from 91 to 88. The second-reopen assertion now rejects growth above the settled baseline while accepting a decrease; it does not claim that the cause of the decrease is known.
