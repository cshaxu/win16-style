# M0 T15 S1 VB6 intrinsic controls

本S按用户批准实施，P1已本地验证并发布；实际远端复核完成前不关闭。M0保持开放，
T15整体实现范围为本机MadShow所体现的VB6按钮、文本框、分组和无窗口客户区文字，
交付后等待用户外观验收；不把一个程序的成功扩张为所有VB6或第三方OCX。
原始调查由[Td S11](M0-Td-S11-madshow-controls.md)保留。

## 实际断点和实现

- 三处独立标准类名单跳过VB6控件；现在统一使用精确ThunderRT6类名和MSVBVM60
  注册模块身份。匹配CommandButton、TextBox和Frame；同名而由应用注册的类拒绝。
- VB文本框带client-edge；保留原生编辑过程、样式、客户区尺寸和选区/撤销，覆盖其
  已有边框。打印借用DC在原生调用后恢复。按钮沿用现有renderer和原生命令/键盘状态。
- Frame拥有无窗口标签，先执行VB原始绘图，再叠加分组框，不能吞掉WM_PAINT。
  原生OBJID_NATIVEOM查询E_FAIL，未尝试访问私有VB对象布局。
- VB字体由运行库持有，WM_SETFONT不能证明接入。限定已附着VB容器/编辑消息作用域，
  仅接入VB或USER/LPK/USP10/GDI32FULL原生文字管线；其他附着窗口形成屏障，离开
  作用域直接走原始trampoline。字体只在实际文字调用期间选入DC，返回前恢复。
- 源字体glyph-index不能直接套给FNT。缓存可逆CP1252映射并保留dx/clip；未知、RTL
  或超界整段保留原始调用。每HWND最多32源字体租约，最后活动调用后释放字体和映射。
- 原型发现16到14像素逐行采样会删去零字帽沿。仅VB变体采用保黑色笔画缩小；
  标题、菜单和标准控件仍用既有策略。原五图形头/声明字节、18内嵌表及ABI3/31导出保持。
