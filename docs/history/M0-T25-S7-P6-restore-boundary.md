# M0 T25 S7 P6：运行中恢复边界审计

继续调查 [P5](M0-T25-S7-P5-apps-and-restore.md)的 Win2000 样式恢复缺口：`win2k_frame_attach` 对顶层窗口禁用 DWM 非客户区绘制并安装子类，当前没有配对的窗口移除入口；`ntw2ks-dll/controls.c` 还对部分子控件调用 `SetWindowTheme`，并通过启动期挂钩接入后续新窗口和对话框。只移除某个窗口子类既不会自动恢复这些控件，也不会阻止未来窗口再次被附着。

现有 `process_hook_startup_hooks.h` 明确启动期事务提交后 trampoline 保留至进程结束，`abort` 仅回滚尚未提交事务；传播接口的 `active` 回调可停用传播，但不等于物理卸载。Win16 的窗口恢复保留可观察的 DWM 开关状态，其源码说明 Windows 不提供区分原本 `USEWINDOWSTYLE` 与 `ENABLED` 策略的查询；不能声称精确还原原策略。Win2000 当前 `--global` 明确不支持，不能把 Win16 的全局恢复当作 Win2000 能力。

因此运行中恢复需要明确窗口、控件、后续附着和传播各自生命周期及实际调用方，而不是增加一个无人调用的局部移除包装。相关边界已补入用户指定的下一 T 共享接入候选；当前 T25 的该缺口仍在 TODO，未计通过。此为只读审计与规划，无产品代码或二进制变化；S7、T25 保持开放。
