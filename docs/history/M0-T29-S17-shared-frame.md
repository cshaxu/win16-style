# M0 T29 S17 Win32 外框共享模型

## 标题绘制

`application/window/caption_paint` 负责标题底色、渐变、分隔线和文字。
它只接收 DC、几何、颜色、字体及呈现属性。现有 Win16 和 Win2000 外框
调用该实现，各自的现代宿主也随原有绘制入口使用同一实现。

生成主题沿用标准背景色、渐变与文字色。可选的 `CLASSIC_STYLE` 1.5
记录 10 保存两个单字节属性。文字可居中裁剪或左对齐省略，分隔线可省略、
放在标题带末行或紧接其后。旧包没有该记录时沿用原兼容默认值。
像素测试把两种声明交叉应用于两个现有适配器，观察标题位置和分隔线行号。

双位宽 MinGW/Ninja 增量构建通过。两宽读取了新生成主题，通过记录编解码
负例及两种呈现交叉测试。S16 的两份发布主题也通过旧格式回退和像素测试。
两宽自有窗口的普通及合成外框直接接入和移除各通过一次。两宽自建 UWP
外框通过切换、缺失描述保留、外框移除和客户区恢复。测试临时包已清理。

## 边框绘制

`application/window/frame_border` 由两个现有外框调用。可选的 `CLASSIC_STYLE`
1.6 记录 11 保存填充范围、对话框填充色角色、两层笔画的锚点和前后侧色角色，
以及对话框内层覆盖色。旧包保留其兼容配方。共享绘制只接收目标 DC、尺寸、
缩放单位和颜色。客户区排除由宿主处理，包括 Win2000 适配器装入裁剪填充配方的情况。

双宽读取新旧主题通过。Win16 普通窗和对话框在两种笔画宽度下与原步骤逐像素一致。
Win2000 保持原边沿像素，改用混搭笔画和对话框着色后，受保护的客户区像素保持原样。
两宽自有普通及合成外框接入和恢复、两宽自建 UWP 外框复验通过。
实际候选启动器的 Win2000 样式变更与运行中新增标题栏探针也通过，两宽共四项。
临时探针目录已清理。

记录 11 增加可选的尺寸分隔标记色角色。共享边框绘制在宿主提供调整尺寸的角区时
使用该角色，主题可省略标记。两宽的新旧主题测试和分隔像素检查通过。

## 标题按钮

`application/window/caption_paint` 提供索引图像绘制和系统字形着色。Win16 使用原按钮
图像和主题色，Win2000 使用系统字形和传入的边框色。两宽 Win2000 标题像素测试覆盖
96、144、192 DPI。原图形资源及来源核对通过。

`application/window/caption_slots` 定义统一的角色顺序、矩形命中、非客户区命中值
和系统命令映射。Win16 直接用角色矩形绘制、命中和局部重绘。Win2000 在
`TITLEBARINFOEX` 的适配边界只传入可见项，其应用图标和窗口原有菜单继续走原生路径。
切到右边的 `SYSTEM` 槽仍命中 `HTSYSMENU` 并映射到 `SC_KEYMENU`，原位置回到 `HTCAPTION`。

双宽增量构建及新旧主题、原生标题像素、控件链接、现代外框布局通过。用开发候选启动
双宽自有窗口，Win16 键盘系统菜单保留定制项，Win2000 菜单成功取消且图标命中正确，
两宽共六项。两宽自建 UWP 和普通／合成外框接入与撤销复验通过。临时探针目录已清理。

CLASSIC_STYLE 1.7 扩展记录 10，允许主题选择索引图或系统字形，并可给索引图添加
轮廓。保留两字节旧记录。两个 Win32 适配器从同一共享入口绘制，索引 PNG 由共享
资源加载器读取。系统菜单按钮使用索引图，系统命令继续由原生窗口处理。缺少可用
索引图的普通角色沿用已有兼容绘制，Win2000 的系统字形继续支持禁用状态。

双宽增量编译通过，新旧包及记录负例通过。96／144 DPI 下两套适配器使用同一主题
索引图和系统字形分别逐像素相等，切换图形来源改变按钮像素。原图普通、按下、MDI
和最大化还原图的回退对照通过。Win2000 系统字形 96／144／192 DPI 样本保持。
开发候选通过双宽 12 项实窗动作，覆盖系统菜单、定制项、应用图标命中、按钮取消、
最大化／还原／最小化／关闭及样式变更后的客户区恢复。自建 UWP 与普通／合成外框
的原有两套主题复验通过。未用真实 UWP 或 WinUI 验证交叉图形资源。
图形来源校验与源码依赖检查通过，临时探针包已清理。

## 外框几何

CLASSIC_STYLE 1.8 的记录 11 追加边框度量、尺寸缩放方式、标题最低高度和分隔保留线。
Win16 通过共享度量计算完整客户区，Win2000 通过相同度量调整原生窗口和客户区矩形。
监视器 DPI 查询集中处理。Win16 继续使用逻辑长度，Win2000 继续使用固定屏幕像素；
两种方式均由主题声明。原生和合成宿主仍拥有各自的客户区定位和生命周期。

现有启动器和双位宽 DLL 保持同一份字节，仅将主题记录 11 的可调整大小窗宽度从 4 改为 2。
在 144 DPI 自有窗口上，Win16 四边相对客户区各缩小 3 像素，Win2000 各缩小 2 像素，
两个位宽均实测相同。四组对照的客户区命中均通过。Win2000 两位宽分别在 DPI 虚拟化和
原生 144 DPI 下复验各八次最大化与还原，旧发布包和本候选的几何、绘制和命中检查均通过。
已清理探针临时包。

首次正式构建的 x86 编译和 ABI 测试通过。兼容 DLL 的导入检查拒绝共享 DPI 查询
新增的 Windows 系统库 SHCORE，最初误判为 UCRT。两种系统 CRT 均受支持，正式包
之前已经要求 SHCORE，仅补充兼容 DLL 的精确允许项。
本批正式构建使用本机双宽 MinGW MSVCRT 编译器及 Ninja、ccache。MSVCRT x86 的 GCC
直接启动 ld，转发链接期
`-fno-lto` 会导致链接失败。用该次的同一组对象复现，取消重复的链接参数后，
主题生成器成功链接并正常执行参数检查。所有对象仍在编译阶段禁用 LTO。

双宽纯 C17 干净构建、ABI、PE 和独立主题读回通过。两处发布的七件文件均与同一候选包
逐件核对，九个退役路径保持缺失。发布后聚焦测试及补充样本见[发布清单](../etc/release.json)。

发布后的 24 项实窗动作通过，覆盖菜单、图标、窗口命令、按钮取消、激活、重算和撤销。
两个位宽各测试普通与 DPI 感知下的八次最大化／还原和二十四次调整大小。两个 Win16 MDI
样本的系统菜单命中、最大化及还原通过。仅改主题边宽的四组对照与原客户区命中再次通过。
两宽扩展、主题绘制、自建 UWP 外框和普通／合成窗口接入撤销均通过。使用原生夹具消息，
没有物理输入、私有桌面、真实 UWP／WinUI 或全量矩阵验收。

旧综合外框测试 `ntw2ks-frame-x86` 与 `ntw2ks-frame-x64` 在已发布候选中均返回 3。
两份 S16 备份按原摘要恢复到临时包后，使用同一夹具复现，两宽的全部诊断与退出码分别
逐字节一致。保留两项既有失败，与已通过的定向最大化、还原和其它实窗检查分别记录。
