# M0 T18 S64 P167: bounded Delphi CoolBar grips

The current delivery adds a bounded `TCoolBar` grip path. Only a same-owner, same-thread control and parent are eligible. During the control's WM_PAINT, the native Rebar procedure must be witnessed; default custom draw then permits the existing classic edge painter within validated band and client geometry. Text, image, bitmap, unsupported flags, application custom drawing and unknown identity fall back to native behavior. Child content and layout, application notifications, resource bytes and the public ABI remain owned by their existing paths. Queries use the witnessed native procedure within the current nested paint scope; ordinary application queries remain routed normally. The native procedure itself is not proven incapable of reentrancy.

Actual GoVCL 1.2.10 real TCoolBar samples with two Delphi buttons, x86/x64 and COMCTL32 5.82/6.x, passed at 96 DPI against the delivered package. Stable-frame changes were 212/380 pixels inside the two grips, zero outside, with both child positions unchanged; detach and process exit succeeded. The real-control harness with an application custom-draw model preserved pre/item/post counts 1/2/0. Earlier 6.x first-frame drift was 21043 pixels; the final check compares consecutive stable frames. The GoVCL test library remains scratch-only and is not a product dependency. This is not evidence for all VCL versions, input modes or DPI values.

The self-contained dual-width lifecycle test covers nested paint, exception unwinding, removal, reparenting, fake owner/procedure, and text/image/bitmap fallback and readback; P166 fails its positive attachment assertion on both widths. A mutated x86 candidate without the text length check fails the narrow-item test. On the tested system a two-character buffer for a 13-character band returned empty text but updated cch to 13; Microsoft documents the input capacity but does not guarantee that returned-length behavior. Other implementations therefore remain an explicit compatibility risk; readback and attachment checks do not prove pixel preservation for every application image or caption.

Menu cancellation test cleanup previously hung destroying its active anchor in both the old and new package. Its isolated worker now leaves the anchor to process exit after all 15 original cases; worker and harness budgets were reduced. Both widths and two DPIs pass, but explicit anchor destruction and the underlying platform wait remain unproven. First attempted cleanup fixes failed and are recorded in the investigation. Focused testing does not replace the full integration matrix or physical input.
