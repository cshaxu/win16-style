# M0 T29 S9 现代外框

范围为 [S2 台账](M0-T29-S2-theme-and-abi.md)第 43、46 项。
WinUI 合成路径继续使用 Win32 窗口呈现器。直接 UWP 外框现在也使用同一
`classic_theme` 模型中的标题配色、按钮组和度量、字体、外框及系统菜单属性。
Win16 同时使用主题中的原有标题和菜单图形。两种直接 UWP 外框保留宿主定义
的客户区孔洞。该孔洞仅参与裁剪和命中，标题布局继续由风格度量计算。

开发运行包阶段，Win16 从本模块读取主题资源，Win2K 从同目录同位宽伴随
文件的数据资源读取。读取使用资源映射，保持伴随 DLL 的原有执行入口和
接入范围。没有可读主题时沿用原回退。外部主题文件和中性双位宽装配由 S10–S11 接续。

## 开发验证

| 证据 | x86 与 x64 结果 |
| --- | --- |
| Win16 `core-uwp-frame_layout` | 96–288 DPI 的七档度量均通过。使用 23 像素主题按钮时，现代外框与 Win32 的标题和三个按钮矩形相同，命中与新矩形一致，客户区保持。 |
| `core-style-classic-theme` | 从两份独立主题读回模型，经共享配色与呈现函数进行原图、标题背景、按钮和度量对照，两宽通过。 |
| `core-uwp-frame-hidden` / `core-uwp-surface-present` | 隐藏宿主重复附着与销毁、表面裁剪、透明区域、失败回收及刷新重入均通过。 |
| Win16 `core-uwp-frame` / Win2K `core-win2k-uwp-frame` | 自有原生宿主两宽通过。覆盖客户区、最小化、最大化、还原、撤销及重复附着。Win2K 加宽关闭按钮后，从主题新增的边缘区域点击得到关闭命令。现有产品入口的两种风格互切和定向移除也通过。 |

合计 12/12 组。测试使用自有窗口和合成消息。初次运行时，已有窗口参与
Z 序重排导致 `SetWindowPos` 返回错误 5。独立探针证实同一窗口创建、
区域设置和分层提交可用，插在测试自己拥有的参考窗之后重排成功。
夹具在测试前及原生状态切换后仅调整自有窗口的 Z 序，生产表面提交及
权限条件保持原路径。Win16 以现有直接 worker 启动，没有创建或切换桌面。

## P1 干净构建和发布后验证

`Build-Package.ps1 -Task 29 -RunName s9-modern-frames-build` 使用纯 C17、
MinGW GCC、Ninja 和 ccache 从同一快照干净构建。x86 用时 270.57 秒，
x64 用时 343.14 秒。来源、五个原始资源、双宽 ABI/PE、归档边界和依赖
门禁通过。四个主题文件重新生成并独立读回，字节与 S8 一致。
17 个源码与测试输入变更，新增 185 行、删除 66 行。窗口和表面的生命周期
继续由现有适配器持有，直接 UWP 中的默认皮肤数据只用作原有缺省回退。

八件开发包先发布到 `assets` 和 `O:/winnt`，双宽实包聚焦回归 29/29。
两处文件按摘要核对后，各通过 12 组框架、布局、表面及独立主题对照，共 24/24。
独立通用 frame 夹具的旧增量版另外出现两次 Z 序错误 5，未计入
这 24 组。变化及证据见[发布记录](../etc/release.json)。

真实应用验证使用 144 DPI 普通桌面和探针创建的实例。

| 样本 | 实际结果 |
| --- | --- |
| Calculator Win16 | 从 `O:/winnt/run16s.exe` 启动，外框表面、最大化、最小化、还原和撤销后的窗口几何通过。 |
| Calculator 与 Scan Win2K | 实际外框的两个可见渐变采样点都匹配 Win2K 配色。最大化、最小化、还原、撤销及撤销后几何均通过。 |
| WinUI 记事本，Win16 与 Win2K | 正式命令分别打开唯一空白文件。均观察到 WinUI 内容桥仍在，DWM 非客户区为禁用，Win16 标题两个采样点均为 `#A4C8F0`，Win2K 标题两个采样点呈不同渐变颜色且存在当前风格标记。两个测试窗口均正常关闭。 |

首次真实 UWP 验证在沙箱内被系统拒绝激活。恢复正常应用激活条件后，
拆分目录的测试出现 Win16 启动超时一次，Win2K 撤销几何断言失败两次。
S8 原包的同目录对照三组通过。S9 使用实际发布目录作为启动器和探针的
同一个 DLL 来源后同样通过三组。硬件输入、真实 WinUI 逐像素撤销及更广
应用覆盖未重复验证。没有创建或切换桌面，没有更改系统安全设置。

S8 同目录对照的暂存 DLL `build/t29-s9-real-uwp-d25ytlvg/ntw16s64.dll`
在测试退出后仍拒绝删除。该目录的其余同批文件已按摘要核验并删除。
此项暂存文件待系统释放后即可清理。
