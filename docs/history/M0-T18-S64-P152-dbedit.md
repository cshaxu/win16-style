# M0 T18 S64 P152: Delphi TDBEdit ANSI forwarding

The real Delphi 7 sample described in [the investigation](M0-T18-S64-data-aware-sample.md) forwards TDBEdit WM_PAINT through the registered ANSI EDIT procedure from its own class module. The existing W-only paint witness missed that route. For the exact single-line TDBEdit class, the ANSI CallWindowProc path now records a witness only inside that same window's active paint scope, for the registered ANSI EDIT procedure and the actual class owner caller. It then uses the existing verified EDIT protocol and renderer. The application still owns editing and data binding; unrelated controls, wrong procedures and foreign callers do not gain this witness. No product ABI or original graphics change.

A native module fixture exercises both widths: exact ANSI forwarding, normal input/selection/readonly, frame removal, fake paint and an ANSI forwarding call from a different module. Both P148 DLLs fail the new positive case. An x86 scratch fault with the owner check removed fails the foreign-caller assertion. The production candidate's real x86 vendor demo test required a test-only import in a private copy of the demo to set French Canadian locale on its startup thread; it did not modify the product DLL or system settings. The modified EXE SHA-256 was `c87d19457a711c82692c863c4b32342010a476221c278b2cf4280ae412f09c17`; all original raw code, data, imports, relocation and resource section bytes were compared unchanged, but the PE headers and added import are modified. The private test helper and unsigned, source-attributed MIDAS library are not product files. The actual package DLL path was observed as the candidate x86 DLL, SHA-256 `aa93e5c4d3375d4010dbaf473ab6763bb964c9d5c63096c1001a9cf1ae2e8cde`.

In this real sample the release and candidate showed identical `Roberto -> RobertoX -> Roberto` edit/restoration and `Bruce -> Roberto` record navigation, followed by normal zero exit. The equal-sized 91-by-21 PrintWindow captures differed at 483 RGB pixels: 432 in the outer two-pixel band, 51 inside. That is bounded visual evidence, not proof for all text or DPI. The app uses a private in-memory dataset; persistent writeback was not tested. The first LIEF import-rebuild variants failed to start and are not counted; the separately constructed test import retained all original section bytes and completed.

The clean C17 MinGW GCC/Ninja/ccache dual-width build, ABI, source receipts and byte-exact original-resource gates passed. The actual same-snapshot four-file package passed 24 focused cases in 22.33 seconds with zero skips. Both publish destinations match the tested hashes, and each passed both installed width models. Other VCL versions, ANSI encodings, IME, real physical input, persistent data writes, and full integration remain unverified. M0/T18/S64 remain open.
