# M0 T18 S64 P113: Delphi radio background

P112 styled actual DelphiVCL4Python 1.0.7 x86 and x64 ordinary `TRadioButton` and `TGroupButton` but filled their entire child surfaces white over a gray parent. In the real unstyled 144 DPI radio sample, the control forwarded its own WM_PAINT to USER BUTTON and requested WM_CTLCOLORSTATIC, receiving a null brush. Bare and P112 runs responded to posted BM_CLICK with 0 to 1 and one application callback. The same white patch occurred in the actual RadioGroup sample containing two TGroupButton children. These observations do not imply all Delphi versions or variants.

The scoped parent-background handling already used for witnessed TCheckBox is extended to witnessed same-owner TRadioButton and TGroupButton. The original renderer draws its glyph and text afterward, and role/parent are revalidated after the system call's potential reentrancy. Unverified, changed, unsupported and push-button paths keep their existing behavior. The system API can fail, whereupon the existing light-fill fallback remains; theme-disabled or complex backgrounds are not claimed. No private VCL structure, original graphic resource or ABI is changed. Search `rg -n 'group_choice_button|group_button_identity|DrawThemeParentBackground' src/ntw16s-dll` identifies the identity guard, witness, installation, renderer call and post-call guard; other control paint paths retain their prior handling.

Both real widths on the actual clean package showed the individual radio and both group buttons attached. At representative background point (220,110), each previous white patch was RGB(255,255,255); both single and group candidates render RGB(240,240,240), matching a nearby parent pixel. The individual radio posted click changed 0 to 1, emitted one application callback, exited target/launcher 0, and left its owned job empty. The group capture probe confirmed close and target wait, then closed its owned kill-on-close job; it did not independently report both exit codes. Screenshots and synthetic messages are not physical input. Other DPI, custom backgrounds, theme-disabled behavior and other versions remain unverified.

Self-contained x86/x64 radio and group models use a custom RGB(42,123,56) parent, check background preservation, group selection, keyboard, font restoration, reparent and role retirement. P112 failed the background assertion for each role and width; all four candidate models passed. Existing checkbox and push models and frame models were included in 20 actual-package cases, all passed without skip in 7.08 seconds; full matrix not run. Both widths and both model roles passed from each of the two deployment locations. Clean C17 GCC 16.1.0/Ninja/ccache 4.13.6 builds passed ABI checks; clean snapshot SHA-256 `31621c95bde14e1891c08796da2afe0495d7ba5411ab46cb5eae3ff949248cc5`. Original five resource headers and provenance passed byte-exact verification. The source/test/selector diff before documentation was 14 added, 11 removed, net 3 lines. M0/T18/S64 remain open.
