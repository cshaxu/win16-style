# M0 T25 S4：标题绘制与重绘审计（进行中）

S3 P1 的窗口状态取自 `GetForegroundWindow`，在非客户区激活通知与前台窗口变化之间可能取到旧状态；每个 `WM_NCMOUSEMOVE` 又无条件重画标题，并覆盖原有窗口图标。S4 在窗口所属线程记录 `WM_NCACTIVATE`，只在非客户区鼠标命中区域变化时补画，使用应用提供的小图标或窗口类图标，并在 `WM_SETICON`、标题、主题、样式及 DPI 变化后更新。窗口销毁时删除状态属性；没有修改应用图标所有权或系统主题。

标题字体使用 8 磅粗体 Tahoma，按窗口 DPI 换算；微软 [Windows UX 字体指南](https://learn.microsoft.com/en-us/windows/win32/uxguide/vis-fonts)说明 Windows 2000 目标使用 8 磅 Tahoma，[Windows User Experience 2001 指南](https://blog-geofcrowl-static-images.s3.us-east-1.amazonaws.com/2020-02-17-collection-higs/MS-Windows-User-Experience-2001.pdf)列出标题栏粗体。字体创建失败回退 Windows 现有 GUI 字体；未将此推定为所有语言及所有 Win2000 自定义方案像素一致。

2026-11-10 自建私有桌面双位宽 `run16s --2k --wait` 窗口探针：活动蓝色与失活灰色标题的实际窗口 DC 像素、初始图标、`WM_SETICON` 更新、`WM_SETTEXT` 更新均有像素差异；单次窗口缩放及最大化/还原后，不额外切换焦点即检查标题像素；标题命中和系统关闭通过。x86/x64 结果一致。探针使用同步消息，不代表物理鼠标、系统菜单、连续拖动、所有 DPI、工具窗口或原版截图已验收。

## 原版渐变对照与工具窗口

只读参考 `private/ntos/w32/ntuser/kernel/globals.c`（SHA-256 `0983d5b102a7baca49118f59ecad450c0377094b7766bc9bcb539ae91fa256e1`）列出活动标题 `RGB(0,0,128)` 至 `RGB(16,132,208)`，失活标题 `RGB(128,128,128)` 至 `RGB(181,181,181)`。`caption.c` 的窗口标题路径在扣除按钮区和图标槽后对文本区域绘制渐变；这些结论是只读行为分析，没有复制实现或资源。用户截图在按钮前采样 `RGB(14,115,198)`；修正后自有窗口相同边界附近采样 `RGB(15,130,207)`。这证明渐变区间和颜色端点修正，不证明完整原版像素或全部配色方案。

将普通窗口和工具窗口连续放在同一自建进程时，x86/x64 的绘制断言均通过，但私有桌面驱动返回 `PRIVATE_DESKTOP_LEAK`；串行复测同样返回该错误。此失败不计通过。拆为各自独立进程后，普通窗口及工具窗口 x86/x64 分别通过且驱动报告桌面释放，但不能证明同进程序列的清理已修复。只读复查期间未查到对应桌面的持有线程，以下测试桌面名称仍可打开：`Win16S-Dialog-26108-346120437`、`Win16S-Dialog-29336-346120531`、`Win16S-Dialog-23188-346136140`、`Win16S-Dialog-37772-346371906`；不能仅凭线程检查推定持有句柄的进程或擅自终止进程。

复查结果：上述前 3 个私有桌面 `OpenDesktop` 返回 2（对象不存在），可确认已释放；`Win16S-Dialog-37772-346371906` 仍可打开。没有据此声称最初的清理断言通过，也未确认最后一个对象的持有者。两种窗口分开测试时桌面均正常释放。

进一步交叉核对 `private/windows/shell/migrate/gradient.c`（SHA-256 `ddfab2d6af3766e235f3d17e5616061860a50f6046cf7e43424ef0bdd9ce3c17`）的 `Windows Standard` 及其大字号变体：活动与失活四个端点与上述内核默认色相同。来源是只读数据对照，不将该表或程序复制进本仓库。用户截图中的标题高度和按钮几何仍由 Windows 11 USER 度量决定，尚未宣称等于原版。

再次核验最后一个桌面 `Win16S-Dialog-37772-346371906` 时，`OpenDesktop` 返回 2（对象不存在），现已释放；原有清理断言失败仍保留，不归因为已知代码问题或宣称同进程序列回归通过。

## 未指定图标的窗口

原版 `caption.c` 的 `xxxGetWindowSmIcon` 在窗口和类没有图标时使用系统默认 WINLOGO；代码亦说明窗口级图标优先于类图标。原实现没有这项回退，导致有系统菜单但未设置图标的窗口丢掉图标槽。现按窗口小图标、窗口大图标、类小图标、类大图标、系统默认图标的顺序查询。自建无类图标窗口在私有桌面的 x86/x64 两个增量测试分别检测到默认图标像素 224、设置窗口大图标后变化 238 像素，均正常退出并释放桌面。测试使用本机系统 WINLOGO，不声称其图形与 Windows 2000 原版一致；未复制外部图像或代码。

## 几何边界

原版 `inctlpan.c` 的 `SetNCMetrics` 从非客户区外观配置取得普通及工具标题宽高，标题高度还包括边界线；`caption.c` 使用对应尺寸绘制标题和按钮。原版并非所有用户配置下固定一个标题高度。当前实现使用系统窗口的 `WM_GETTITLEBARINFOEX`，因此 Windows 11 决定实际标题、按钮和命中几何；单独缩小绘图矩形不能改变原生客户区或命中区域。几何实现及鼠标命中须作为后续窗口交互工作一起验证，不将渐变和图标验证写成原版几何一致。

## P2 图标回归

用户在 Solitaire 截图中发现标题栏出现两个图标。只读对照原版 `winable2.c` 可见 `rcTitleBar` 排除了系统菜单图标区；现有 Windows 的原生非客户区绘制已绘制该图标，P2 又在标题文字区域画了一份。修复移除额外图标绘制及重复预留区域，保留系统图标绘制和命中。自有双位宽增量窗口探针实际检查原生图标区：设置大图标后改变 212 像素，而标题区同期变化 0 像素；普通窗口标题与图标更新测试通过。这不证明其他几何或图标资源与原版一致。

## 用户提供的配色参考

用户指出标题渐变及按钮、边框颜色不合格，并提供 Windows 2000 网图。该图片标题区域近右侧采样约 RGB(165,188,229)，与此前源码 Windows Standard 配色的亮蓝终点 RGB(16,132,208) 明显不同；网图来源、颜色管理及外观方案未获验证，不能声称两者是同一方案的原始像素。按用户提供的视觉目标调整活动标题右端为 RGB(166,192,232)，以截图观感而非源码默认方案作为本次选择。自有双位宽窗口近右端均采到 RGB(164,190,231)。

此前标题按钮和外框调用系统绘图，当前系统 COLOR_3DFACE 为 RGB(240,240,240)，不同于原版 Windows Standard 按钮面 RGB(192,192,192)。标题按钮在离屏位图中绘制并将系统经典灰阶局部映射到目标配色，未修改系统颜色或注册表；外圈使用独立灰阶。两位宽普通窗口的关闭按钮内均检测到 372 个 RGB(192,192,192) 像素。该检查不代表各按钮状态、所有边框、原版像素或人工视觉验收均已通过。
