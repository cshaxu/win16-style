## 原版渐变对照与工具窗口

只读参考 `private/ntos/w32/ntuser/kernel/globals.c`（SHA-256 `0983d5b102a7baca49118f59ecad450c0377094b7766bc9bcb539ae91fa256e1`）列出活动标题 `RGB(0,0,128)` 至 `RGB(16,132,208)`，失活标题 `RGB(128,128,128)` 至 `RGB(181,181,181)`。`caption.c` 的窗口标题路径在扣除按钮区和图标槽后对文本区域绘制渐变；这些结论是只读行为分析，没有复制实现或资源。用户截图在按钮前采样 `RGB(14,115,198)`；修正后自有窗口相同边界附近采样 `RGB(15,130,207)`。这证明渐变区间和颜色端点修正，不证明完整原版像素或全部配色方案。

将普通窗口和工具窗口连续放在同一自建进程时，x86/x64 的绘制断言均通过，但私有桌面驱动返回 `PRIVATE_DESKTOP_LEAK`；串行复测同样返回该错误。此失败不计通过。拆为各自独立进程后，普通窗口及工具窗口 x86/x64 分别通过且驱动报告桌面释放，但不能证明同进程序列的清理已修复。只读复查期间未查到对应桌面的持有线程，以下测试桌面名称仍可打开：`Win16S-Dialog-26108-346120437`、`Win16S-Dialog-29336-346120531`、`Win16S-Dialog-23188-346136140`、`Win16S-Dialog-37772-346371906`；不能仅凭线程检查推定持有句柄的进程或擅自终止进程。

复查结果：上述前 3 个私有桌面 `OpenDesktop` 返回 2（对象不存在），可确认已释放；`Win16S-Dialog-37772-346371906` 仍可打开。没有据此声称最初的清理断言通过，也未确认最后一个对象的持有者。两种窗口分开测试时桌面均正常释放。
