# M0 T20 S19: system menu regression (in progress)

The released demo showed the native modern system popup. The original owner-draw preparation can fail for the actual demo system menu; restoring its state leaves native USER painting. The private popup scope now paints supported native system-menu rows using the existing System menu renderer after USER painting, without replacing the menu handle or command dispatch. Application owner-drawn and unsupported bitmap items cause this overlay to be skipped.

Evidence: on a private desktop a DPI-aware native observer captured the actual window DC (not just WM_PRINT). The old O:/winnt package yielded zero selected Win16 blue pixels and the candidate yielded 8785; the candidate screenshot is build/t20-s19/demo-sysmenu-screen.bmp. The real demo negative fixture detects the old package. The native self-owned menu test verifies popup state restoration and application owner-draw callbacks; it does not claim no temporary owner-draw conversion, since the pre-existing renderer temporarily uses it.

The s19-clean2 clean x86/x64 build and ABI checks passed; source and original resource identity gates passed. s19-check tested the same four files: 15 focused cases passed, no skips, including both menu cancellation matrices, x86/x64 system menus and actual demo. This is not the full matrix. The s19-stage-publish stage deployed the tested files to assets and O:/winnt with matching SHA-256. The test harness did not test physical input. A posted WM_NCLBUTTONDOWN did not open the native menu on the inactive private desktop; this is a probe limitation and mouse activation remains unverified. Dynamic no-flicker on real mouse movement remains unverified. Do not close S19 on these results alone.
