# M0 T18 S64 P71: ordinary Delphi group-box frame

Ordinary runtime-owned `TGroupBox` controls previously retained their themed frame. A candidate is now observed during the newly created window's own `WM_PAINT`. A successful group-theme background call establishes the exact frame rectangle for that paint; for a nonempty caption the subsequent `DrawThemeTextEx` must match the same window, owner module, parent, enabled role, title text, DC coordinates and frame geometry before the title rectangle is excluded and the one-pixel frame is drawn. An empty caption uses the observed full-window background rectangle. The original theme and text calls execute first; their results and last-error values are preserved. Application captions, font, content and input remain under the application/framework's ownership. Unrecognized roles, disabled state, unexpected mapping or drawing order fall back to native. A bound group retires when its parent changes. Reentrant state and parent identity are checked again before drawing.

The new project-authored C fixture is a model, not a Delphi runtime. Both widths passed no-background and outside-paint rejection, accepted matching paint, clip preservation, reparent retirement, reentrant reparent rejection, empty title, disabled fallback and wrong parent owner. The prior published package failed the positive attachment assertion for both widths. The actual separately built DelphiVCL4Python 1.0.7 x86/x64 samples at 144 DPI used the candidate package's matching DLL, reported group attached, restored observer imports and closed normally. Against the corresponding previous published captures, each 250x120 image changed 633 RGB pixels; the observed title rectangle and a separate central client rectangle changed zero pixels. Empty-title real-sample pixel evidence is x86 only; x64 empty-title was exercised in the C model. The native screenshot is in the registered local scratch `build/t18-s64-vb-groupbox/pkg32.bmp`.
