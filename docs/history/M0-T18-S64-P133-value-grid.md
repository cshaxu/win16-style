# M0 T18 S64 P133: value-editor frame

The real Delphi XE x86 `TValueListEditor` sample described in [the investigation](M0-T18-S64-valuelist-investigation.md) has an application-owned Unicode grid window with `WS_EX_CLIENTEDGE` but no initial scrollbar. P132 did not attach the grid itself; the existing `TStringGrid` / `TDrawGrid` path requires a scrollbar and does not recognize this class. Its editor and popup were already independently styled.

The existing grid nonclient renderer now also accepts this exact Unicode application-owned class, on its creation thread and original parent, with the client edge and non-RTL role intact. The first completed `WM_PAINT` admits a no-scrollbar instance; an instance with a scrollbar still requires valid public scroll information. The grid owns its cell painting, data and editing, and role/parent loss retains the existing retirement path. No graphic resource, public ABI or additional product file was introduced. The existing string/draw grid branches keep their scroll requirements.

The clean package's real x86 sample at 96 DPI showed 846 changed nonclient pixels and zero client changes in a same-window removal comparison. In the attached window the editor changed `A-100` to `A-100Z`; the owned process exited zero. A separate run with the grid attached opened its list, changed the item count through long/short/long/short, returned the selected Japanese value and released capture. This is not evidence of physical input, binding semantics, other Delphi versions or real high DPI.

Self-owned x86/x64 models verify the frame pixels, unchanged client, missing-edge fallback, dynamic scrollbar show/hide, original-parent retirement and destruction, alongside the pre-existing popup model. P132 fails the new grid positive assertion on both widths. The clean C17 MinGW GCC/Ninja/ccache build and both ABI checks passed; original graphics and source receipts passed their identity gates. The actual same-snapshot four-file package passed 24 focused cases in 19.84 seconds, zero skips, including prior grid, list, edit, startup, VB and menu paths. Both release locations matched the tested hashes and each passed both installed-width models. Full integration, other application-owned grid subclasses, physical input and real high DPI remain unverified.

The production diff adds seven and removes four lines, the test adds six and removes one, and package markers add two and remove two.
