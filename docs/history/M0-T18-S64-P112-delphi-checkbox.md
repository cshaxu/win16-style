# M0 T18 S64 P112: runtime-owned Delphi checkbox

The actual DelphiVCL4Python 1.0.7 `TCheckBox` is registered by the runtime module and is not a native superclass according to RealGetWindowClass. At 144 DPI on both x86 and x64, P111 initialized and attached the root, but not the checkbox. The control's own WM_PAINT forwarded to the USER32 registered BUTTON procedure from its class-owner module; its dialog code, ideal size, check and state responses were valid, and the observed ordinary role used BS_3STATE. The temporary observer restored its IAT changes. A posted BM_CLICK caused the actual application OnClick once and BM_GETCHECK 0 to 1 for both bare and P111 runs. Each owned target and launcher exited 0 and its job emptied.

The implementation extends the existing same-owner, same-thread paint witness and public BUTTON protocol to the exact `TCheckBox` BS_3STATE role, retaining its native state/event owner. Unsupported roles, image/bitmap, push-like and RTL fall back; no private VCL layout or public ABI was added. Initial candidate screenshots showed the generic control painter covering the parent with white. The real unstyled control sent WM_CTLCOLORSTATIC and received a null brush; the bounded candidate now invokes the system parent background drawing API for this checkbox before its glyph and text, then revalidates its role after possible reentrancy. The real 144 DPI capture shows the original gray background. If the parent background call fails, the existing painter's light background is used; complex parent painting and theme-disabled cases have not been proved.

The actual same-batch clean package attached the real checkbox in both widths, selected the existing Win16 System font, drew the classic check glyph, and posted one click yielding 0 to 1 and one OnClick. Target and launcher exits were 0, owned job active count 0. This is synthetic input, not physical input. The self-owned C model exercises unwitnessed and foreign callers, wrong parent, bitmap exclusion, input and three check values, a non-default parent background, background-time reparenting, owner-draw role transition, font restoration and cleanup. Both widths failed its attachment assertion against P111; they passed with the candidate. A 22-case focused actual-package run passed without skips in 22.82 seconds, including existing VB, radio, group and push cases and mandatory injection/propagation. It did not include the full matrix. Other DPI, non-Western text, more Delphi versions, real three-state interaction, physical input and theme-disabled/custom complex backgrounds remain unverified; no claim is made that all checkbox variants or all controls are complete.
