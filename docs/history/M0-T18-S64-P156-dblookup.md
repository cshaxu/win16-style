# M0 T18 S64 P156: Delphi data lookup dropdown button

One real x86 Delphi data-aware sample creates an application-owned `TDBLookupComboBox`: it is Unicode at the creation hook and ANSI after the VCL construction. Its enabled dropdown button uses a tracked COMBOBOX theme, same-window client DC, same class-owner caller and a right-edge client rectangle. The bounded change recognizes this exact child class only with same-thread, same-owner parent and client edge; it reuses the existing dropdown-button face and original arrow. The original in-place editor identity remains separate, so its popup-list admission is unchanged. BUTTON-theme drawing, unknown states, mismatched parent, owner, DC, clipping and geometry do not gain this dropdown renderer. Data, callbacks, client text, assets and ABI are not replaced.

The actual clean candidate package loaded x86 DLL SHA-256 `298fdd5474abecc5d64fdd406d4d2261edb1aa792bd1bae18433cc8724338656` in the private XDB sample documented in [the investigation](M0-T18-S64-lookup-investigation.md). A mouse-message selection closed the separate popup and the target exited zero. Compared with the published baseline, the control capture changed by 289 RGB pixels in the button; the sample's `TDBText` bound key display region was identical between baseline and candidate before and after selection, and each version's region changed by 30 pixels when the selection changed. This is observable binding display, not a direct key read or persistence proof. The subclass changes `IsWindowUnicode` from 0 to 1 in this sample; WM_GETTEXT A/W both return empty and are not text evidence.

Dual-width native ANSI fixture tests cover `Café` through A/W messages on ACP 1252, enabled dropdown glyph, wrong owner/parent, missing client edge, fake paint, foreign BUTTON theme, reparent and removal. Existing in-place tests also cover geometry, clipping, unrelated drawing, pressed/hot fallback and unwind. The earlier focused positive-only model fails on both old-package widths because lookup is not attached. The final combined model also fails on the old package in a pre-positive removal assertion, so that latter failure alone is not evidence of the new positive assertion. Real non-ASCII content, physical input, keyboard cancellation, multiple data versions, additional DPI, disabled/hot lookup paths, persistent key writes and full integration remain unverified.

MinGW GCC/Ninja/ccache clean x86/x64 build, ABI and source/resource gates passed. The first package build failed the local source receipt gate and was discarded; updating all three affected receipts and normalizing LF passed the manifest self-test. The final same-snapshot four-file package passed 24 focused actual-package cases in 16.17 seconds with zero skips. Both destination installations passed the dual-width lookup model and match the candidate four-file SHA-256 values. No fifth product file was added. M0/T18/S64 remain open.

A separate x86 scratch fault that removed the lookup BUTTON-theme guard was rejected by the `!attached(button_lookup)` assertion. The fault DLL was never published.
