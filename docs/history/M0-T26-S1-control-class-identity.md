# T26 S1 控件类身份抽离

将原 `win16-control/control_class.h` 中的原生类、系统控件协议以及 VB5/VB6 运行时类身份识别移入 `lib-style/common/control_class.h`；Win16 产品和控件库直接调用公共名称，不保留旧别名。VB 运行时类仍须通过已有的运行时模块身份校验，不能仅凭同名窗口冒充。组合框、按钮等常用类的别名映射随身份识别提供给其他风格，公共头不依赖 Win16 绘制或私有头。

Win16 特有的 DPI、owner-draw、图形选项和 VB 容器支持资格仍在 `win16-control/control_class.h`，因为它们约束的是已有绘制能力，不应作为其他风格的通用限制。Win2000 尚未接入这组识别函数，本次不宣称新增任何控件样式。

双位宽增量编译通过；公共控件协议测试在原生编辑控件、超类、错误类别及伪造 VB 类上验证识别。Win16 独立链接测试通过；自建 VB6 运行时模型在 x86/x64、96/144 DPI 分别运行未套样式和套样式的控件路径，通过类身份、组合框、编辑框、按钮、滚动条、交互和移除恢复测试。没有创建或切换隔离桌面；测试副本已清理。来源清单、公共源码边界和 `git diff --check` 通过。这是增量验证，尚未干净构建、发布或测试正式产品包。

补充：公共测试分别加载自建 VB5 和 VB6 文件控件模型，验证目录列表身份及错误类别，x86/x64 均通过；它不安装产品钩子，不能替代产品完整路径。`core-vb-files --private-worker` 的四个位宽/版本组合在安装测试线程钩子时均返回错误 126；第十二批已发布启动器同机对照也有相同结果，四项均为失败而非通过。Win2000 现有选择只接受五种精确原生类名，公共别名识别会扩大该范围，因此没有直接替换其选择策略。
