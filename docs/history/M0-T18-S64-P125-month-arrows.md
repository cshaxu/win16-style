# M0 T18 S64 P125: Delphi month-calendar navigation arrows

The prior [month-calendar investigation](M0-T18-S64-monthcalendar-investigation.md) found that disabling the window theme changes the native minimum size. Further measurement showed that replacing the font with stock System changed the 96 DPI sample's minimum to 246 by 185, exceeding its existing width. Varying the public calendar border could not independently recover the original width and height. Neither technique is used by this delivery.

The real x86 Delphi XE sample forwards WM_PAINT to the registered SysMonthCal32 procedure. Under the existing theme, the system control calls DrawThemeBackground for the published `MC_NAVPREV` and `MC_NAVNEXT` parts on an intermediate memory DC. The implementation reuses the existing, byte-identical left/right scrollbar glyph resources only for square parts within a fresh, same-thread paint witness, the exact window theme and native caller. It leaves the native theme, other calendar pixels, font, colors and layout in place. Unsupported shapes, multiselect, unverified callers and roles fall back to native. There is no new hook, product file or public export.

The actual package's same-window comparison found 512 changed pixels inside the two rectangles reported by MCM_GETCALENDARGRIDINFO and zero outside; the disabled-control comparison had the same boundary. The minimum remained 225 by 160. Synthetic next/previous messages moved the visible month 2015-11 -> 2015-12 -> 2015-11 and released capture; the native and styled sample both changed selection from 2015-11-02 to 2015-11-01, so no stronger selection-preservation claim is made. The sample normally writes global locale settings on close: the probe did not click its buttons or close normally, and terminated only its own job. Four owned target/launcher jobs were emptied; this is not normal shutdown evidence.

An initial same-window comparison found zero changes. Diagnostic traces showed the sample's initial month-transition animation was still presenting an old buffer; allowing the target message loop 600 ms to settle produced the region-bounded result above. A separate pressed-state comparison also produced zero changed pixels during an animation; it is not counted as validation of the pressed visual. Physical input and other DPI/runtime versions remain unverified.

Self-owned x86/x64 v6 models pass wrong owner, fake paint, foreign caller, fresh witness, exception unwind, reparent during paint, multiselect fallback, selection, minimum layout, application color and theme retention, pixel boundaries and cleanup. P124 failed at the new attachment assertion in both widths. The C17 MinGW GCC/Ninja/ccache clean dual-width build, ABI and original-resource gates passed. The actual four-file package passed 29 focused cases in 20.58 seconds with no skips; both assets and O:/winnt/system32 matched its hashes and passed x86/x64 installed models. The native date grid, title and font remain outside this limited change; full T18 integration is incomplete. M0/T18/S64 remain open.
