# M0 T29 S10 中性样式运行时

基线为 [S9 发布](M0-T29-S9-modern-frames.md)。交付按[主题契约](../proposals/msstyles-build-contract.md)
和 [S2 兼容台账](M0-T29-S2-theme-and-abi.md)核对。

## 外部主题读取

工具继续生成约定的 ASCII 描述。运行时读取 `VisualStyles` 的三个字段，
将其中的文件名限定为同目录的单一 `.msstyles` 文件，并按描述查找尺寸和配色
变体。无效或不完整描述在映射前失败。读入失败不替换调用方现有状态。
`classic_theme_open` 返回模型和拥有的只读资源映射，`classic_theme_close`
负责释放。映射存活期间可按模型中的 ID 读取标题按钮、菜单图像和原有对话框模板。

两宽增量构建和原生测试通过。测试从实际两份 `.theme` 读回两种模型，
核对 Win16 标题及菜单原图与 Win2K 三份打印页资源，并覆盖路径越界、绝对路径、
重复键和缺字段四项负例。x64 的 `check-classic-themes` 重新生成四个主题文件，
摘要与 S9 发布逐件一致。来源及五个原资源门禁通过。

## 外部主题进入绘制和对话框

普通窗口、标准控件、复合控件的相关配色、直接 UWP 外框和 Win2000
公共对话框均按渲染模块所在目录查找对应的外部主题。窗口复制模型和标题图形后
释放映射；需要延迟读取选择控件图像的 Win16 控件持有映射直到控件退役；
打印属性页在原生调用返回后释放对其资源的引用。当前没有 `themes` 目录的旧式
测试目录仍可用嵌入资源。x86 增量构建树没有独立 `.msstyles` 的生成目标，
所以开发回归将两组共享文件与双宽运行件一起暂存。

- 两宽各用现有 Win16 和 Win2K 入口对自有普通窗口和按钮附着及撤销。
  仅改变暂存副本的标题、按钮填色条目后，四组都实测标题为 `#1D435B`、
  按钮为 `#2F78A4`。每组另跑原主题作为对照，八次探针均通过。
- 移除暂存 Win2K DLL 的 201–203 三份打印模板后，x86 和 x64 的 ANSI
  取消及 Unicode 扩展页 Apply 均通过。模板仍从 `.msstyles` 加载，
  实测完整页 438×322、扩展页 438×354，后者返回三份副本和两段页码。
- 双宽自有 UWP 宿主使用同一目录的两组主题，样式互切、最大化、还原和
  移除通过。探针及其临时目录已清理。
- Win2K 正常启动的双宽原生窗口通过标题、按钮命中、重绘与恢复断言。
  Win16 六类控件的 20 轮回归，两宽各通过一次。x64 初次在 USER 对象数
  断言失败，单独复测的 S9 基线、S10 外部主题和 S10 嵌入回退均通过，
  三次 GDI 为 9→9，USER 为 0→0。

## 装配迁移

两种呈现装配已经链接进 x86 和 x64 的 `ntwshk`。中性 DLL 内部直接调用
Win2K 的窗口接口。直接 UWP 路径从外部主题读取，两种风格均可在没有旧 DLL
的目录中工作。旧资源来源说明同步放入中性 DLL。

在仅有对应位宽 `ntwshk`、两个主题和自有测试程序的目录中，两宽各完成
Win16 与 Win2K 的标题和按钮换色、恢复，八次对照通过。双宽 UWP 自有窗口
完成两种风格互切、最大化、还原和移除。PE 检查得到 x86 94 个、x64 95 个
命名导出，两个旧 DLL 的 42 个命名接口全部存在。中性 helper 使用序号 1，
两宽均无对旧 DLL 或自身的 PE 导入。增量八文件的 PE/ABI 包门禁通过。
测试临时目录已清理。

普通启动现使用 `ntwshk`，启动载荷明确区分两种风格。两个位宽使用同一个
启动事务与原有辅助流程。兼容安排按 S2 台账执行。原先 `ntwshk` 序号 1
对应的 `process_hook_install_helper` 仍可按名调用，序号 1 现在是
`rundll32` 使用的中性初始化回调。旧 DLL 本身的序号保持原样。

在没有旧 DLL 的暂存目录中实测 12 组。两种风格各通过 x86、x64 直接启动，
并各通过 32→32、32→64、64→32、64→64 子进程样式传播。所有自有窗口均
确认初始化、样式及恢复。两种风格各在缺失、无效主题时提前退出，共四组，
均在创建目标前报错退出。Win2K 正常启动的双宽 ANSI 打印取消和 Unicode
扩展页 Apply 也通过。双宽启动载荷测试及增量八文件 PE/ABI 包门禁通过。

## 全局模块选择与主题失效

全局控制器使用与普通启动共用的包路径解析，验证双宽 `ntwshk` PE。
全局会话身份与晚期传播也使用中性文件名，保留原会话和权限校验。
中性 DLL 的窗口样式切换在两个方向均取同模块的另一套呈现作为移除和恢复目标。
托盘选择新主题前验证其描述和资源，失败时保留当前选择。取消已选样式仍可执行。
UWP 切换在移除旧外框前验证目标主题。

- 双宽增量构建成功。双宽托盘控制器单元测试验证切换失败时不会发送停止，
  当前主题描述缺失时仍可关掉当前样式。
- 暂存目录只有双宽中性 DLL、主题和自有会话夹具。两宽仅在自有线程启用生产
  接收器，文件选择、查找、颜色、字体、消息和两种打印用法共 14/14 通过。
- 同一受限方式验证 Win16 晚期传播。32→32、32→64、64→32、64→64
  四组的根窗口均由生产接收器附着。八个子进程或孙进程均加载中性 DLL，
  并观察到创建的自有窗口附着 Win16 样式。
- x86、x64 各按原生、普通 Win16 启动、普通 Win2K 启动三种起点运行
  六种 Win32 切换。两种样式互切、切回原生和新会话重启共 36/36。
  观察两个呈现器的实际附着状态，整段只对自有 UI 线程安装接收器。
- 初次向已用 Win2K 启动的目标切 Win16，两宽出现回调异常。原生栈显示
  `bridge_create` 递归并耗尽栈。修复后普通 Win2K 启动只注册一次
  COM 桥，晚期沿用原调用指针并按活动会话选择模式。普通启动的 Win2K
  COM 打开和保存、Win16 `CoCreateInstanceEx` 目录确认和取消共 12/12。
- 两宽的 UWP 自有宿主外框通过双向切换和恢复。从两个方向暂移目标主题描述时，
  均拒绝切换并保留原有外框。临时验证目录已清理。
- 增量八文件 PE/ABI 门禁、来源清单和五份原图核验通过。

启动器的既有窗口和 UWP 查找已指向中性 DLL，真实应用端到端复验见下。
受限全局探针未开启桌面全局钩子，观察窗口附着状态，不计作物理输入或
逐像素恢复验证。

首次干净快照在源码边界门禁停止。启动协议的备用风格位在公共头和解析器中
带有具体年代名称。已改为通用备用风格位，产品独自决定该位代表 Win2K，
保持载荷位值及校验规则。源码边界门禁复验通过。实际 UWP 探针也更新了
撤销路径，从生产启动器所在目录使用同一中性 DLL 执行撤销。

## 交付前回归

旧验收夹具原先复制年代 DLL 并按旧模块名判断启动、传播及演示窗口。
已改为同时暂存两对主题和两个中性 DLL，并在实际进程中验证中性模块。
使用已有直接 worker 入口，未创建或切换桌面。双宽启动矩阵、
八条 A/W 子进程链（含跨位宽、三代及调用方暂停状态）、原生与 Win16
演示对照、Win2K 演示均通过。Win16 演示初次在显式现代文件选择入口
发现自身仍查询旧 DLL。该入口已指向中性 DLL，重新运行后，三条保留
现代布局的入口及其余打开、保存和目录选择路径均通过。演示程序未增加
样式 PE 依赖。启动载荷双宽通过，四个主题摘要在两处发布目录及开发构建一致。
隔离的暂存目录和位图输出已清理。

第二次干净构建通过，两宽分别用时 356.61 秒和 400.50 秒。演示修复及夹具改动
发生在快照完成后，逐件复核全部快照输入，仅演示的产品源码有变化。
同一干净树中重新生成演示及相应夹具，再对八件包执行 PE、ABI、构建根摘要门禁。
两份中性 DLL 均核对到原始 18 张字模表及来源声明，四个主题独立读回通过。

用户提供的 About Notepad 截图侧边各为 11 个物理像素。用自有
`C:/Windows/System32/notepad.exe` 实测，144 DPI 下原生与中性 Win2K
候选的 About 对话框均为 709×630，非客户区左、上、右、下均为
11、45、11、11；样式标记确认候选确实附着。当前固定外框压缩比较的
系统度量与目标同为 3，因此实际保留了该对话框的原生外框。内部内容布局
由原生对话框持有。本轮记录差异，未改对话框几何。测试目录已清理。
另一次 WinUI 测试实际打开的是同一个经典 Notepad。显式商店别名返回
1920，未计作真实 WinUI 验证。

## 发布与实包回归

首次复制在 `O:/winnt/ntw16s64.dll` 遇到映射占用，已将两处本次改动恢复
至 S9 并逐件核对。自有副本证实同盘改名可保留旧映射。重新发布时先将每个旧
文件改名至任务暂存区，再用已核对摘要的候选占据原路径。两处的 8 个程序文件
及 4 个主题摘要一致。未关闭占用者。保留的映射和回滚文件与新路径分离。

发布后 18/18 项聚焦验证通过。两处均验证双宽 ABI、启动、实际 Win2K 外框、
COM 文件对话框和八条传播链，另在 `O:/winnt` 复测 Win16 与 Win2K 演示。
实际 Scan Win2K 和 Calculator 两种风格均通过状态转换、撤销和原有几何恢复。

在同一真实桌面重测通过。该现象不证明冷启动稳定性。两种真实 WinUI Notepad
均保留内容桥并观察到对应标题像素，未验证实际记事本撤销。见[发布摘要](../etc/release.json)。
当前两处仍是 S10 过渡包，七件正式切换及旧文件退役由 S11 执行。
