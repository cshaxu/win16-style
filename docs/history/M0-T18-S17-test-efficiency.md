# M0 T18 S17 — package progress and font-test efficiency

S15's test runner aborted when an observer held `progress.json` with a read-only sharing mode. A focused test reproduced the old `Set-Content` failure as Win32 sharing violation; the replacement treats only sharing/lock violations as an advisory missed progress snapshot, counts them, and retries on the next scheduled update. After the reader releases the file, the next snapshot is written and parsed; an unrelated invalid-path error still propagates. Actual case exits, assertion failures, timeouts, and package identity checks remain fatal.

The font matrix retains its original `GetTextExtentPoint32W` single-character comparisons for every ASCII character, every case, every warmup and both DPI-awareness contexts. It selects each source/candidate font once per 95-character group instead of switching twice per character; all eight warmup rounds, pixel oracles, and final GDI-resource comparisons remain unchanged. Standalone x86/x64 full-matrix runs passed in 75.30 and 65.07 seconds; the preceding serial S16 runs were 103.75 and 65.54 seconds respectively, subject to machine load. A scratch negative fixture deliberately changed one expected character width and still exited 1 at the width assertion. An additional test-only comparison found `GetCharWidth32W` matched single-character extents in the tested x86/x64 matrices, but the production test retains its original extent API rather than relying on cross-platform equivalence of different APIs. No product renderer, ABI or original graphics changed.

The clean S17 dual-width snapshot passed source, original-resource, governance and ABI gates. Its actual four-file package passed 92 cases with zero skips in 496.80 seconds at two slots; physical input and the separate full-integration matrix were not run. The explicit live reader held the real progress file for four seconds; the runner recorded three sharing conflicts, continued, and completed all cases. In this same package run x86/x64 font cases took 66.06/57.32 seconds, versus 103.75/65.54 seconds in the preceding S16 run at the same concurrency; machine load is not controlled. Test failure and non-sharing I/O failure paths remain fatal.
