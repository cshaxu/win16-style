# M0 T18 S64 P174: bounded VCL file-list nonclient models

Embarcadero documents both TDirectoryListBox and TFileListBox as TCustomListBox descendants. Existing native LISTBOX classification reached a generic owner-draw rejection before the nonclient path. The new candidate recognizes only exact Unicode names, application main-module class owner and same-owner parent, same GUI thread, USER LISTBOX superclass, owner-draw with strings, client edge and a vertical or horizontal scrollbar. It routes that shape to the existing grid nonclient border/scrollbar painter and leaves the application-owned client, item contents, drawing callbacks and selection unchanged. This is a deliberately bounded native model: no real Delphi file-list control, filesystem navigation, directory/file linkage, actual icons, ANSI runtime or other DPI has been verified, and this is not a claim of complete family support.

The self-authored dual-width LISTBOX superclass models create both exact names with 20 owner-drawn entries. Each candidate attaches, invokes measurement and drawing, retains selected index and item data, and differs from the removed state by 2816 nonclient RGB pixels and zero client pixels. No-edge, no-scroll, wrong parent owner and reparent retirement are checked; the initial directory positive assertion fails on P173 in both widths. The original first candidate failed positive on both widths; an x86 temporary diagnostic showed control=1, grid identity=1 and generic owner-draw rejection before candidate routing. It was discarded. The subsequent model candidate passed, after which no-scroll rejection and both models were added to the final snapshot.

An unrelated existing superclass case failed its original 30-second wait in a bare child before product injection; short tracing isolated the wait to teardown of its active test root window. Clearing focus did not fix it. The test now leaves remaining owned windows and classes for isolated process exit, while retaining assertions, font/DC cleanup and parent-owned job-empty checks; individual waits are limited to 10 seconds. Thus this suite does not prove explicit root-window destruction or class unregister and the platform wait root cause remains unknown. Both widths ran its four bare/styled, 96/144 DPI cases in the final package. The earlier failed 18-case run and independent 16-case pass are retained, not overwritten.
