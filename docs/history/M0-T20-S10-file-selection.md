# M0 T20 S10：旧框导航后选择结果原型

S8 固定文件选择和S9目录/筛选刷新此前各自验证；本S将二者合并在同一次
系统旧框：自有根目录进入子目录，txt→log→txt，然后选真实枚举的长名。
首版用旧框hook捕获选择后调用 EndDialog；[微软文档](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/ms646932(v=vs.85))明确禁止这一操作，故此版本仅作负面证据，不可用于产品。修订版在捕获后按文档投递 IDABORT，以独立标志传回用户确认，再在**测试程序内**构造调用方应收到的
Explorer格式；无产品源码或公开API变更。目录身份来自对话框祖先列表，不
采用进程当前目录。测试结束恢复探针自身工作目录并删除自有文件目录。

首版双宽 A/W、直接/注入共24组增量对照通过（该版使用不合规的 EndDialog，仅为历史证据）：导航筛选后选一项、选两项及8字符
小缓冲；检查所选项目、实际子目录、单项完整路径、多项NUL与双NUL、文件名
及扩展名偏移、过滤器索引与清理。无注入系统Explorer单项双宽A/W四组另通过；
测试路径相差 `\SUB` 四字符时系统的偏移50/60和原型54/64一致。小缓冲原型
返回的12291和所需长度由测试程序构造，**底层 `CommDlgExtendedError()`
在首版 EndDialog 实测为0，而文档规定的 IDABORT 路径实测为65535**：这不是系统原生错误契约，正式实现必须先处理线程局部错误
及后续调用、取消、重入和错误所有权；不能直接把原型复制进生产。

两个其他关键边界尚未闭环：首版强制 `EndDialog` 不符合微软文档；修订版使用 IDABORT 依然不会走系统正常确认步骤，真实
应用可能依赖验证、当前目录、只读状态和通知；原型仅覆盖两个ASCII筛选和
夹具，未覆盖任意通配、输入文字、双击、网络/UNC、非ASCII、文件变更及应用
自定义hook/模板。这些不能以测试自身成功代替实际契约。当前发布版继续为
普通Win32多选保留Explorer；用户希望的旧布局尚未实现。

下一步优先研究如何在系统确认路径保留真实调用语义、正确提供错误和取消；
在无法证明之前不得发布产品实现。COM布局长尾仍按用户指示降级。

首个 `s10-selection-final` 快照含旧的 EndDialog 探针；发现微软禁止后已停止
本次自有过期构建，未将其结果计入验证。S10 修订导航探针及 S8 固定夹具探针，
均改为投递 IDABORT；S8 先前的 EndDialog 通过记录只保留为不合规历史证据。
修订版双宽 A/W 注入的单、多选与小缓冲12组增量测试通过，底层状态均明确
记录为 FALSE/65535，探针在退出后自行构造返回值。尚需与真实系统错误接口
及应用调用进行端到端验证。
