## 已证实或待核实的发现

1. **全局发现错误丢失**：`src/ntw16s-dll/global/manager.c` 的 `discover_existing_processes`、`discovered_process` 忽略扫描结果；`src/lib-win32/process-global/enumerate.c` 的线程迭代未区分 `Thread32Next` 正常结束与中途失败。候选已让初始扫描错误返回启动调用者，并识别迭代失败；新增测试注入迭代失败，另验证回调主动结束不被误报和快照句柄回收。事件回调 `discovered_process` 返回 void，如何传递其错误仍待设计和审计，不声称已完全修复。
2. **句柄创建可能覆盖原始错误**：`manager.c` 的 manager 启动连续调用 `OpenEventW`、`CreateEventW` 后才统一读取最后错误。候选逐调用立即记录失败并执行已有清理；管理器正常生命周期测试双位宽通过，单个句柄创建失败的注入验证尚未覆盖。
3. **附着状态集中**：`src/lib-win32/win16-control/attachment_state.h` 将许多控件状态和回调表共置；`src/ntw16s-dll/attachment.c` 负责跨类型协调。属于结构性审计线索，不预先认定所有字段或抽象都能安全删除。先梳理控件生命周期和状态访问，再选择能减少真实耦合、保留行为的改动。
4. **随机会话标识失败可能丢失原始错误**：`src/run16s-exe/global.c` 原先在 `CryptGenRandom` 失败后先释放 provider、再由调用者读取线程最后错误。候选改为在资源释放前保存错误并返回，释放本身失败时也向外返回，正常标识生成规则不变；x64 启动器和对应集成 fixture 已增量编译链接，失败注入及实际包尚未验证。
5. **打印 DC 创建重复**：`src/lib-win32/win16-dialog/print_extended.c` 的普通结果和 Apply 快照分别以相同的 ANSI/Unicode、DC/IC 参数选择创建打印设备上下文。候选合并为一个内部函数，保留各路径独立的 DEVMODE 准备及资源所有权；x86/x64 编译链接通过。增量同快照四文件在自建私有桌面通过 16 项对照：双位宽、ANSI/Unicode、Print/Apply、返回 IC/同时请求 DC 与 IC；均确认 `old=1`、`valid=1`，不表示已执行实际打印或最终包验证。
6. **不可达旧文件夹选择接线**：`ntw16s_classic_folder` 在产品、测试和导出清单均无调用，且此前用户指定文件夹选择使用 Shell 树；候选删除该产品侧入口、线程状态和失效接线，保留共享静态库和当前 Shell/COM 路径。双位宽增量包的 Shell、COM 树选择分别覆盖接受/取消，共 8 项私有桌面测试通过；不是最终包验证。另删除没有任何调用者的产品内部 `run16s_global()` 薄封装，保留实际入口 `run16s_global_with_parent()`。

全局发现的错误边界复核：`scan_existing` 的快照错误由 `manager_start` 返回并触发启动清理；实时 `discovered_process` 是无返回值的事件回调，当前明确丢弃单次线程快照错误，后续窗口发现仍可补救，不能据此声称所有发现错误都已向外传播。`scan_process` 在已记录 `ERROR_NOT_READY` 候选后，即使遍历随后失败也会提交该候选并返回遍历错误；其调用方目前忽略该错误。是否应丢弃候选或增加事件边界报告会改变现有重试行为，尚缺失败后目标接入与恢复的对照证据，暂不擅自修改。线程身份仍在正式接入时重新验证；这里的源码检查不等于故障、竞争和真实全局模式已经验证。

同一调用链中，`process_entry` 在目标事务后调用窗口遍历，但忽略遍历结果；`notify_window` 对消息注册失败和超时发送结果也不报告。窗口遍历组件本身区分超时、取消与成功，已有组件测试覆盖这些返回，不覆盖管理器忽略错误后的窗口实际附着。窗口观察回调也会尽力枚举子窗口，`EnumChildWindows` 的结果未传播。这些是现有尽力处理边界而非已证明全部成功；在保留原本成功目标、失败目标重试和窗口通知语义的前提下，仍需决定可由哪个最外层边界汇报，不能直接将部分窗口失败改成整体接入失败。

对产品启动和全局接线中的单行函数复核：`prepare_target` 是启动生命周期要求的回调，并注入 `CreateProcessW`；全局事务的 `step_validate`、`step_ready`、`step_apply` 和管理器的 `process_*` 适配器将公共回调上下文转换为产品票据，`mapped_identity` 还绑定产品导出名及解析器。它们不是可以直接将被调用函数名替换到回调表的同签名空转发；是否可进一步减少适配器需连同回调契约一起设计，不以删除名称或不安全的函数指针强转计作简化。
