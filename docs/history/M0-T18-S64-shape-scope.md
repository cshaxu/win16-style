# M0 T18 S64: TShape content scope and real samples

Embarcadero describes [`TShape`](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.ExtCtrls.TShape) as geometric content drawn on a form, with application-controlled [shape](https://docwiki.embarcadero.com/Libraries/Athens/en/Vcl.ExtCtrls.TShape.Shape), pen and [brush](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.ExtCtrls.TShape.Brush). It is not the same as [`TBevel`](https://docwiki.embarcadero.com/Libraries/Sydney/en/Vcl.ExtCtrls.TBevel), which supplies raised or lowered frames. Based on the user's instruction to leave application-provided drawing alone, TShape is classified as content to preserve, not a normal control chrome remaining to implement. This is a scope decision based on the role, not an assertion that the application manually draws every pixel.

Self-owned DelphiVCL4Python 1.0.7 x86 and x64 samples each constructed a rectangular and an elliptical TShape, at client positions (20,30) and (170,30), each 110x80, with red fill and green pen set through application properties. Bare and P164-styled runs captured the real form separately on private desktops; each styled target loaded the matching assets DLL and all targets exited zero. Native code recorded the distinct client offsets, and comparison aligned captures by client coordinates. Each corresponding 8,800-pixel shape rectangle was RGB-identical between bare and styled on both widths. The rectangle had 8,424 red/376 green pixels; ellipse had 6,592 red/268 green pixels. A scratch single-pixel modification was detected by the comparator (exit 1). The results do not establish all shapes, brushes, DPI values, VCL versions, interactions or future frames. Original captures, comparator and failing control are in registered `build/t18-s64-vb-mask-survey/shape-*` scratch.

No product source, graphics or binaries changed. TBevel remains under investigation and is not excluded. M0/T18/S64 remain open.
