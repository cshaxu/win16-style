# M0 T18 S64 P129: TValueListEditor in-place button

The real x86 Delphi XE sample and its source, hashes and test boundary are in [the investigation](M0-T18-S64-valuelist-investigation.md). Its `TValueListEditor` hosts a `TInplaceEditList` that draws an ellipsis button itself. The old package left that child unattached and its button visually modern.

The bounded implementation observes the child only when its same-thread parent is an application-owned `TValueListEditor` with the same class owner. During that child's own `WM_PAINT`, a successful, tracked BUTTON-theme part 1 call by the same owner can reuse the existing classic button face when its DC, coordinate system and right-edge geometry match. Only normal and pressed enabled states are admitted; disabled, hot, other roles and unverified situations retain native drawing. The original call and subsequent application ellipsis remain in place; text, selection, focus, events and data stay owned by the application. The scope unwinds on exceptions and retires if the parent or role changes. No new hook, public export, product file or original graphic was added.

The x86/96 DPI real sample's same-window removal comparison showed 254 changed pixels inside the button and zero outside, with 12 identical black interior pixels from the ellipsis. Both the old and experimental versions displayed one application dialog after a synthetic click, retained `A-100`, accepted `Z`, undid back to `A-100`, and released capture; all owned jobs exited zero. The real pressed theme call was observed as state 3. Disabling the editor left its theme state at 1, so eligibility also checks the actual enabled state. Physical input, other DPI/Delphi versions, dropdown buttons, hot and disabled classic styling remain outside this delivery.

Self-owned x86/x64 models check normal and pressed pixels, exact button area, glyph preservation, DC clipping, wrong parent and rectangle, fake painting, a foreign draw outside the paint scope, disabled and hot fallback, paint exceptions, click forwarding, reparenting and cleanup. P128 fails the positive attachment assertion in both widths; a deliberate omission of the enabled-state check is detected in both. The first foreign-draw comparison incorrectly drew the translucent theme over two different backgrounds; after resetting the same background before both calls it showed zero differing pixels. The first x64 scratch configuration used a missing ccache path and was corrected; neither failed attempt is counted as a pass.

The clean C17 MinGW GCC/Ninja/ccache dual-width build, ABI and original-resource gates passed. The actual four-file package passed 25 focused cases in 22.41 seconds without skips. The real sample confirmed the same 254/0-pixel comparison, click and editing results with that package. Both assets and O:/winnt/system32 matched all four hashes and passed the installed x86/x64 models.

The staged production source diff is 20 additions and 11 deletions in two files; the fixture, model, build and package-selection changes add 65 lines with no deletions, for a net 74 lines across code, tests and build tooling. Search `rg -n "inplace_identity|inplace_candidate|ntw16s_inplace_button|win16_style_bitbtn_face" src/ntw16s-dll` identifies the admission, lifetime guard and shared face painter; unrelated and unwitnessed theme calls keep their original path.

M0/T18/S64 remain open.
