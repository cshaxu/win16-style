# M0 T18 S64 P131: value-editor popup list

The real Delphi XE x86 sample described in [the investigation](M0-T18-S64-valuelist-investigation.md) creates `TPopupListbox` as a child of `TInplaceEditList`, then reparents it to the desktop. P130 left the visible list's border and scrollbar native. The original parent belongs to the executable and is under `TValueListEditor`; the list's `WM_PAINT` forwards to the registered USER32 LISTBOX procedure from that same executable.

The implementation recognizes that precise creation hierarchy and, only after the expected desktop reparent and same-window paint forwarding witness, installs the existing nonclient frame and scrollbar renderer. It rejects owner-draw and unsupported style variants, preserves the native list client, data and font, and checks its live identity. It introduces no export, graphics or product file. Other popup types and unverified ownership or forwarding stay native.

The clean package's real x86 sample at 96 DPI showed 2,268 changed nonclient pixels and zero client changes in a same-window removal comparison; the font handle and 13 entries were unchanged. Selecting entry 1 and sending Enter to the editor returned the exact three-character Japanese entry, hid the popup and released capture; the owned job exited zero. This is not physical input or evidence for other Delphi versions or real high DPI.

Native models on x86 and x64 verify wrong parent, owner-draw and fake paint rejection, native forwarding, list selection, scrolling, same-window frame pixels and unchanged client/font, reparenting and destruction. P130 failed the new positive assertion on both architectures. The actual same-snapshot four-file package passed 22 focused cases in 8.69 seconds with zero skips, including both models and adjacent rich edit, calendar, hotkey, box and editor tests; a second 17-case run covering classic startup, VB controls, menu cancellation and adjacent rich text passed in 20.74 seconds with zero skips. Clean C17 MinGW GCC/Ninja/ccache builds and ABI checks passed at both widths. Original resource and source provenance self-tests passed. Both publication locations matched the tested package and each passed both installed-width models. Full integration, physical input, true high-DPI rendering and other application variants remain unverified.

The production attachment change has 12 additions and 10 deletions; CMake adds four lines, package case registration adds two lines, and the project-authored model is separately recorded in the source receipts. Search `rg -n "rich_popup|ntw16s_rich_witness|win16_style_grid_install_created" src/ntw16s-dll` locates the narrow candidate and existing witness/frame path; other existing rich-control paths remain on their prior branch. The model and sample use only self-owned instances; no shared desktop process is injected. Scratch is registered under `build/t18-s64-vcl-value-survey` and `build/t18-package/s64-list-p131-*`.

M0, T18 and S64 remain open; this is a bounded development delivery.
