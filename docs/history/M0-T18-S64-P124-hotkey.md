# M0 T18 S64 P124: Delphi THotKey border

The [author's Delphi XE5 example](https://mrxray.on.coocan.jp/Delphi/plSamples/360_GlobalHotKey.htm), archive SHA-256 `543721a295052a3bbcc2b62afae94c667bf695ddf91b0a2156c1118a9516e73e`, contains several programs; only `07_ShortCut_THotkey/Project1.exe` (SHA-256 `af2e134ed914a3859c0ff45bea5a256abf77515a6f3a176f0020caa4ffa877aa`) was used. Its reviewed startup reads the control value and its shortcut handler is application-local; it does not register a global hotkey. No downloaded source or resource was incorporated into the product.

The real x86 Unicode `THotKey` had a client edge and was unattached under P123. A temporary same-thread observer found both WM_PAINT and HKM_GETHOTKEY forwarded through CallWindowProcW to the registered `msctls_hotkey32` procedure; the import was restored. The implementation extends the existing same-thread, same-owner fresh native-paint witness and existing edge painter to this exact Unicode role. It does not install an additional hook, change the application font, implement shortcut commands or register global hotkeys.

With the actual candidate package at 96 DPI, a same-window symmetric redraw/removal comparison showed 276 changed nonclient pixels and zero changed client pixels. The native and styled example both returned `045a` after the same synthetic key messages, retained focus, and restored the original shortcut after changing `0441 -> 0651 -> 0441`. Both owned target/launcher pairs exited zero and their jobs emptied. This is a message-level result, not physical-keyboard or IME verification.

Self-owned x86/x64 models cover wrong owner, fake paint, foreign caller, exception unwind and later painting, stale witness after reparenting during paint, client-edge role change, shortcut get/set, synthetic input compared with native and pixel preservation. P123 failed the new model at the attachment assertion in both widths; the candidate passed. Other runtime versions, DPI, ANSI controls, shortcut modifiers beyond those tested, physical input, application self-drawing and complete T18 integration remain unverified.

The clean C17 MinGW GCC/Ninja/ccache dual-width build, ABI and original-resource gates passed. The actual four-file package passed 27 focused cases in 21.80 seconds without skips. Both assets and O:/winnt/system32 matched the four hashes and each passed x86/x64 installed models. M0/T18/S64 remain open.
