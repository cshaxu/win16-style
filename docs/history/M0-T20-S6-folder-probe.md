# M0 T20 S6：COM 文件夹探针与临时目录超时

S4 所留的旧 COM 文件夹用例 x86 在已发布 P2 包再次超时；测试以实际批次
源码和工具运行，30秒预算耗尽。沙箱内私有桌面错误5为 skip，不是通过。

探针原来用文件对话框控件判断文件夹旧布局。S6 修改为验证旧 Shell 树的直接
子控件及真实返回路径，并保留文件打开/保存的原路径。曾误以“任何树控件”
判定旧布局：无注入系统现代框也有树，负例证明误报；最终要求直接子控件
14145及树类，并增加双宽系统现代框负例。探针用有限超时的窗口文本查询，
避免同步查询长时间阻塞。

旧探针原条件在系统临时目录创建目录并将其设为初始位置；改用 Windows 目录
作为只读目标后，已发布包 x86/x64 各确认、取消通过，返回路径核对通过。
这改变了测试夹具，**不能称原临时目录超时已修复**；原条件保留为
`com-dialog-target.exe folder cancel tempinitial` 可独立复现，且不将其计入通过。
同一旧 Shell API 使用自有临时目录初始选择时，无注入与注入 x86 对照均在
35秒超时；无注入现代 COM 选择框可出现及取消。两次线程采样见到 Shell 和
项目窗口处理栈，但不能证明项目重入是原因，也不能证明全部系统均会超时。
两项有明确路径的自有空临时目录在进程退出后已删除。更早旧探针超时没有打印
自有目录名，无法安全辨认并清理，未对用户临时目录做通配删除。

已知问题转 TODO：需要可重复且快的目录夹具、Shell 初始选择与项目性能对照，
仍需 x64、不同目录和长时间行为；不能通过增加超时或跳过测试称已修复。
