# M0 T18 S64: Delphi NumberBox investigation

A self-owned DelphiVCL4Python 1.0.7 TNumberBox at actual 144 DPI remains unattached and visually native in x86 and x64 current assets. The exact class, real class and class owner are TNumberBox and the runtime module, with four/eight native class extra bytes; the observed default sample has no child HWND. Bare and styled processes in both widths forward their own WM_PAINT and EM_REPLACESEL to the registered system EDIT procedure, and the observer restores the original import and text. Synthetic WM_CHAR changes 42 to 72; real OnChange logs were emitted, with all target and launcher exits zero and owned job process counts zero. Direct EM_REPLACESEL produced 4X, a native message observation, not proof that the numeric validation accepts arbitrary letters on user input.

Candidate: exact newly created single-line TNumberBox with the existing verified same-thread class-owner native EDIT paint witness and protocol, then the existing edit renderer. No blanket class-name-only install. First test default and numeric variants, input/value/event and bounds, paint/clip, wrong caller/identity, reentrancy, old-package negative, both widths and real pixel output. No product or binary changed as of admission; untested spin-button options and other frameworks cannot be assumed supported.
