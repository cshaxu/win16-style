# M0 T20 S8：旧式文件框长名多选受控原型

## 已验证内容

基于 S7 证据，使用系统 `GetOpenFileNameA/W` 旧模板和自有 hook，不修改产品：
在测试文件列表中补入两个自有、无8.3别名的固定长名，以标准列表消息选择，
在确认时读取两个实际选中项。原生旧框被 `EndDialog` 结束后虽然返回成功，
`lpstrFile` 为空；探针因此在返回后自行生成 Explorer 目录、文件名、双NUL
格式并校验结果。小缓冲时原型写入所需字节或字符数并报告 12291。
这只是探针自行模拟，不能宣称系统已原生提供该结果或产品已支持。

自有私有桌面，双宽 A/W 的直接旧框正常选择与小缓冲8组通过；样式启动后的
双宽 A/W 正常选择4组通过，x86 Unicode取消的直接和样式启动各通过。第一次
原型因 `EndDialog` 退出后当前目录仍指向测试目录导致删除目录失败；确认进程
结束后按两次输出的精确自有路径删除空目录。探针现先恢复启动时工作目录，
再删除自身文件及目录；这只解决探针清理，不证明对任意应用的当前目录行为。

## 产品实施前的缺口

文件名目前由探针固定提供，并非任意目录的真实枚举；目录导航、筛选变化、
隐藏文件、单选、手输、双击、文件不存在/变更、Unicode/ANSI不可表示字符、
超长结果、重入和资源生命周期都没有验证。强制关闭对话框绕过系统默认确认
路径，可能改变只读、路径验证、通知、文件偏移或进程目录等契约。测试中
自行恢复当前目录也不能用作产品全局解决方案。应用hook、模板和未知标志应
继续保留系统路径。上述风险没有被本原型解决，当前不得据此改写生产转接；
已发布包的普通Win32多选仍保留Explorer布局。

最小后续方向是在真实旧系统框内以当前目录和过滤规则补充可选文件，先分别
验证导航/过滤刷新、选中文件身份、单选与取消，再确定如何安全处理确认、
缓冲和当前目录；任何无法保留调用契约的场景必须回退并明确记录。
