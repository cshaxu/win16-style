# M0 T18 S64 P114: modern Delphi editable combo

Real DelphiVCL4Python 1.0.7 runtime-owned TComboBox x86/x64 at 144 DPI forwarded its own WM_PAINT through the runtime to USER COMBOBOX. P113 attached its native EDIT child but not the shell, leaving its arrow and border modern. The fix admits the precise same-thread, same-owner parent/child editable CBS_DROPDOWN without owner-draw or RTL, after same-owner native procedure paint witness and public combo information/count/selection validation. It reuses the existing renderer, popup list and resources. Parent and role are checked before and after synchronous validation and installation; after installation a parent or role change retires the exact attachment. Native selection, edit, notification and list ownership remain with the application. No public ABI or product file was added.

The editable shell retains the application's font; its already independently attached EDIT remains responsible for its own styled text. The initial scratch prototype replaced the shell font, and restoring it during removal while the list was open caused the native combo to close the popup. Bare Delphi also closed its popup when sent the same WM_SETFONT. The final candidate avoids the synthetic shell font replacement and thus does not need to restore it. In the real clean-package sample in both widths, the 32-item popup was visible and captured with classic text, selection and scrollbar; GetComboBoxInfo reported 32 items and selected index 0. While the popup was open, removing shell styling left it open, kept the EDIT attached with the same font handle, kept the list HWND valid, and allowed it to close. Targets and launchers exited 0 and owned jobs emptied. A separate font-change comparison in both widths found parent font acceptance/restoration identical to P113; the EDIT's private font handle changed on restoration in both, so equality of that handle is not claimed. These observations use synthetic messages and PrintWindow, not physical input.

The independent self-owned C fixture verifies same-owner native paint, fake paint, wrong caller, wrong parent, item selection, application font, removal with an open popup, reparent, owner-draw role change, a CB_GETCOUNT-triggered reparent and cleanup. The fixture creates a real system combo through delayed initialization; RealGetWindowClass changes from TComboBox to COMBOBOX in that fixture, unlike the actual Delphi sample. Admission requires the observed TComboBox real class at creation, with either observed identity accepted on revalidation. P113 failed the new shell-attached assertion for both widths; an earlier experimental candidate failed the font assertion in both. The reparent trigger was observed after a paint but its exact relation to binding was not independently established. The fixture's EDIT is not independently attached; the real sample separately verifies that case. An initial 64-bit long-list probe selected the popup as the root and failed; fixing root classification made both actual sample widths pass. These failures are not counted as passes.

Clean C17 GCC 16.1.0/Ninja/ccache 4.13.6 builds passed both PE and ABI checks; snapshot SHA-256 `72b00c4e9cc5ab5d58cf0db01d31587d0108b5dce0e9b51ea16fe51eb4ddfdf3`. The same four-file package passed 24 focused tests in 12.88 seconds without skips, and was tested in real Delphi and published to assets root and O:/winnt/system32 with matching SHA-256. Installation tests passed both widths at both locations. Original resource headers and provenance passed byte-exact verification. Search `rg -n 'combo_candidate|combo_passthrough|bind_verified_combo|vcl_combo_valid' src/ntw16s-dll` identifies admission, paint witness, control guard, font ownership and protocol paths; native, VB and unverified modes retain their previous paths. Physical keyboard/mouse, IME, other DPI and VCL versions, dropdown-list/simple/owner-draw/RTL variants, complex concurrent popup interactions and fault injection remain unverified. Eight early cycles showed variable GDI totals even for P113; no claim of zero leaks is made. Full integration remains pending. M0/T18/S64 remain open.
