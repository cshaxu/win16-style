# M0 T20 S12：真实扩展错误入口交接原型

## 做了什么

在**自有测试进程**启动时使用项目私有启动期 trampoline 挂接真实
`GetOpenFileNameA/W`、`ChooseColorA/W` 和 `CommDlgExtendedError` 入口；不是
系统全局hook，也没有修改产品。测试中的旧框hook按微软文档投递IDABORT；
仅在测试确认标记存在且原生调用结束后，把小缓冲所需长度和错误交接给测试
调用者。该固定长度80及确认标记是探针夹具，不是产品文件选择实现。

首轮初始化使用C静态函数指针，误挂到本程序导入跳板，实际API调用没有进入
钩子，四组均读到原生65535并失败；记录在本S历史，不计通过。修订版用
`GetProcAddress` 解析系统实际导出地址，并检查实际入口日志及真实调用结果。
双宽 A/W 共4组：同一线程连续读取12291，另一个线程的颜色对话框错误为1且
不改变原线程，后续同线程颜色框返回1，普通取消返回0，嵌套颜色错误后取消
在本机返回1；均与S11原生次序一致。该原型仅说明所测两个入口可协作，不证明
其他公共API已覆盖。

两个必要负例：故意改为进程全局伪错误时，第二线程清除状态导致主线程读回
65535而不是12291，断言确实检出。更关键的是，对未纳入原型的 `ChooseFont`
进行错误调用后，系统底层错误为1，而真实 `CommDlgExtendedError` 仍被伪错误
遮成12291；x86/x64 A/W四组均复现。这是明确的产品阻断缺口，不能把该原型
直接接入产品。测试中的 gap 模式以“观察到缺陷”为预期，退出0仅表示负例
成功复现，不表示该行为正确。

## 后续实施条件

必须覆盖项目接管及真实应用可能调用的其他公共对话框入口，验证同线程调用、
嵌套、并发、错误多次读取、取消、异常/卸载及未覆盖入口；还需处理系统
`CommDlgExtendedError` 的native调用顺序与LastError副作用。S10确认路径、目录、
编码及窗口生命周期等问题仍独立存在。原型通过不构成产品兼容声明；无法证明
覆盖的入口不能让伪错误泄漏。初版注入目标地址错误及故意全局状态负例均保留。

## S12 同批包验证

及治理门禁；`s12-shadow-focus` 28项通过、无跳过，约43秒：4项实际API交接
正例、4项全局状态负例、4项ChooseFont未覆盖缺陷见证、8项S11嵌套原生/注入
对照及8项必选基础回归。负例“通过”仅表示错误被成功检测，字体入口污染仍然
存在于**测试原型**，不表示已经支持。物理输入未测试。
