# run16s 手动全局样式模式

## 状态与用户决策

用户已准入手动 `run16s --global`：启动后接管新启动的传统 Win32 GUI 程序，并尽可能为已有进程及其已有窗口接入钩子和样式；已有程序作为与新程序并行的重要目标。UWP/XAML 不在本次范围。活动任务由 [CURRENT](../states/CURRENT.md) 管理。

用户选择复用 run16s.exe 承担全局管理，而非另增管理 EXE 或 Windows 服务。
用户最新要求：退出全局模式时优先尝试让所有已接管的程序恢复原样；若完整恢复不可行可接受，用户明确允许退出后有残影；S1 仍须实测并明确范围。早先“退出后保留样式”的方向由此更新。

## 目标与有限架构

- 保持三组件四产物、纯 C17 / MinGW GCC / Ninja / ccache。
- run16s.exe 保留原单应用启动、Console 子系统、等待/退出码、提权和错误体验；
  增加独立可选全局管理模式，候选命令为 `run16s --global`，最终 CLI 在准入时确定。
- 本次以显式 `--global` 启动和退出为入口；不增加登录自动启动。必要的状态、排除及退出协调按验证结果实施，不将托盘当作前置条件。
- x64 run16s 在当前用户桌面承载 x64 全局钩子；系统 x86 rundll32 承载
  ntw16s32.dll 专用宿主入口及消息循环。正常一个用户桌面两个后台进程，
  不是增加两个产品文件，也不是服务。宿主可行性尚待原型验证。
- 两个 DLL 继续拥有唯一 renderer；普通无载荷加载保持被动，通过独立、受控的
  全局接入入口初始化，不直接重跑启动期 bootstrap，不在 DllMain 中等待或操作 GUI。
- 固定可信安装目录和绝对 DLL 路径；不依赖复制到
  Windows 系统目录、AppInit_DLLs、关闭安全功能或兄弟仓库。

## 规则冲突与接入边界

[架构规则](../rules/ARCHITECTURE.md)已按用户明确请求允许显式全局模式使用受控当前桌面钩子；普通单应用模式原边界不变。双位宽宿主与初始化必须先以隔离原型实测。

目标覆盖当前用户桌面及权限允许的新建和已有传统 Win32 GUI 应用；可研究必要的现有窗口枚举和受控接入，但必须证明目标线程、进程身份、生命周期及失败安全。不使用低级键鼠钩子充当进程内加载机制。已有程序的已有窗口和后续新建窗口均需分别实测。现行架构规则仍禁止扫描接入既有进程，用户已明确授权本次变更；在采用该方式前须先以独立治理步骤协调规则，不把旧阶段约束误当作用户否决。
提权程序、多用户/桌面、受保护进程、AppContainer/UWP不自动计入支持面；
注入成功不等于任意自绘控件都能换肤。不修改全局主题、DPI或安全设置。

## 退出与所有权契约

正常退出时停止新接入，验证是否可让已接管窗口在其 GUI 线程恢复原来的样式、字体、菜单及资源，再撤销本模式全局钩子并回收自有宿主。若存在正在执行的回调或无法安全解除的项，必须保持模块及状态有效并报告，不能强制卸载或破坏目标。
退出后新开的独立程序不因该已结束会话自动接入；恢复失败而仍保持接入的进程及其后代行为须实际记录。
用户要求不按启动来源区分退出行为：全局模式运行期间，先由 `run16s <filename>` 启动再开启全局模式，或先开启全局模式再由 `run16s <filename>` 启动，都视为全局退出时的统一恢复目标。全局模式退出时，对两种顺序都尽力撤销样式及相关钩子、恢复程序原状；无法安全撤销时保留目标稳定、记录具体剩余状态，用户接受残影。普通 `run16s <filename>` 在没有全局模式参与时仍独立工作。
统一退出语义不排除实现内部去重、状态与资源所有权管理；这些机制只为防止重复安装、跨线程或卸载时破坏目标，不构成按启动来源保留样式的例外。窗口样式、进程钩子与后代传播能否分别撤销须分别实测，不可根据窗口恢复推定钩子已经移除。
重复启动、管理器崩溃、宿主失效、钩子卸载期间在途回调的生命周期分别验证，
不声称当前DLL已经具备这些保证。

## 架构设计（待原型验证）

```text
普通模式：run16s <filename> -> 创建目标 -> 对应位宽 ntw16s DLL -> 窗口和后代

手动模式：run16s --global (x64，管理与消息循环)
          ├─ 当前桌面 x64 全局钩子 -> 新建 x64 GUI 进程 -> ntw16s64.dll
          └─ 系统 x86 宿主（候选 rundll32） -> 当前桌面 x86 全局钩子
                                               -> 新建 x86 GUI 进程 -> ntw16s32.dll
```

- 保持三个组件四个产品文件；系统 x86 宿主可行性、退出控制和安全路径须由 S1 实证，不能因 DLL 被加载就认定已换肤。若系统宿主不可行，先给出具体证据及最小替代方案，不能悄悄增加第五产物。
- 仅 `--global` 创建管理会话和桌面钩子；普通 `run16s <filename>` 原调用、等待、错误与子孙传播路径保持不变，普通 DLL 无载荷加载仍被动。
- 启动时冻结会话身份与基准时间。回调以目标进程句柄及创建时间共同识别进程并区分已有/新建，防 PID 复用；不能因进程早于启动而自动拒绝。身份、权限或线程无法可靠确认时记录原因并保持原样。这里是目标资格过滤，并不能阻止 Windows 为分发全局钩子先把 DLL 加载到同桌面其他符合系统条件的进程；加载、激活和窗口附着必须分开处理。
- 现有 `ntw16s_hooks_begin/commit/abort` 明确只适用于刚创建、尚未交付的进程，失败路径甚至可能终止进程；不能在全局回调中直接重跑或对既有多线程进程直接打补丁。S1 比较可安全保持首个窗口的 GUI 线程回调、创建作用域与受控初始化方案，验证是否可覆盖线程及重入；真正可行机制确定后再实施。
- 目标 DLL 使用受保护、同用户同会话的控制信息，验证管理器身份、可信包目录和匹配 DLL 位宽。共享对象的命名、访问控制、防伪和竞态处理需要原型验证，不能依靠可预测名字或 PID 单独授权。初始化不在 `DllMain` 里等待、创建线程或操作 GUI。
- 已有进程是明确研究目标：对比系统全局钩子自然回调、受控窗口枚举及唤醒、必要时的其他接入方式；在自有隔离进程中验证已有 HWND、已有子控件及后续新窗口，支持成熟可靠的情况。不能把获取模块句柄、注入成功或进程存在等同完整换肤；不能调用仅适用于启动期的危险事务。
- 退出时先阻止新接入，在各目标 GUI 线程尝试可逆卸载和恢复，再撤销两种位宽钩子并回收自有宿主；无法安全卸载的目标须继续持有足够引用并报告。退出恢复是优先目标而非不论代价的硬要求，不能为恢复杀死或破坏用户进程。
- 相同用户同桌面、普通权限的传统 Win32 GUI 是首个覆盖边界；受保护/提权进程、其他会话或桌面、共享系统宿主和 UWP/XAML 不承诺。对于系统钩子会先加载 DLL 的共享宿主，回调必须在采取任何接管动作前识别并排除；Windows 加载行为本身不是扫描注入。
- 正常停止、宿主意外退出、控制器崩溃及重复启动均应有明确的句柄、钩子和模块释放策略；钩子回调始终继续正常调用链。全局入口的操作反馈、可取消方式和冲突错误以原型结果确定，不引入登录自启。

## 实施顺序与 S 任务队列

S1 隔离可行性验证已完成，T21 保持开放；其余为本 T 的顺序规划，正式准入前不作为已分配或已完成的编号。每个 S 使用独立证据，先通过相应验收再进入下一个。

1. **S1：架构与隔离可行性。** 完成本文设计，然后在私有桌面用自有进程验证 x86/x64 双钩子、系统 x86 宿主、生命周期、加载/回调、首窗创建时机、现有/新窗口接入及退出后恢复能力；明确失败和无法覆盖面。不得将探索原型直接当作产品发布。
2. **S2：产品接入与受控初始化。** 在既有两个 DLL 中实现经 S1 证明的安全路径，新程序及已运行程序的身份筛选、状态绑定、去重、各 GUI 线程和经验证的已有窗口 renderer 附着；普通启动保持独立。
3. **S3：退出、异常和传播。** 管理两位宽宿主、控制器退出/崩溃、在途回调及模块引用；验证已接入窗口在停止全局模式后的恢复、失败回退和后代行为。安全方案不足时准确保留限制，不称全部完成。
4. **S4：命令入口和真实应用。** `run16s --global` 的启动、状态、停止、错误与重复启动；真实 32/64 位新程序、已运行自有实例及常用控件对照。此阶段不增加登录自启或 UWP/XAML。
5. **S5：任务级验收与收口。** 整理入口及权限矩阵、双宽实际包、单程序回归、异常和资源证据，审计未覆盖项，按用户要求交付与收口。

每个产品 S 按仓库规则双宽干净构建、同批四文件实际包测试；有二进制改动时发布至 assets 根和 O:/winnt，核对 SHA、提交推送并复核远端。研究 S 的可观测原型与正式产品必须分开记录。

## 验证及退出条件

原生纯C探针自行驱动，不用computer-use，不把整套测试交给用户。分别证明DLL加载、
传播初始化、窗口钩子初始化、HWND附着及正常显示后的实际绘制；记录PID/位宽/
映像路径、DLL绝对路径/SHA、创建关系和错误码。覆盖x86/x64、可行的传播组合、
多UI线程、去重、排除、DPI、标题/字体/菜单/滚动条保留、输入语义及资源生命周期。
以原包/禁用模式作负例；明确失败、跳过与未覆盖面。

退出测试必须检查：新独立目标停止自动接入；此前接入的程序及窗口是否恢复原样、继续可用；对未恢复情形记录范围及原因；全局宿主资源退出及目标正常关闭；单应用模式不受影响。
额外覆盖两种混合顺序：先全局后 `run16s <filename>`、先 `run16s <filename>` 后全局；两种顺序退出全局模式均尝试同等恢复，分别观察已存在窗口、进程钩子、新建子窗口及之后创建子进程的实际状态，并明确无法恢复的边界。上述混合场景尚未实现或验证。
原图形资源及来源声明逐字节保留；无新renderer、第五个产品文件或外部必需后端。
每个产品S按[执行规范](../rules/EXECUTION.md)完成干净双宽构建、同批四文件实际包
测试；binary change后发布到assets根目录及O:/winnt，核对摘要、提交推送
并取回实际远端复核。未验证的权限/桌面/框架覆盖不承诺通用支持。

接口依据：[SetWindowsHookEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw)、
[rundll32](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/rundll32)。
