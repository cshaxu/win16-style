# run16s 登录全局样式模式

## 状态与用户决策

M0 下未编号的 T 候选，具体顺序由 [QUEUE](../states/QUEUE.md) 管理；只登记 proposal，
不准入实施、不分配 T/S/P，不覆盖 [CURRENT](../states/CURRENT.md) 的活动包。
依据本次讨论及用户“加入队列首位T任务proposal”；未来准入须另行明确。

用户选择复用 run16s.exe 承担全局管理，而非另增管理 EXE 或 Windows 服务。
用户明确选择：退出全局 run16s 后，已经接入的应用继续保持样式，直到应用退出；
其 DLL 后代传播继续有效。退出只停止全局自动接入，不承诺撤销已有样式。

## 目标与有限架构

- 保持三组件四产物、纯 C17 / MinGW GCC / Ninja / ccache。
- run16s.exe 保留原单应用启动、Console 子系统、等待/退出码、提权和错误体验；
  增加独立可选全局管理模式，候选命令为 `run16s --global`，最终 CLI 在准入时确定。
- 全局模式提供托盘、启用状态、应用排除、诊断、登录自动启动开关及退出协调。
  自动启动须用户主动启用，可撤销；无控制台登录启动及无闪现程度必须实测。
- x64 run16s 在当前用户桌面承载 x64 全局钩子；系统 x86 rundll32 承载
  ntw16s32.dll 专用宿主入口及消息循环。正常一个用户桌面两个后台进程，
  不是增加两个产品文件，也不是服务。宿主可行性尚待原型验证。
- 两个 DLL 继续拥有唯一 renderer；普通无载荷加载保持被动，通过独立、受控的
  全局接入入口初始化，不直接重跑启动期 bootstrap，不在 DllMain 中等待或操作 GUI。
- 固定可信安装目录和绝对 DLL 路径，登记明确的登录启动命令；不依赖复制到
  Windows 系统目录、AppInit_DLLs、关闭安全功能或兄弟仓库。

## 规则冲突与接入边界

当前[架构规则](../rules/ARCHITECTURE.md)只允许本次启动树的新建目标并禁止全局
hook，[架构设计](../design/ARCHITECTURE.md)也不赋予启动器驻留职责。
本候选明确提出可选模式的例外；排队不等于现行规则已修改。正式实施前须通过
明确授权的治理修订协调规则、设计、UI及ABI契约，原单应用模式边界保留。

初版优先覆盖启用后新建的、当前用户桌面及权限允许的传统 Win32 GUI 应用；
对排除目标不接入，不扫描注入既有进程，不接管共享系统宿主，不使用低级键鼠钩子
充当进程内加载机制。已有程序新建窗口的回调资格必须实测并明确过滤策略。
提权程序、多用户/桌面、受保护进程、AppContainer/UWP不自动计入支持面；
注入成功不等于任意自绘控件都能换肤。不修改全局主题、DPI或安全设置。

## 退出与所有权契约

正常退出时停止新接入、撤销本模式全局钩子并回收自己创建的x86宿主。
已接入进程中的DLL不强制卸载，继续负责renderer及后代传播，不能因宿主退出
丢失必要路径/策略或引用；不要求注销，也不自动恢复字体、主题或窗口样式。
退出后新开的独立程序不因该已结束会话自动接入；已有样式进程的后代仍可能接入。
显式run16s启动和全局接入须去重，排除策略与后代传播的优先级须在原型阶段明确。
重复启动、管理器崩溃、宿主失效、钩子卸载期间在途回调的生命周期分别验证，
不声称当前DLL已经具备这些保证。

## 候选 S 分解

以下是阶段顺序，不预分配 S 编号；正式准入后按实际下一编号分配，可据证据拆分。

1. 治理边界协调与双宽原型：审核导出/ABI、桌面钩子种类、受控初始化、
   目标过滤、GUI线程调度和宿主生命周期；先给出实际支持/失败证据。
2. 全局接入与传播：完成去重、载荷/策略、模块路径身份、有限新窗口接入、
   停止接入并保留现有样式/传播，以及崩溃和重复启动处理。
3. 用户入口：托盘、排除、诊断和可撤销登录启动；验证隐藏启动与原CLI完整保留。
4. 全任务覆盖审计：冻结支持矩阵，实际安装包、截图、运行/退出/重新登录证据，
   完成部署与远端复核后收口，不用原型成功代替任务完成。

## 验证及退出条件

原生纯C探针自行驱动，不用computer-use，不把整套测试交给用户。分别证明DLL加载、
传播初始化、窗口钩子初始化、HWND附着及正常显示后的实际绘制；记录PID/位宽/
映像路径、DLL绝对路径/SHA、创建关系和错误码。覆盖x86/x64、可行的传播组合、
多UI线程、去重、排除、DPI、标题/字体/菜单/滚动条保留、输入语义及资源生命周期。
以原包/禁用模式作负例；明确失败、跳过与未覆盖面。

退出测试必须证明：新独立目标停止自动接入、已有窗口继续可用且样式保持、
已有目标继续创建样式后代、全局宿主资源退出及目标正常关闭；单应用模式不受影响。
原图形资源及来源声明逐字节保留；无新renderer、第五个产品文件或外部必需后端。
每个产品S按[执行规范](../rules/EXECUTION.md)完成干净双宽构建、同批四文件实际包
测试；binary change后发布到assets根目录及O:/winnt/system32，核对摘要、提交推送
并取回实际远端复核。未验证的权限/桌面/框架覆盖不承诺通用支持。

接口依据：[SetWindowsHookEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowshookexw)、
[rundll32](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/rundll32)。
官方机制依据不能替代本项目双宽宿主与初始化原型证据。
