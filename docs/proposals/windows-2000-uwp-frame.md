# Windows 2000 现代窗口外框

以已经验证的 [Win3.x UWP 外框](../history/M0-T22-closure.md)和
[Win2000 普通外框](../proposals/windows-2000-classic.md)为基线。
首批真实目标沿用 ApplicationFrameHost/CoreWindow 模型，以系统计算器为主，
本机可用时用 Scan 验证第二种应用。保留应用内容、原生布局和既有标题动作。
WinUI 混合窗口由 S2 单独准入。UWP 与 WinUI 客户区保持应用原样。

## 复用边界

- 公共 application/adapters 的 frame、host、surface 和 input 提供所有权、
  图层裁剪、跟随刷新、输入及移除。
- Win2000 window 提供活动与非活动渐变、Tahoma 标题、边框、标题按钮及
  系统菜单。普通窗口和 UWP 共用经典绘制原语。
- 沿用公共运行时和全局层的 UWP 目标验证及生命周期。产品选择年代和入口。
- 标题内容、按钮和命中区共享一次几何计算，资源沿用现有风格。
- UWP 的启动和托盘入口共用一个宿主 DLL，宿主根据请求选择绘制器。
  这样同一个 HWND 的外框仍由一个公共实例持有。移除按所选风格核对，
  避免旧风格的停止请求清掉已经切换的新外框。

## S 顺序与验收

| S | 工作 | 独立证据 |
| --- | --- | --- |
| S1 | UWP 外框、正常启动和真实托盘 | 双宽模型、真实计算器和 Scan 的启动与切换已取证。关闭按钮的混合 DPI 屏幕差异和后续源码的同包正式交付仍待验证 |
| S2 | WinUI 桌面外框 | 按下节验证真实目标、交互与恢复，并同批复验 S1 的待交付范围 |

开发阶段用增量构建，按可交付批次合并验证。
真实宿主与原生模型分别取证，正式发行按同批八文件先发布后测试的规则执行。

开发和环境对照见 [S1 记录](../history/M0-T28-S1-uwp-frame.md)。

## WinUI 桌面外框

从 [T23 的现代桌面窗口识别](modern-desktop-window-style.md)入手，先用
自有 Notepad 启动区分启动进程和实际 WinUI 顶层 HWND。检查已有 Win2000
接入是否走原生 Win32 非客户区路径，以及自绘标题区何时需要公共现代宿主。
仅满足现有身份、进程来源和会话条件的窗口才接入。

- WinUI 适配器持有标题区域、应用标签和菜单的边界，以及窗口状态、重绘、
  命中和移除。Win2000 标题、边框和按钮使用已有共用度量和 painter。
- 三种窗口的标题按钮均按最终矩形直接栅格化，沿用 Win32 参考路径。
  96、144、192 DPI 的按钮颜色和字形与对应尺寸的参考像素核对。
- 对客户区延伸至窗口顶部的桌面 XAML 窗口，预留标题行，应用仍布局自己的
  标签与菜单。取消样式时保留当前窗口外矩形，由应用重新计算原生客户区。
- 在普通和最大化状态验证标题、按钮命中和客户区保持。检查缩放及导航
  重绘不会覆盖经典外框，停用后恢复窗口几何和原生交互。
- 若能启动独立 Explorer 文件夹窗口，则交叉验证导航和菜单；共享 Shell
  或现有用户窗口不作为探针对象。Task Manager 权限、Terminal 自绘按钮
  等旧债务仅按本次实证报告。
- 回归已有 Win32 和 UWP 的 Win2000 及默认 Win16 路径，完成同快照交付、
  摘要复核和远端检查后再收口。
