## 任务边界与完成条件

| 项 | 工作包 |
| --- | --- |
| 责任/前置 | ntw16s-dll；依赖 “来源冻结与独立化设计”任务完成来源、资源、ABI、初始化方案 |
| 范围 | 导入已处置的唯一 renderer 及必要资源；建立本地 CMake/Ninja 双架构图、明确源码列表、私有头和导出边界；保留固定来源原资源；T6 S2用户要求覆盖历史替代方案 |
| 交付 | ntw16s32.dll、ntw16s64.dll 构建能力和匹配测试；无 run16/WOW/服务链接依赖；单一几何/绘制/字体实现 |
| 聚焦验收 | 使用真实 DLL 的双位宽 fixture：ABI/导出、同线程安装/移除、错误线程拒绝、创建作用域、销毁与重入、字体/GDI/DLL 引用释放 |
| 回归/退出 | 对 “来源冻结与独立化设计”任务冻结支持面复验 frame、menu、button/static/edit/list/combo/scroll 的绘制、原生状态及通知；记录差异与失败，不把历史 pass 数当证据 |
| 停止条件 | ABI 不一致、资源处置未落实、出现第二 renderer 或源仓库依赖时，先修复当前任务 |

fixture 可显式调用 API；这只证明 DLL 核心，尚不证明自动注入。当前不发布整个
产品包，也不声称 run16s/透明应用集成已完成。生成的 DLL 留在 build/。

- S1：本地双架构构建与已审源码/资源导入
- S2：真实 DLL 附着、外观与线程/资源生命周期复验

全部 S 的实际提交、相关回归、未解决项接收者与退出条件，不能由单个 S 替代。
