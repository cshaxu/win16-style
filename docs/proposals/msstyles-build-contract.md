# T29 S2 主题源、构建产物与运行时契约

## 构建交付

每种风格有一套可编辑主题源。一次构建至少各生成一份 `.msstyles` 和一份 `.theme`，并提供描述中实际引用的资源。标准视觉属性、项目扩展与描述索引均从同一个主题源生成，避免两份手填配置分叉。x86 和 x64 消费相同主题字节。

| 产物 | 合规门槛 |
| --- | --- |
| `Win16.msstyles`、`Win2K.msstyles` | 生成真实的 MSStyles PE 资源容器。首批以已实测的版本 4 容器为目标。独立解析器读取指定类、部件、状态、度量、图像和变体。原始栅格及来源声明随包核对。 |
| `Win16.theme`、`Win2K.theme` | 按 Windows 的主题描述语法生成，包含显示名称及 VisualStyles 的 Path、ColorStyle、Size。Path 指向同目录的 `.msstyles`，配色及尺寸必须能在目标文件中找到。发布配置不得引用额外文件或构建目录。 |

用户确认正式包共七个文件。包根目录提供 `run16s.exe`、`ntwshk32.dll` 和
`ntwshk64.dll`，在启动器的直接子目录 `Win16` 与 `Win2K` 下各提供一对主题。
普通启动必须先写主题目录名，再写程序。`--global` 单独调用时进入托盘并扫描可用主题。
双位宽运行时装配归 `ntwshk`。演示程序留在构建树用于验收。

标准格式验证与系统加载测试分别记录。发布的目标是格式和引用合规，同时由项目运行时只读消费数据。Windows 系统主题的签名、安装和全桌面应用属于另外的能力；本任务的样本验证不修改系统主题、注册表、系统文件或安全策略。[Microsoft Theme File Format](https://learn.microsoft.com/en-us/windows/win32/controls/themesfileformat-overview)

## 编译、互操作及回归判据

1. 同源重复构建比较 SHA-256；同时从两份分别暂存的完整产物验证副本不会引用构建目录。Windows 兼容路径以实际部署配置测试，项目自己的相对路径解析不得冒充 Windows 路径兼容。
2. 用独立方式读取标准记录并对比预期属性值及图像摘要。再用项目读取器验证扩展的版本、边界和语义。验证标准视图在忽略扩展时依然完整可读。S3 记录独立解析器的精确版本和验证范围。拒绝截断、越界、未知必需版本、断链和无效变体。
3. S4 将两种主题的标题栏、按钮和滚动条接到实际布局、绘制与命中验证。格式正确与经典像素对等分别验收。
4. S11 用只含上述七件的独立目录验收，并切换包门禁、发布器和回滚记录。必须证明两种主体风格和双位宽共用 `ntwshk`，普通、运行中和全局生产入口都能从该目录读到外部主题。验收前运行包沿用最近验证的基线，四个主题文件可独立预览。

## 扩展版本、默认值与资源所有权

首批以 v4 标准记录提供配色、字体描述、图像、部件、状态和度量。两种风格从单源构建，并把只读主题模型作为共享 renderer 与宿主适配的接口。持久数据为标准 PE 资源，以及可选命名 RCDATA `CLASSIC_STYLE`。资源标记 `CSTY` 后依次为小端 u16 主版本、u16 次版本、u32 总字节长、u32 记录数。记录头依次为 u16 类型、u16 标志、u32 负载长度。标志第 0 位为必需，剩余位保留。v1.0 读者拒绝未知主版本、未知必需类型、越界、组合字段矛盾、重复唯一记录。匹配主版本且后续次版本增加未知可选记录时按长度跳过。出错时保持已应用主题，报告失败；没有已应用主题时保持系统外观。

八类记录按表顺序取稳定类型 1–8。尺寸显式标注坐标域，窗口和控件度量使用 96 DPI 逻辑像素，对话框模板使用 DLU。引用资源使用文件内的类型／名字或 ID，无进程句柄及宿主绝对路径。固定主题资源由验证成功的只读主题模型持有；渲染快照持有模型引用，替换时先验证新模型，旧模型等最后使用者退场后释放。窗口、GDI 和 COM 对象继续由各运行时所有者释放。基本状态缺值仅使用标准继承及声明的默认变体。缺少候选必需部件或扩展时，该候选不能提交应用；缺失可选装饰使用已定义的角色默认值。

类型 1 标题按钮组的负载依次是 u16 槽位数、u16 左边距、u16 右边距和 u16 布局位。1.27 及更早的布局位保留零。1.28 使用位 0 声明显式布局，位 1 允许窄标题栏裁切右侧按钮，位 2 让按钮填满标题栏高度。零保留旧主题的适配器默认行为。每个槽位使用 u8 角色、u8 边侧、u16 前置间隔；槽位按从左到右排列，左侧槽位先于右侧槽位。边侧 0 为左、1 为右，角色 1–5 依次为窗体菜单、最小化、最大化或还原、帮助、关闭。同一组内角色唯一。运行时根据窗口能力选取槽位，按坐标域换算度量。

类型 3 滚动度量从 v1.1 起可选，负载为 u16 尺寸来源和 u16 尺寸。来源 1
取实际滚动条横截面，来源 2 取当前 DPI 的系统端钮长度，两者的尺寸字段均为零。
来源 3 的非零尺寸按 96 DPI 逻辑像素指定端钮标称长度。现有 Win16
和 Win2K 布局以该标称值计算短条压缩和滑块长度，绘制与命中共用结果。
缺少此记录时沿用该风格的传统布局来源。主机仍决定控件的实际宽高。

类型 7 Win16 弹出菜单列度量从 v1.2 起可选。负载为四个 u16，依次表示勾选列、
快捷键间距、子菜单箭头列和无箭头菜单的尾部留白，单位均为 96 DPI 逻辑像素。
缺失时沿用 18、8、12、4。文字列宽由当前字体和菜单内容决定，测量和绘制使用
同一组度量。Win2K 继续使用原生菜单布局。

类型 8 公共对话框度量从 v1.3 起可选。负载为 18 个 u16。
前四项是紧凑文件对话框和完整 Places 所需工作区的宽、高。接下来两项
是 Places 客户区的 DLU 宽高，再后两项是右侧间隙与底部留白。
接下来三项是打印 General 的完整页最小工作区宽度、普通完整页和大页的
最小高度。工作区门槛、间隙和留白采用 96 DPI 逻辑像素。
最后七项采用 DLU，依次为展开色板的宽高、查找的宽度及其原生与经典高度、
带调用方钩子的 stock 字体对话框宽高。
两份随包主题均带 RT_DIALOG 201–203 的三份 General 模板及原有语言。
运行时从当前主题读取文件、标准对话框的度量及打印页模板，首先读取线程作用域，
其次是活动全局会话，再读取启动主题。当前主题缺少打印模板时，沿现有打印桥接
和原生 API 回退。已有窗口尺寸、参数资格和打印控制流由运行时负责。

两种主题均需要的历史数据落在类型 1–5，菜单度量使用 7，公共对话框度量
使用 8。当前 Win16 菜单用标准 `TMT_MENUFONT` 描述宿主 System 采样字体，
在运行时建立进程私有栅格及 advance。类型 6 仍为保留号。项目状态选择、
命中、系统回退和 API 转接仍由共享运行时执行。

## S14 公共对话框策略

生成器在 CLASSIC_STYLE 1.4 写入必需的类型 9 记录，负载为四个字节。
按顺序定义窗口布局适配器、文件打开／保存、目录、打印／页面设置。
运行时按字段解释固定编码，四个字段能独立配置。

| 字段 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| 窗口布局适配器 | 保留 | 整体客户布局 | 原生客户矩形与非客户区绘制 |
| 文件 | 原生 API | 旧式文件布局 | Explorer 文件布局 |
| 目录 | 原生 API | 旧式目录树 | COM 使用原生目录窗口并观察初始化，Shell A/W 保留原生调用 |
| 打印与页面设置 | 原生 API | 兼容打印桥接 | 通用打印属性页与页面设置观察 |

本次迁移保留原记录编号、版本和字节编码。随包默认值定义在
`tools/theme/classic_source.h`。

运行时加载主题目录时要求记录 9。缺失时拒绝该主题。记录中的文件、目录和
打印字段为 0 时使用原生 API。配置不能提供函数名、模块名或代码。调用方参数
校验、回调、结果回写和失败行为继续由共用运行时实现。原生策略直接调用
原 API，普通窗口级样式仍按全局或启动时的外观选择执行。目录策略在 COM
Show 时按 FOS_PICKFOLDERS 分派，Shell A/W 对 Win2000 保留现有调用语义。

## S22 标准对话框路线

CLASSIC_STYLE 1.18 的可选记录 21 含三个字节，依次控制颜色、字体和查找／
替换对话框。每个字段独立选择。0 为缺省，1 为原生 API，2 为保留

## S17 外框呈现

CLASSIC_STYLE 1.7 的可选记录 10 依次声明标题文字对齐、分隔线位置、按钮图形来源和索引图外轮廓。
两字节旧记录只提供前两项。缺省对齐为左对齐、过长省略，缺省不绘制分隔线。
图形来源可选索引图或系统标题字形，未声明来源时按图像引用可用性选择，颜色取主题边框角色。
标题按钮及菜单栏 MDI 按钮共用这个声明。
索引图可声明一圈边框色描边。位图由 MSStyles `Window` 部件状态的 `ImageFile` 属性引用。
`SYSTEM` 角色的图形取菜单按钮索引图，窗口仍提供真实系统菜单。宿主继续负责按钮是否可用、
命中坐标和命令派发。随包主题的普通、按下及 MDI 子窗按钮图由主题资源提供。
索引图不可用时，标题栏使用系统应用图标或对应的系统标题按钮字形。
完整客户区适配只为主题声明的角色布局槽位。内部无主题调用使用系统标题度量，
不生成额外的标题按钮槽位；外部主题格式要求提供按钮组。非客户区适配使用
主题的标题高度与按钮尺寸。内部无主题调用保留 Win32 系统标题按钮矩形，
现代合成外框使用当前系统度量布局靠右的窗口按钮。

CLASSIC_STYLE 1.21 的可选记录 24 有一个字节，值 1 隐藏应用图标，
值 2 使用原生应用图标。主题声明的系统菜单按钮优先。窗口必须支持
系统菜单，工具窗口不显示应用图标。两种窗口布局省略记录时均显示原生应用图标。

CLASSIC_STYLE 1.22 的可选记录 25 声明复选框、单选框缺少索引图时的字形。
记录含一个字节，值 1 使用系统 Marlett 符号绘制。省略记录时使用原生
DrawFrameControl。有效索引图优先，两个窗口布局都使用相同的选择规则。

CLASSIC_STYLE 1.23 的可选记录 26 定义选择控件的字形宽高、标签间距及布局标志，
共四字节，宽高为 1 至 64，间距为 0 至 64。标志位 1 按 DPI 换算度量，
位 2 使用当前字体半个「0」的宽度作为间距并要求间距字段为零，
位 4 响应控件原生顶部和底部对齐。省略记录时使用 Windows
系统字形尺寸与字体间距。两种布局共用同一份算法。

CLASSIC_STYLE 1.24 的可选记录 27 定义索引 UpDown 按钮的描边、内边距和取样裁切，
共三个字节。描边与内边距以 DPI 换算后的像素为单位，范围 0 至 4；
裁切从箭头位图每侧去掉 0 至 8 个源像素。省略记录时直接绘制完整索引图。
系统符号和原生调色的 UpDown 路径不读取此几何记录。

CLASSIC_STYLE 1.25 的可选记录 28 选择 UpDown 的绘制路径。值 1 从
控件的箭头绘制回调应用主题字形，值 2 保留控件自己画的轮廓和状态并
替换颜色。省略记录时保留原生控件。调色在完整客户区和非客户区布局均可
使用，箭头回调当前由完整客户区适配器提供。

CLASSIC_STYLE 1.8 的可选记录 11 在原十字节的边框呈现后追加七字节几何声明。
顺序为缩放方式、可调整大小窗边宽、固定窗边宽、对话框边宽、单线边宽、标题栏
最低高度和标题下方保留线的单位数。缩放方式为 96 DPI 逻辑单位或固定屏幕像素。
最低高度使用目标坐标像素，保留线允许 0 或 1 个按 DPI 换算的绘制单位。

## S19 弹出菜单文字呈现

CLASSIC_STYLE 1.9 使用可选记录 12，负载为小端 u16。第 15 位表示显式配置。
第 0 位选择禁用文字的点阵效果，第 1 位选择快捷键右对齐，第 2 位选择弹出菜单
默认项加粗，第 3 位选择菜单栏标签居中，第 4 位选择原生系统命令的小图形。
其余位保留。该记录须与八字节的菜单列距
记录 7 同时存在。省略记录 12 时，两种布局均采用快捷键右对齐、默认项加粗、
显示系统命令小图形，禁用文字保留普通灰色。省略记录 7 时，两种布局均取原生
菜单标记宽度作为左右预留列宽，列间无额外间距。旧解析器可按长度跳过记录 12。
Windows 原生仍拥有菜单项、命令、状态和跟踪。

CLASSIC_STYLE 1.26 的可选记录 29 以两个字节声明自测量菜单行的最低文字高度
和单侧垂直留白，均为 96 DPI 逻辑单位。高度范围为 1 至 64，留白为 0 至 16。
测量时取主题最低高度与实际字体高度的较大者，再加上下留白。适用于完整客户区
适配的菜单栏及自测量弹出项。省略时使用系统菜单高度，并至少容纳实际字体；
由 Windows 排版的菜单保留原生行矩形。

发行门禁从 Win16.msstyles 直接读取 IMAGE 和 RCDATA，逐像素核对 24 张
索引图及 13 份箭头掩码。原图头文件与来源声明继续按字节校验。
两宽运行 DLL 保留来源声明，门禁要求 DLL 不包含这 18 张原始绘制表。
同快照构建门禁用编译器配套的符号读取器检查两宽运行 DLL。读取器必须
找到正式主题解析入口，且不得发现旧内置主题加载、预设补全或旧标题栏
兼容实现的符号。该检查补充 PE 资源、导入导出和调用闭包审计。

`product-contract.json` 的 `standalone_only_exports` 记录只供独立兼容 DLL
使用的入口，验包拒绝它们进入正式运行时。正式导出直接在 `ntwshk.def` 声明。
构建只补充位宽对应的调用约定和辅助序号。实际窗口和控件由运行时读取当前主题后
调用共享绘制器。

CLASSIC_STYLE 1.32 的可选记录 34 在声明了外框几何时允许滚动条共用外框内沿。负载是一个值为 1 的字节，单位与标题分隔线相同。完整客户区适配仅在普通可调整且使用右侧滚动条的外框上应用。省略记录时为滚动条保留完整宽度。

CLASSIC_STYLE 1.31 的可选记录 33 在菜单度量存在时声明自绘 MDI 合并按钮的禁用态显示。一个字节沿用类型 22 的角色掩码和显式位。未声明时传递全部原生禁用态。

CLASSIC_STYLE 1.30 的可选记录 32 在类型 3 存在时声明滚动条拖拽容差。三个字节依次为坐标来源及两个距离。来源 1 用 96 DPI 逻辑像素声明 X/Y，来源 2 用条宽和系统滑块度量声明横向／沿轴倍数。省略时使用系统拖拽容差。

CLASSIC_STYLE 1.29 的可选记录 31 在类型 3 存在时用两个小端 u16 声明滚动条首发延迟与重复间隔，以毫秒计，两者均大于零。省略时使用宿主调节的重复速度。

CLASSIC_STYLE 1.27 的可选记录 30 含一个字节。值 1 至 48 指定完整客户区
适配的控件采样宿主 System 字形时所用的点数，保持应用字体的字宽与行高。
随包 Win16 主题声明 12 点。标准控件、
工具栏、状态栏、静态文字和已支持的 VB/VCL 文本路由读取同一选择。
省略记录时保留应用字体。位图字体租约在原行为可用的范围内生效。
标题、菜单和日历字体继续使用各自的主题字段。

## S23 下拉箭头

可选 RCDATA `CLASSIC_COMBO_ARROW` 的头为三个 ASCII 字节 `CAR` 和版本 1。
随后每行一个位掩码，共九字节。位 0 至 6 从左到右选择笔画像素，位 7 保留。
组合框、日期选择器、VCL 内嵌组合框在各自原生按钮矩形内复用该位图。
缺少资源时使用简化下拉字形。Win16 主题提供原始栅格。

## S23 菜单栏横向留白

CLASSIC_STYLE 1.19 的可选记录 22 声明菜单栏呈现。第一个字节为
96 DPI 下每侧的逻辑像素，有效范围 1 至 64，0 使用 Windows 菜单字体度量。
测量时对总宽缩放，绘制时分别对每侧缩放。可选第二字节的高位表示显式声明，
低四位依次选择 MDI 系统、还原、最小化及关闭按钮。省略该字节或取 0 时，
使用 Windows 提供的全部合并按钮。单独设置高位时隐藏这四种按钮。其他位保留。

记录独立于弹出菜单列距及文字呈现。Win3.x 随包主题声明留白 6 及系统、
还原按钮。Windows 2000 仍使用原生菜单栏矩形。运行时保留菜单项的命令、
原始索引及灰化状态。旧运行时可跳过记录 22，旧主题可继续加载。

## S20 静态控件分隔线

CLASSIC_STYLE 1.10 的可选记录 13 负载为一个字节。值 1 使用随窗口 DPI

高光和阴影边，矩形分隔线追加反向内边。颜色沿用主题的静态边框色。
省略记录时沿用适配器已有的兼容呈现。解析器拒绝重复记录及未知值。

## S20 滑块几何

CLASSIC_STYLE 1.11 的可选记录 14 负载为一个字节。值 1 使用固定滑块和
共享边沿，值 2 使用按页大小计算的滑块。记录 3 仍独立确定端钮和滑块的

## S20 按钮边框

CLASSIC_STYLE 1.12 的可选记录 15 负载为一个字节。值 1 选择阶梯边框和

## S20 分组框与编辑框边缘

CLASSIC_STYLE 1.13 的可选记录 16 有两个字节，依次声明分组框与标准编辑框。

CLASSIC_STYLE 1.20 的可选记录 23 有一个字节，值 1 选择平边，值 2

## S20 滚动条端钮资源

可选 RCDATA `CLASSIC_SCROLL_ARROWS` 的头为三个 ASCII 字节 `SAR`、版本
字节 1 和一个呈现方式字节。方式 1 后面是 12 张 17×17 的索引图，状态顺序
为正常、按下、禁用，每种状态按上、下、左、右排列。像素从左至右、从上至下，

## S21 进度条几何

CLASSIC_STYLE 1.14 的可选记录 17 有六个字节，依次为标志、内缩、末端留白、
块间距、块长分子和分母。标志位 0 表示记录有效，位 1 使内缩、留白和间距
随 DPI 缩放，位 2 绘制外边线，位 3 四舍五入填充长度，位 4 将已开始的末块

## S21 工具栏、状态栏与 Rebar

## S23 日历文字采样

## S23 主题目录标识

正式主题查找只接受当前目录标识。UWP 请求须携带目录标识，窗口布局由该目录
的主题声明提供。直接窗口线程入口同样读取该目录的布局，并与全局窗口入口
共用切换和恢复机制。按目录名启动和托盘扫描使用各目录自己的标识。复制或改名后
可继续用新的目录名选择主题。

独立兼容装配可通过 `[Theme]` 中的 `CompatibilityFolder` 解析旧数字入口。
该值须与实际目录匹配，主题声明的窗口布局须符合旧请求，重复匹配会被拒绝。
该兼容字段可省略。
