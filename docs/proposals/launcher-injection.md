# 启动器与首次自动附着

状态：用户授权准入 M0 T3；活动 S 与基线以 CURRENT 为准。固定 M0；[前置任务](style-core.md)须交付并关闭。
共同来源与验收矩阵见[导入总览](native-style-import.md)，顺序见[QUEUE](../states/QUEUE.md)。

## 任务边界与完成条件

| 项 | 工作包 |
| --- | --- |
| 责任/前置 | run16s-exe 与 ntw16s-dll 的私有注入/窗口拦截边界；依赖 “双位宽样式核心”任务的双位宽 DLL 通过 |
| 范围 | x64 CLI 解析和目标选择、实际目标位宽识别、可信包目录定位、挂起创建/注入/恢复；DLL 有界引导与 loader-lock 外初始化、窗口创建自动附着 |
| 必须明确 | CLI 引用/Unicode/参数透传、是否支持 wait 及其退出码、缺参/不支持目标的诊断；不能保留 run16 的服务/DOS 路由或要求用户输入 --win16-style-all |
| 交付 | x64 run16s.exe；复用 DLL 所有的唯一注入实现；最小版本化载荷与必要导出；无需样式 API 的原生 x86/x64 测试目标 |
| 聚焦验收 | x64 启动器分别注入 x86/x64，验证实际同位宽 DLL 与窗口附着；初始及后续 GUI 线程窗口、动态控件均走相同外观实现 |
| 失败验收 | 缺失/错误位宽 DLL、损坏/不支持目标、权限失败及可控安装故障，证明非零状态、原始错误诊断、拥有句柄清理和未放行半安装目标 |
| 回归/退出 | “双位宽样式核心”任务的双位宽核心重跑；目标无样式链接/调用仍成功附着；无第五产品，helper（如选用）的超时/退出/清理证据齐全 |
| 停止条件 | 引导需要 loader-lock 内禁止操作、目标在就绪前已执行、目标位宽误判或失败目标被恢复时，不能转子孙传播任务 |

本任务负责首次目标自动附着，包括原窗口 API trampoline 绑定；后代拦截及其
创建语义由后续任务实现。不用“模块已加载”代替“窗口实际附着”的证明。

## 本 T 的候选 S 划分

- S1：x64 CLI、目标识别与唯一注入事务
- S2：DLL 引导及窗口自动附着、双位宽目标验证
- S3：失败回滚、核心回归与本任务审计

这些 S 只属于本 T，准入后从本 T 的 S1 开始；其他 T 各自重新从 S1 开始。
每个 S 的 P 为完整验证交付，不预分配 P 数量。T 关闭前须逐项对照本任务目标、
全部 S 的实际提交、相关回归、未解决项接收者与退出条件，不能由单个 S 替代。
