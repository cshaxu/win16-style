# Windows 2000 经典风格：调研与准备

用户准入 M0 T25：研究并为窗口、控件及公共对话框的 Windows 2000 经典外观实现做准备。当前是研究计划，不表示已有 Win2000 renderer，也不自动授权直接更改系统主题、注册表或目标程序文件。范围以普通 Win32 为首要基线；UWP 外框和 WinUI/应用自绘的可行性单列，不由 Win32 结果推定。保留现有 Win16 行为、普通启动和全局模式。

## 已核实的系统基础

- Microsoft 的 [Visual Styles 文档](https://learn.microsoft.com/en-us/windows/win32/controls/themes-overview)说明 Windows 8 起不再提供 Windows Classic 模式；[EnableTheming](https://learn.microsoft.com/en-us/windows/win32/api/uxtheme/nf-uxtheme-enabletheming)在 Windows 8 及以后不再关闭 visual styles。不能依赖一次系统开关获得目标外观。
- [DrawFrameControl](https://learn.microsoft.com/windows/win32/api/winuser/nf-winuser-drawframecontrol) 和 [DrawEdge](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-drawedge)暴露按钮、标题按钮、箭头与立体边框等绘图原语；前者的某些类型输出黑白掩码，且 API 不做 DPI 虚拟化。两者在 Windows 11 实际像素是否与 Windows 2000 相同必须对照，不能预先承诺。
- [主题文件格式](https://learn.microsoft.com/en-us/windows/win32/controls/themesfileformat-overview)区分颜色、指标、字体和 VisualStyles 信息；Classic 与 Luna 的视觉样式不是一个可以简单换色的绘制模型。`.theme` 可作以后数据输入候选，`.msstyles` 直接承载完整 Win2000 几何和交互尚无证据；本任务不承诺格式兼容或导入。

## 研究方法与产物

1. 只读盘点本机可用 Windows 2000 原版样本、主题/字体/资源及来源；确认实际版本、色彩方案、DPI 和许可。没有可靠样本时明确标为缺失，不把网上截图或当前 Windows 配色当作原版。
2. 冻结窗口、控件、对话框的有限优先级矩阵：激活/非激活、普通/禁用/按下/选中/焦点、菜单和滚动、标题及边框、默认字体与配色；分别列原版参考、Win11 原生、现有 Win16 和待实现效果。非客户区交互、DPI、恢复与回退纳入同一验收。
3. 以自有纯 C 探针比对当前 Windows 的系统绘制 API 与原版样本：像素、几何、状态、颜色来源及 DPI；不能复现时再评估独立 painter/资源。样本与资源只读，许可证和来源逐项记录。
4. 设计最小可扩展接口：样式身份与一次选择、窗口生命周期及拥有者独立于 painter；窗口、控件、对话框分别承担明确责任。先列实际必要数据、调用点及 ABI 兼容方案；不预建空框架、不改变注入或目标范围。
5. 排列后续可交付步骤：优先标准窗口/菜单、常用标准控件、常用对话框，再按真实应用 ROI 处理长尾及现代宿主。每步明确双位宽、旧样式不回归、自动探针、demo 手动对照、错误和资源清理；用户确认后再将实现纳入相应活动包。

原版基准仍缺运行时证据：指定源码包支持静态行为研究，其来源和授权未独立核实；未复制任何其中的代码或资源。直到获得可核验的 Windows 2000 运行画面或样本，颜色、字体、像素和 DPI 一致性都不能标记完成。

### 既有全局测试的限制

`tests/integration/global_mode.c` 启动 `--global` 后直接等待全局会话进入 active；而当前 `tray_controller.c` 的初始状态为未启用，需要用户选择 Enable。这是测试预期与当前产品 UX 的独立差异。实际包在私有桌面还遇到托盘创建失败；已发布 T24 的同条件对照也有相同故障，详见 P1 交付记录。

现有 `tray-fixture` 使用测试专用托盘通知桩和显式测试控制消息，不代表真实 Explorer 托盘。以它在私有桌面测试时，日志报告全局后台进程事件需要管理员权限，测试在 disable 阶段失败；该结果不能作为真实托盘或完整全局回归通过的证据，也不能仅凭这一日志断言所有失败都由权限导致。测试产生的临时文件已清理。

## 用户追加的接入目标

建立 `ntw2ks-dll` 的 x86/x64 产物，并由 `run16s --2k` 选择；`--16` 明确选择现有风格，省略时与旧行为一致。用户明确要求新增 DLL，覆盖旧四文件包限制，目标包为 launcher、demo、ntw16s32/64 和 ntw2ks32/64 六文件。构建、包校验、发布工具和治理清单已按六文件调整；增量构建的临时包通过位宽、版本、导入导出、许可证、原 Win16 图形资源及构建文件摘要检查，尚未完成干净构建和实际包完整测试。新 DLL 的序号 1 接入跨位宽辅助入口；自建测试验证了双位宽载荷加载和四种父子位宽的传播，不证明完整视觉效果。禁止让 `--2k` 静默使用 Win16 冒充 Win2000。

普通启动载荷现在包含样式选择，安装器依选择和目标位宽确定 DLL，子进程传播复用该选择，模拟 UAC 参数中也保留 `--2k`。`--global`、UWP、默认 Explorer、Terminal 和控制台宿主仍使用 Win16 专属路径，Win2000 选择目前明确拒绝这些已识别入口。普通 Win32 的初步控件处理已经接通，但并非完整 Windows 2000 样式；实际应用、真实 UAC 和默认/显式 Win16 的全面回归仍未完成。
