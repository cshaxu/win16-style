# 样式库与通用接入重组

用户指定此项作为当前 T25 之后的下一个 T；本方案为队列候选，未准入、未分配 T 号，不改变当前活动任务。

## 目标

- 将 `src/lib-win32` 下的 `win16-*` 和 `win2k-*` 样式组件迁入 `src/lib-style`，同步整理对应测试、构建入口、包含路径与来源清单。
- 审计现存 `ntw16s-dll` 下的 `uwp`、`injection`、`global` 及其所有调用方，把真正通用的样式进程接入、挂钩传播、全局管理、宿主定位等能力整理到 `src/lib-win32/style`，让 Win16 与 Win2000 使用同一通用实现，并为后续 XP、Vista 和 Win7 样式保留明确接口。
- 通用机制与具体绘制、对话框、Win16 专属策略和应用协议解耦；根据实际依赖拆分，不以改目录名称冒充共享，也不将 Win16 私有实现原封不动作为公共接口。具体样式行为由对应样式组件或产品适配层提供。

## 实施与验收

准入后先冻结当前生产文件、类型、依赖、产品入口、测试调用方和样式差异清单，区分可共享机制与各样式专属行为；按依赖顺序迁移，删除旧路径和重复实现，并验证公共组件无对具体样式或产品私有头的反向依赖。Win16 和 Win2000 均须实际调用共享机制，不能只提供空包装；已有功能、兼容边界及公开 ABI 保持，未实现的现代框架或全局样式不因此声称已支持。

按当前仓库交付规范执行双位宽干净构建、先发布后测试、启动与传播及适用的全局/UWP 回归、同批产物摘要核对、提交推送和远端复核。不得使用用户禁止的隔离桌面；不能运行的测试明确标为未覆盖。保留资源、来源声明和用户改动，测试后及时清理本次临时构建。具体 S 分解和边界以准入时的完整审计为准。
