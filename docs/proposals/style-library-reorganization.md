# 样式库与通用接入重组

用户已准入 M0 T26；活动 S 和实际进度以 CURRENT 为准。本任务覆盖 Win16 窗口、控件、对话框，以及 Win32、UWP 和 WinUI 路径中可由 Win2000、XP、Vista、Win7 复用的机制。
原 T25 S9 的 Win16/Win2000 重复代码合并并入本任务，须检查实际调用和旧实现，不重复建立独立任务。

## 目标

- 将 `src/lib-win32` 下的 `win16-*` 和 `win2k-*` 样式组件迁入 `src/lib-style`，同步整理对应测试、构建入口、包含路径与来源清单。
- 审计现存 `ntw16s-dll` 下的 `uwp`、`injection`、`global` 及其所有调用方，把真正通用的样式进程接入、挂钩传播、全局管理、宿主定位等能力整理到 `src/lib-win32/style`，让 Win16 与 Win2000 使用同一通用实现，并为后续 XP、Vista 和 Win7 样式保留明确接口。
- 通用机制与具体绘制、对话框、Win16 专属策略和应用协议解耦；根据实际依赖拆分，不以改目录名称冒充共享，也不将 Win16 私有实现原封不动作为公共接口。具体样式行为由对应样式组件或产品适配层提供。
- 统一审计样式生命周期：运行中停用、已附着窗口和控件恢复、后续新窗口附着及传播分别有明确所有者和契约；不得把停用传播、恢复窗口和物理卸载挂钩混为一谈。Win2000 已有全局窗口移除路径，普通启动目标的运行中移除边界仍需核实；不能假设迁目录即可恢复。

## 实施与验收

准入后先冻结当前生产文件、类型、依赖、产品入口、测试调用方和样式差异清单，区分可共享机制与各样式专属行为；按依赖顺序迁移，删除旧路径和重复实现，并验证公共组件无对具体样式或产品私有头的反向依赖。Win16 和 Win2000 均须实际调用共享机制，不能只提供空包装；已有功能、兼容边界及公开 ABI 保持，未实现的现代框架或全局样式不因此声称已支持。

按当前仓库交付规范执行双位宽干净构建、先发布后测试、启动与传播及适用的全局/UWP 回归、同批产物摘要核对、提交推送和远端复核。不得使用用户禁止的隔离桌面；不能运行的测试明确标为未覆盖。保留资源、来源声明和用户改动，测试后及时清理本次临时构建。具体 S 分解和边界以准入时的完整审计为准。

## 初步分解（待 S1 审计完成后校正）

1. S1 冻结生产与测试范围、依赖和每项迁移决策，明确行为及验证基线。
2. 迁移风格目录及构建/来源映射，保持产品功能与 ABI。
3. 合并外框、非客户区生命周期与菜单可共享机制，包含原 T25 S9。
4. 抽离控件状态、输入及渲染接口，独立保留各代几何和绘制。
5. 抽离对话框契约和适配机制，保留旧式布局及回退策略。
6. 抽离 UWP/WinUI 的宿主与外框通用机制，保留平台及样式差异。
7. 清理产品侧通用样式接入、生命周期和反向依赖，核验各调用方。
8. 全范围去重和最终审计，按实际证据与用户验收收口。

以上是审计起点而非已完成事项或对工作量的保证。每一项可按依赖和测试
结果细分 S；不为凑序号合并尚不能独立验证的变化。

## 首批审计发现

- `style-common/global_window` 已通过产品适配表承载全局窗口应用、移除和
  切换；它可迁入样式共享层，但回滚与实际恢复是不同的验证项。
- `win16-window-uwp/frame_layout` 直接使用 Win16 几何与命中测试；宿主、
  生命周期可审计抽象，几何和按钮外观不能整文件冒充通用。
- `win16-control/scroll_track` 包含 Win3.1 的拖拽、取消及重复语义；应把
  可配置的通用机制和这些明确的风格策略分开，不能直接作为 Win2000 行为。
- `win16-dialog/print_ranges` 的页码解析、格式化没有 Win16 绘制依赖，是
  可供迁移审查的候选；调用位置和失败契约仍须保留与测试。
- 文件路径初始全集见 [S1 清单](../history/M0-T26-S1-initial-inventory.md)；
  这只是冻结范围，逐文件调用、测试和目标归属尚未完成。
