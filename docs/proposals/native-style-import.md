## 候选任务及 S 划分

为保持项目简单，整个原生样式独立化作为一个实现 T 的候选；按下列六个 S
组织，不将三个组件拆成互相等待的独立版本。以下 S 号只是该候选的分解方案，
尚未准入或分配。实际执行顺序由 [QUEUE](../states/QUEUE.md)统一管理。
每个 S 准入时填写 CURRENT，只有当前 S 可以执行；完成当前 S 不等于整个 T 关闭。
每个 P 是可复核且具备对应证据的完整交付，不预设 P 数量或制造部分完成占位。

各工作包同时交付所需测试，最终验收负责组合复验，不能将所有测试延后到最后。
每次代码交付记录实际文件、来源差异、生产/测试净行数、focused/regression
命令、真实结果及未解决项。产品外观和原生行为定义以 design 为准。

| 项 | 工作包 |
| --- | --- |
| 责任/前置 | run16s-exe 与 ntw16s-dll 的私有注入/窗口拦截边界；依赖 S2 双位宽 DLL 通过 |

| 交付 | x64 run16s.exe；复用 DLL 所有的唯一注入实现；最小版本化载荷与必要导出；无需样式 API 的原生 x86/x64 测试目标 |
| 聚焦验收 | x64 启动器分别注入 x86/x64，验证实际同位宽 DLL 与窗口附着；初始及后续 GUI 线程窗口、动态控件均走相同外观实现 |
| 失败验收 | 缺失/错误位宽 DLL、损坏/不支持目标、权限失败及可控安装故障，证明非零状态、原始错误诊断、拥有句柄清理和未放行半安装目标 |
| 回归/退出 | S2 双位宽核心重跑；目标无样式链接/调用仍成功附着；无第五产品，helper（如选用）的超时/退出/清理证据齐全 |
| 停止条件 | 引导需要 loader-lock 内禁止操作、目标在就绪前已执行、目标位宽误判或失败目标被恢复时，不能转传播 S |

此 S 负责首次目标自动附着，包括原窗口 API trampoline 绑定；后代拦截及其
创建语义由下一 S 实现。不用“模块已加载”代替“窗口实际附着”的证明。

## S4 子孙传播与创建语义

| 项 | 工作包 |
| --- | --- |
| 责任/前置 | ntw16s-dll 的进程创建拦截；依赖 S3 首次注入与窗口自动附着通过 |
| 范围 | 原生 CreateProcess A/W 拦截、递归防护、最小上下文传播；每一代复用同一注入事务，彻底去除 broker/RPC/VDM 重定向和前端句柄上下文 |
| 交付 | 两个 DLL 均可传播至原生子孙；双位宽创建 fixture、参数观测与安装故障 fixture；不增加产品 helper |
| 聚焦验收 | x86->x86、x86->x64、x64->x86、x64->x64 四边及至少第三代组合；逐代验证同位宽模块和实际窗口附着，而非只统计 PID |
| 语义验收 | A/W、显式/空 application 字段、路径和参数引用、Unicode、环境/cwd、句柄继承、STARTUPINFO/EX、CREATE_SUSPENDED、失败 LastError；只抵消本层增加的挂起 |
| 回滚验收 | 安装失败只回收新建未交付子进程及自己拥有的句柄，不影响已运行父/兄弟进程；明确超时/目标先退出时的处置 |
| 回归/退出 | S2 核心与 S3 首次启动重新通过；传播不依赖服务或既有进程扫描，未覆盖 API/变体逐项列明，核心创建语义失败不得带入发布 |
| 停止条件 | 参数被改写、调用者挂起被擅自恢复、重复 hook、跨位宽失败、影响既有进程时，保留失败证据并修复当前 S |
