## 实施原则

保持三组件四产物、纯C17/MinGW GCC/Ninja/ccache；适配位于现有双宽ntw16s DLL，
复用唯一renderer和现有原图形资源。五头及来源声明逐字节保持，不新增第五产品，
不要求安装VB IDE/编译器作为本项目构建或核心测试依赖，不改兄弟仓库。

先验证VB5/VB6对应运行库的C可观察边界和真实类/协议；只接纳准确runtime owner及
经验证的角色。保留VB属性、Value三态/分组、Click/Change、焦点、Tab/快捷键、
IME、无障碍、容器/事件重入和销毁；不直接读写私有VB对象布局，不接管业务逻辑。
对无窗口控件核实所属容器的同步绘制作用域/实际调用者/DC，不能全进程替换字体
或吞掉应用自绘。字体继续按既有策略，标题/菜单/滚动条保持；如需改变已确认
策略，先展示实际断点和最小方案，不擅自重做字体或引入其他资源。

目录/驱动器列表的图像先确认实际来源及可复用资源；若需要新增经典资源，先做
许可/来源和资源准入审查，不把应用图像改成自编近似。文件夹公共对话框仍由
[独立候选](classic-folder-dialogs.md)负责，不借本T暗改对话框API/路径返回语义。

## 用户指定的分S顺序

1. **S1审计**：冻结VB5/VB6逐控件/变体矩阵和真实样本；区分本机已存在/缺失、现有适配/新增缺口、原生保留及阻断。
2. **S2 demo**：扩充纯C64位原生demo，展示可见控件的对应项/状态及交互；不可见/数据/嵌入对象按职责展示说明，不伪装完整业务实现。真正32位VB运行库/OCX不能装进64位demo，另由原生32位探针验证，不新增第五产品。
3. **S3起连续实施**：先选择按钮及VB5基础接入，再按审计矩阵处理编辑/列表/滚动/文件列表、容器/无窗口文字、微软OCX等；每S冻结有限范围，按规模顺序分配下一S，不预占编号。
4. **最后独立收口S**：按S1冻结全集逐项核对实现/原生保留/有证据阻断，核对实际包、真实VB5/6与展示，给出完整支持/限制和截图；必测仍有缺口时不能称全部完成。

每个实施S按CURRENT先报根因/最小方案、冻结有限范围；在已准入任务内自动执行
必要后续S，按老规矩完成干净双宽/同批四文件实际包/双发布/摘要/提交推送/实际
远端复核。若实际需要重大架构/安全边界调整，停在证据和最小方案，不暗扩产品。

## 验证、完成谓词与限制

纯C原生探针、自有隔离实例、超时及完整回收；不使用computer-use，不让用户反复
执行整套测试。核心协议/绘制/生命周期测试自包含，真实Actor/MadShow等作另列
实际应用对照，不成为必需构建/测试依赖。真实VB5与VB6分别取得正常显示及状态/
事件证据；原生C仿真runtime/类名fixture不能冒充真实VB运行库验证。

实际VB运行库为32位，x64 DLL仍需构建和原生回归；x64 C fixture不称为64位VB5/6。
模块加载、接入初始化、控件识别和实际绘制四层分开记录。覆盖当前实际DPI、
legacy/aware、打印/正常显示、重复创建/属性更新/卸载、GDI/句柄和捕获释放。
旧实现必须能被新增负例检出；真实UI截图和状态/API证据相互验证。

冻结矩阵每行必须有通过、明确原生保留/无视觉意义、或有证据的阻断及接收者。

明确skip且不能计通过。特殊边界保留不等于隐藏实现缺口；如需缩小承诺先说明。
最终给用户完整支持/回退/未覆盖清单及真实截图验收，M0固定。
