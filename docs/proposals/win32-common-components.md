# 公共 Win32 基础组件

用户要求在不修改隔壁的前提下，制作两项目将来可共用的纯 C 组件。先对照各项目实际接口、语义和许可；共享是目标，只有在隔壁实际适配及回归后才能声称已共用。

1. process-image：提取本项目 PE 文件校验和进程位宽查询；隔壁当前以 SEC_IMAGE 查询，错误和拒绝边界不同，先保留各自语义，不直接宣称等价。
2. process-launch：调查命令行、进程句柄与启动辅助，将产品等待和失败策略留给调用方。
3. module-import：调查模块导入表查询和受控修改，将具体 hook 所有权留给调用方。
4. security/elevation 和 console：调查通用提权查询、调用及控制台句柄辅助，将全局模式策略留给调用方。

依顺序在活动 T 内分 S，实现与产品调用方均需双宽测试和四文件交付；组件必须无产品私有头、无隔壁构建依赖。每项验收按实际覆盖报告，不把新名称当成双方行为一致的证据。

S32 将既有 MZ/非 PE 判断、挂起进程创建及未交付子进程激活/失败清理/等待、通用 Shell 调用及句柄等待迁入相应公共库。调用方仍持有目标解析、是否等待、DLL 准备、UAC 参数、用户提示与已交付进程策略。module-import 独立于 process-hook。目标是源码共用，但隔壁尚未导入或构建验证。

隔壁的映像查询使用 NtCreateSection/SEC_IMAGE 与 NtQuerySection；本项目保留自身文件头校验和 MZ/非 PE 判断。自有双宽探针对七种合成旧/无效样本对照 CreateFileMappingW 的 SEC_IMAGE：本项目 PE 校验及映像节均返回 193；本机有效自身映像两者均接受，本项目额外拒绝不匹配的预期机器。该探针不是隔壁 NtQuerySection 的完整结果比较，不证明所有格式和错误码相同；选择机制及兼容判断仍须由隔壁调用方负责。

S34 按用户要求把唯一由启动器使用的 stderr 重绑定归回 run16s-exe，不再保留独立 console 库；security 库不变。

S36 导入隔壁 process-launch，按用户要求统一 LF；启动器的准备、恢复、失败回滚及等待事务留在 run16s-exe。

S37 从固定来源导入 handle，调用者继续持有句柄所有权和策略。

S38 导入 file 身份和路径原语及独立测试；现有文件内容检查语义不等价，未替换产品调用。
