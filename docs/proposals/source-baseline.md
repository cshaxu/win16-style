## 任务边界与完成条件

| 项 | 工作包 |
| --- | --- |
| 责任/输入 | 根构建与来源接收；固定提交及 105 条候选指纹、目标架构、来源策略 |
| 范围 | 从固定提交追踪 include/link/资源依赖闭包；逐文件记录源 blob、目的路径、原声明、保留/修改/排除及理由；额外依赖显式补入清单 |
| 必须决策 | renderer 与 Hook 合并后的唯一责任；public/private ABI 与导出；无 broker 的最小载荷；loader-lock 外初始化/窗口拦截时序；跨位宽 helper 的必要性、边界、超时和清理 |
| 资源处置 | 对全部外部图形 header/资源逐项选定排除、项目自制替代或具备依据的发布路径；未处置字节不复制；替代方案的制作与像素差异由样式核心任务接收 |
| 工具链 | 探测 MSVC、SDK、CMake、Ninja 的版本与双架构编译/链接能力；使用任务 scratch，不创建虚假产品目标或发布文件 |
| 交付 | 本地来源 manifest 与依赖闭包、资源清单、ABI/初始化/跨位宽设计、可重现构建入口方案及有限支持面/测试清单 |
| 验收/退出 | 每个待导入文件和依赖均有处置；工具链双架构能力有实际证据；后续任务能按方案构建且不依赖兄弟目录；不能仅复述 105 条目录 inventory |
| 停止条件 | 来源不符、依赖无法脱离服务、需要第五产品或资源处置未定时，记录具体问题，不推进相关源码复制 |

不重写 renderer、不提前复制未审素材。支持面须列出 frame、菜单、六类标准
控件及已知不支持变体，说明来源现状和本项目证明责任；不得通过移除核心需求
把后续验收变成必过。需要更改产品目标的发现先报告用户。

本任务还交付本地来源 manifest 校验工具，使后续导入可验证 blob/声明处置，且校验已导入清单不依赖兄弟仓库；不只交付研究文字。

## 本 T 的候选 S 划分

- S1：逐文件来源、依赖闭包及资源处置
- S2：ABI、初始化与跨位宽设计及工具链验证
- S3：本地来源 manifest/校验工具、设计交接和本任务审计

这些 S 只属于本 T，准入后从本 T 的 S1 开始；其他 T 各自重新从 S1 开始。
每个 S 的 P 为完整验证交付，不预分配 P 数量。T 关闭前须逐项对照本任务目标、
全部 S 的实际提交、相关回归、未解决项接收者与退出条件，不能由单个 S 替代。
