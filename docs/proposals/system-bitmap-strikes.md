# System 风格多字号位图字形设计（T19 S2，进行中）

用户要求为不同字号制作更协调的 System 风格位图字形。不得更改标题、菜单、五个原始图形资源及其来源声明；需保留控件布局、原字符 advance 和字体所有权。不是宣称所有自动缩小结果都经过人工设计，也不能将只有英文原型冒称完整字符集。

## 已有证据

- [S2 试用记录](../history/M0-T19-S2-proportional-font.md)的逐字符等比例缩放已被用户评价为更糟；字高随字格变化导致同一行基线和字形不统一，该视觉评价保留。
- [MadShow 证据](../etc/evidence/madshow-controls.json)显示主要控件使用 Tahoma，`lfHeight=-12`、`tmHeight=14`；标题等独立路径不由此推断。
- 本机只读 EnumFontFamiliesExW 探针枚举 `System`，得到 ANSI raster 16px / ascent13 / weight700 与 20px / ascent16 / weight700 两档；这只是本机实际枚举，不承诺其他系统相同。
- 同机原生 GDI 14px Tahoma 示例：`i` advance=2，而16px System 的 `i` advance=4、墨迹宽2；`s` 分别为5、8、6；`R` 为7、10、9。旧试用把整张字符单元压到原 advance，尤其会把 `i` 的高度一起压小。仅按字符单元尺寸缩放不能证明黑色笔画真正放得下。

## 设计与退出条件

先做针对14px 的完整可审查字形试作，明确每个字符的字高、基线、可辨笔画、advance 与裁切；随后覆盖产品字体生成器已接纳的 1..64px 请求，列明专门设计的字号、缩放策略及不适合尺寸的原生回退，不将算法生成的字号称为逐字手工优化。至少覆盖现有 CP1252 的行为边界，非可验证字符保留可靠回退，不得引入不存在的字体或替换成问号。要核查真实字体来源和可分发许可，保留完整声明。

原型必须用整行和真实控件截图比较，而不是仅用每个字符的缩放公式当质量证据；测试字符包括 `Settings`、`Particles`、`Radius`、`0 1 2`、大小写、标点、变音符号、窄字符及长字符串。以双位宽、MadShow实际样本、不同 DPI、标准/VB控件、基线/行高/逐字符advance/裁切、标题和菜单的前后对照、资源寿命与缺字回退验证。绘制测量互相一致且控件位置不变；图像验收未通过时不发布或不宣称解决。

当前已有派生字形试用实现及初步验证，实际范围、极小字号回退和未完成的逐字号设计见[试用记录](../history/M0-T19-S2-system-glyph-trial.md)；不能称为所有字号逐字人工设计完成。

用户已否决本轮字体试用并要求全部撤回；本候选不继续实施。历史试验保留为事实记录。
